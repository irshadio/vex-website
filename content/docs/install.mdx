Vex comes as one download, the **Vex SDK**: the `vex` command with its standard library and runtime, the documentation, and on Windows and Linux the C toolchain `vex` builds programs with. Unpack it anywhere and add its `bin` folder to your `PATH`; nothing is installed elsewhere and nothing needs administrator rights.

<Callout type="info" title="Supported systems">
Vex runs on macOS (Apple silicon and Intel), Linux (x86-64) and Windows (x86-64). Vex is pre-release, and no version has been tagged yet: until the first release, [build from source](#build-from-source).
</Callout>

## Download

SDK archives are published on the [GitHub Releases](https://github.com/vex-language/vex-lang/releases) page of the language repository when a version is tagged. **Stable** is for everyday use; **Beta** previews the next release.

<Downloads />

| System | Archive | What it holds |
|---|---|---|
| Windows (x64) | `vex-sdk-<version>-windows-x64.zip` | `vex.exe` and [LLVM-MinGW](https://github.com/mstorsjo/llvm-mingw): clang, lld and the Windows headers and libraries. No Visual Studio is needed |
| Linux (x64) | `vex-sdk-<version>-linux-x64.tar.xz` | `vex`, clang and lld, a [musl](https://musl.libc.org) sysroot and a static OpenSSL libcrypto. Programs are static executables that run on any x86-64 Linux |
| macOS (Apple silicon) | `vex-sdk-<version>-macos-arm64.tar.xz` | `vex`; programs are built with Apple's Command Line Tools |
| macOS (Intel) | `vex-sdk-<version>-macos-x64.tar.xz` | The same, for Intel Macs |

On macOS the C compiler, the system headers and `swiftc` come from Apple's Command Line Tools, whose license doesn't allow passing them on. Install them once:

```sh
xcode-select --install
```

Each release lists the archives' SHA-256 sums in `SHA256SUMS`. To check a download before unpacking it:

```sh
shasum -a 256 vex-sdk-*.tar.xz     # macOS
sha256sum vex-sdk-*.tar.xz         # Linux
```

```powershell
Get-FileHash vex-sdk-*.zip         # Windows
```

## Unpack and add vex to your PATH

<Tabs items={['macOS', 'Linux', 'Windows']}>
  <Tab value="macOS">
    ```sh
    mkdir -p ~/sdk
    tar -xJf ~/Downloads/vex-sdk-*-macos-arm64.tar.xz -C ~/sdk
    echo 'export PATH="$HOME/sdk/vex-sdk/bin:$PATH"' >> ~/.zshrc
    source ~/.zshrc
    ```

    zsh is the default shell on macOS; with bash, use `~/.bash_profile` instead of `~/.zshrc`.
  </Tab>
  <Tab value="Linux">
    ```sh
    mkdir -p ~/sdk
    tar -xJf ~/Downloads/vex-sdk-*-linux-x64.tar.xz -C ~/sdk
    echo 'export PATH="$HOME/sdk/vex-sdk/bin:$PATH"' >> ~/.bashrc
    source ~/.bashrc
    ```

    The bundled clang needs glibc 2.35 or newer on the machine that builds programs: Ubuntu 22.04, Debian 12, Fedora 36 or newer. The programs it builds run on any x86-64 Linux.
  </Tab>
  <Tab value="Windows">
    Unzip the archive, for example to `C:\sdk`, so that `C:\sdk\vex-sdk\bin\vex.exe` exists. Then add that `bin` folder to your user `PATH` in PowerShell:

    ```powershell
    Expand-Archive "$HOME\Downloads\vex-sdk-*-windows-x64.zip" C:\sdk
    [Environment]::SetEnvironmentVariable("Path", "C:\sdk\vex-sdk\bin;" + [Environment]::GetEnvironmentVariable("Path", "User"), "User")
    ```

    Open a new terminal for the change to take effect.
  </Tab>
</Tabs>

The folder can live anywhere, even in a path with spaces or on another drive: `vex` finds the toolchain next to itself, after following symbolic links, so a link to `vex` from `/usr/local/bin` works too.

### What's in the SDK

```text
vex-sdk/
  bin/vex[.exe]           the command, with the standard library and runtime built in
  toolchain/              the C toolchain (Windows and Linux only)
  docs/                   the language guide and the standard library's API docs
  version                 what this SDK is, as JSON
  LICENSE-APACHE, LICENSE-MIT, LICENSE-RUNTIME-EXCEPTION
  THIRD_PARTY_LICENSES    the notices of everything bundled
```

The standard library, the runtime and the C half of `vex:crypto` are embedded in the `vex` binary, so there is no `lib` folder.

## Check the tools with vex doctor

```sh
vex doctor
```

```text
Doctor summary (to see all details, run vex doctor -v):
[✓] Vex (0.1.0-dev+11b0009)
[✓] C toolchain - builds Vex programs (Apple clang 21.0.0)
[✓] git - downloads packages for vex get (git 2.50.1)
[✓] Xcode - builds iOS apps (Xcode 26.4)
[!] Android toolchain - builds Android apps (NDK 29.0.13113456)
    ! Java 11.0.26 is too old; Android builds need JDK 17 or newer
      Set $JAVA_HOME to Android Studio's JDK

! Doctor found issues in 1 category.
```

`vex doctor` checks the C toolchain, `git` for [`vex get`](/docs/projects/packages), and, for phone apps, Xcode and the Android SDK, NDK and JDK. It says what is missing and how to install it, and never installs anything itself. Only a missing C toolchain stops Vex from building programs; the rest are warnings. `vex doctor -v` shows where each tool was found, including whether the C compiler is the one bundled with the SDK. See [vex doctor](/docs/tools/cli#vex-doctor).

`vex` looks for the C compiler in this order: the command in `CC` if it is set, which may be a full path with spaces; then `toolchain/bin/clang` of the SDK `vex` belongs to; then `clang`, `cc` or `gcc` on your `PATH`.

## Windows

Vex works on Windows with no Visual Studio and no WSL. Programs are built with the SDK's clang from LLVM-MinGW. [Vex on Windows](/docs/windows) covers installing, the console, paths, `vex doctor` and every difference in detail.

- `vex build hello.vx` writes `hello.exe`.
- Arguments, environment variables, file names and console output are UTF-8, so text in any script prints correctly in Windows Terminal and PowerShell.
- Source files may use Windows (CRLF) line endings.
- [`os.run`](/docs/stdlib/os#run) and [`os.output`](/docs/stdlib/os#output) run commands with `cmd` instead of `sh`.
- `vex:crypto` takes its system algorithms from CNG, which ships with Windows, so nothing extra is needed.

## Build from source

Building `vex` needs Go 1.23 or newer, and building programs needs a C compiler: `clang` or `gcc` on macOS and Linux, and clang from LLVM-MinGW on Windows (`winget install MartinStorsjo.LLVM-MinGW.UCRT`).

```sh
git clone https://github.com/vex-language/vex-lang.git
cd vex-lang
./build.sh
```

The script runs `go build` and writes the compiler to `bin/vex`, then prints its version:

```text
Built bin/vex (vex 0.1.0-dev+3a88a7e)
```

The part after `+` is the git commit the compiler was built from, with `-dirty` added when the working tree had uncommitted changes. The compiler has no Go dependencies outside the standard library, and the standard library and runtime are embedded in `bin/vex`, so it works on its own: you can copy it anywhere. Add its folder to your `PATH`:

<Tabs items={['macOS and Linux', 'Windows']}>
  <Tab value="macOS and Linux">
    ```sh
    echo 'export PATH="'"$PWD"'/bin:$PATH"' >> ~/.zshrc
    source ~/.zshrc
    ```

    Use `~/.bashrc` instead of `~/.zshrc` with bash.
  </Tab>
  <Tab value="Windows">
    `./build.sh` works from Git Bash. From PowerShell, build and add the folder to your user `PATH`, then open a new terminal:

    ```powershell
    go build -o bin\vex.exe .\cmd\vex
    [Environment]::SetEnvironmentVariable("Path", "$PWD\bin;" + [Environment]::GetEnvironmentVariable("Path", "User"), "User")
    ```
  </Tab>
</Tabs>

Without the SDK's toolchain, a few extra packages are needed for `vex:crypto`: on macOS, `swiftc` from the Command Line Tools, which `xcode-select --install` provides; on Linux, OpenSSL 3's development files (`sudo apt install libssl-dev` or `sudo dnf install openssl-devel`). On Linux, install a C compiler with `sudo apt install build-essential`, `sudo dnf install gcc` or `sudo pacman -S base-devel`.

## Verify the installation

Check that your shell finds `vex`:

```sh
vex version
```

```text
vex 0.1.0-dev+3a88a7e
```

Then compile and run a program, which also checks the C compiler. Save this as `hello.vx`:

```vex title="hello.vx"
fn main() {
    println("Hello, world!")
}
```

```sh
vex run hello.vx
```

```text title="Output"
Hello, world!
```

If you see `Hello, world!`, everything works. Continue with [Your first program](/docs/first-program).

## Editor support

There is no editor extension or language server for Vex yet. A VS Code extension with syntax highlighting, followed by a language server with errors, go-to-definition and completion, is on the roadmap.

Until then, Swift syntax highlighting is a reasonable stand-in, since the two languages look alike: in VS Code, open a `.vx` file, run **Change Language Mode** and pick Swift. Use `vex check` to see errors as you go.

## Upgrade

<Tabs items={['Download', 'From source']}>
  <Tab value="Download">
    Download the new archive, delete the old `vex-sdk` folder and unpack the new one in its place. Your `PATH` stays the same.
  </Tab>
  <Tab value="From source">
    Pull the latest code and build again:

    ```sh
    cd vex-lang
    git pull
    ./build.sh
    ```
  </Tab>
</Tabs>

Run `vex version` to confirm the new version. Vex is in early development, so a new version may change the language; recompile your programs after upgrading.

## Uninstall

Vex keeps nothing outside its own folder except the package cache, `~/.vex/pkg`, which `vex get` fills. Programs you built with `vex build` don't depend on it.

1. Delete the `vex-sdk` folder, or your `vex-lang` clone.
2. Delete `~/.vex` if you used packages.
3. Remove the folder from your `PATH`: the `export PATH=...` line in `~/.zshrc`, `~/.bashrc` or `~/.bash_profile`, or the entry in your user `Path` on Windows.

## Troubleshooting

### `command not found: vex`

Your shell can't find `vex` on the `PATH`. Check that the folder you added really contains the `vex` binary, that you ran `source` on your shell file (or opened a new terminal), and that you edited the file of the shell you use: run `echo $SHELL` to see which one that is.

On Windows the message is `The term 'vex' is not recognized`. A `PATH` change reaches only terminals opened after it, so open a new one; see [Vex on Windows](/docs/windows#troubleshooting).

### No C compiler found

```text
vex: no C compiler found; install clang (on macOS: xcode-select --install) or set $CC
```

`vex check` works without a C compiler, but `vex run` and `vex build` need one. On Windows and Linux the SDK brings its own; check that `toolchain/` is still next to `bin/`. On macOS run `xcode-select --install`. Or point `CC` at a compiler you have:

<Tabs items={['macOS and Linux', 'Windows']}>
  <Tab value="macOS and Linux">
    ```sh
    export CC=gcc
    ```
  </Tab>
  <Tab value="Windows">
    ```powershell
    $env:CC = "C:\Program Files\LLVM\bin\clang.exe"
    ```
  </Tab>
</Tabs>

### `CC` names a missing program

```text
vex: running the C compiler (nosuchcc): exec: "nosuchcc": executable file not found in $PATH
```

The `CC` environment variable is set to a command that doesn't exist. Fix it, or remove it with `unset CC` (`Remove-Item Env:CC` in PowerShell) so that `vex` finds its compiler by itself. `vex doctor -v` shows which compiler it chose.

### The C compiler fails on generated code

```text
vex: the C compiler (/usr/bin/clang) failed on generated code; this is a bug in vex
```

Vex checks your program before it writes any C, so C that doesn't compile is a bug in the compiler, not in your code. This can also happen with a C compiler that isn't `clang` or `gcc`, since the generated C needs their extensions.

### `vex:crypto` doesn't build

On macOS, a program that imports `vex:crypto` needs `swiftc`: run `xcode-select --install`. On Linux with your own compiler instead of the SDK's, install OpenSSL 3's development files: `sudo apt install libssl-dev` or `sudo dnf install openssl-devel`. `vex doctor -v` reports whether `swiftc` was found. Please report it with the program that triggers it at [github.com/vex-language/vex-lang](https://github.com/vex-language/vex-lang).

### `no package.toml`

```text
vex: no package.toml in .; create one with:

[package]
name = "myapp"
```

The suggested name is the name of the current folder. `vex run`, `vex build` and `vex check` without a file name work on the project in the current folder, which needs a `package.toml`. Either name the file to run, as in `vex run hello.vx`, or create the project file. See [Modules](/docs/projects/modules).

### `go: command not found` when building from source

`build.sh` needs Go 1.23 or newer. Install it from [go.dev/dl](https://go.dev/dl/) or your package manager, then run `./build.sh` again.
