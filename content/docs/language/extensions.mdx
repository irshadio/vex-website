title: Extensions
description: Adding methods, getters, setters, static members and operators to existing types, including int, float, bool, string, Bytes, lists, maps and interfaces, how extensions are scoped across modules, and extension types, distinct types that wrap one value at no cost.
---

An extension adds members to a type that already exists. You can extend your own structs, enums and interfaces, types from other modules, and the built-in types `int`, `float`, `bool`, `string`, `Bytes`, lists and maps. A related form, [`extension type`](#extension-types), makes a new type out of an existing one. Calls to the new members look exactly like calls to the type's own.

```vex title="shout.vx"
extension string {
    fn shout() -> string => upper() + "!"
    get isBlank -> bool => trim().len == 0
}

extension int {
    get squared -> int => self * self
    fn isEven() -> bool => self % 2 == 0
}

fn main() {
    println("hi".shout(), "  ".isBlank, "x".isBlank)
    println(7.squared, (1 + 3).isEven())
}
```

```text title="Output"
HI! true false
49 true
```

## Writing an extension

`extension TypeName { ... }` holds the new members. Inside, the value is `self`, and its members can be used without `self.`, as in a struct: `upper()` means `self.upper()`, and in a list extension `len` means `self.len`.

What an extension can add depends on the type:

| Type | Methods | Getters | Setters | Static methods and constants | Operators |
|---|---|---|---|---|---|
| Structs | yes | yes | yes | yes | yes |
| Enums | yes | yes | no | yes | no |
| `int`, `float`, `bool`, `string` | yes | yes | no | no | no |
| Lists and maps | yes | yes | no | no | no |
| Interfaces | yes | no | no | no | no |

Methods can have default parameters, throw, be `async` and be generic, like any method.

## Extending structs and enums

An extension of a struct or enum can add methods, getters, setters (structs only), static methods, static constants and operators:

```vex title="struct_ext.vx"
struct Counter {
    count: int = 0
}

extension Counter {
    get doubled -> int => count * 2
    set doubled(v: int) {
        count = v / 2
    }
    fn reset() {
        count = 0
    }
    static fn startingAt(n: int) -> Counter => Counter(count: n)
    static const limit = 10
    operator +(other: Counter) -> Counter => Counter(count: count + other.count)
}

enum Direction { up, down }

extension Direction {
    fn flipped() -> Direction => match self {
        up => .down
        down => .up
    }
}

fn main() {
    let c = Counter.startingAt(3)
    c.doubled = 8
    println(c.count, c.doubled, Counter.limit)
    println(c + Counter(count: 1))
    c.reset()
    println(c, Direction.up.flipped())
}
```

```text title="Output"
4 8 10
Counter(count: 5)
Counter(count: 0) Direction.down
```

An extension can also add a [`toString`](/docs/language/structs#tostring) method to a struct or enum, which printing and interpolation then use.

### Extensions can't add fields

An extension can't add stored data, since every existing value of the type would need room for it. Compute the value with a getter instead:

```vex title="no_fields.vx"
struct Point { x: int }

extension Point {
    y: int
}

fn main() {}
```

```text title="Output"
error: extensions can't add fields
 --> no_fields.vx:4:5
  |
4 |     y: int
  |     ^ compute it instead: get y -> T { ... }
```

### Generic structs and enums

An extension of a generic type names it without type arguments, and its members use the type's own parameters:

```vex title="generic_ext.vx"
struct Box<T> {
    value: T
}

extension Box {
    fn get() -> T => value
    fn describe() -> string => "box of {value}"
}

fn main() {
    println(Box(value: 3).get(), Box(value: "a").describe())
}
```

```text title="Output"
3 box of a
```

Writing `extension<T> Box<T>` is an error: `an extension of a generic struct or enum names it without type arguments`. You can't extend only `Box<int>`.

### Meeting an interface

A method added by an extension can meet a requirement of an interface the struct already lists after `:`. This lets you keep the interface methods in their own block, or in another file of the same module:

```vex title="meet_iface.vx"
interface Shape {
    fn area() -> float
}

struct Square: Shape {
    side: float
}

extension Square {
    fn area() -> float => side * side
}

fn main() {
    let shapes: [Shape] = [Square(side: 2)]
    println(shapes[0].area())
}
```

```text title="Output"
4.0
```

The struct must still declare the interface itself. `extension Square: Shape { ... }` isn't valid syntax.

## Extending built-in types

`int`, `float`, `bool` and `string` get methods and getters:

```vex title="builtins.vx"
extension float {
    get half -> float => self / 2.0
}

extension bool {
    fn toInt() -> int => match self {
        true => 1
        false => 0
    }
}

extension int {
    fn times(body: fn(int)) {
        for i in 0..self {
            body(i)
        }
    }
}

fn main() {
    println(3.0.half, true.toInt())
    3.times(fn(i) { print(i, "") })
    println()
}
```

```text title="Output"
1.5 1
0 1 2 
```

Built-in types can't get static members, constants or setters:

```vex title="builtin_limits.vx"
extension string {
    static fn make() -> string => ""
    static const empty = ""
    set loud(v: string) {}
}

fn main() {}
```

```text title="Output"

2 |     static fn make() -> string => ""
  |               ^^^^ make it a top-level function

error: only extensions of structs and enums can add constants
 --> builtin_limits.vx:3:18

3 |     static const empty = ""
  |                  ^^^^^ move it to the top level
```

### Lists and maps

A list or map extension is either for one element type, such as `extension [int]`, or for all of them, with type parameters and optional constraints after `extension`:

```vex title="collections.vx"
extension [int] {
    fn total() -> int {
        var total = 0
        for x in self {
            total += x
        }
        return total
    }
}

extension<T: Comparable> [T] {
    fn largest() -> T? {
        if len == 0 {
            return nil
        }
        var best = self[0]
        for x in self {
            if x > best {
                best = x
            }
        }
        return best
    }
}

extension<K: Hashable, V> [K: V] {
    get size -> int => len
}

extension [string: int] {
    fn total() -> int {
        var t = 0
        for _, v in self {
            t += v
        }
        return t
    }
}

fn main() {
    println([1, 2, 3].total())
    println([3, 9, 2].largest() ?? 0, ["b", "c", "a"].largest() ?? "")
    let empty: [int] = []
    println(empty.largest() ?? -1)
    println(["a": 1, "b": 2].size, ["a": 2, "b": 3].total())
}
```

```text title="Output"
6
9 c
-1
2 5
```

The constraint decides which lists get the member: `largest()` exists on `[int]` and `[string]`, but not on a list of a struct that isn't `Comparable`. The constraints are the same as for [generics](/docs/language/generics#constraints).

When an extension for one type and an extension for all lists both add a member with the same name, the one for the specific type wins:

```vex title="specific.vx"
extension<T> [T] {
    fn describe() -> string => "a list of {len}"
}

extension [int] {
    fn describe() -> string => "{len} ints"
}

fn main() {
    println([1, 2].describe(), ["a"].describe())
}
```

```text title="Output"
2 ints a list of 1
```

Two generic extensions that both match are ambiguous, and using the member is an error that names both lines: `'first2' of [int] is declared by more than one extension, on lines 32 and 35`.

### Type aliases

An extension can name a [type alias](/docs/language/types), and then extends the type the alias stands for:

```vex title="alias_ext.vx"
typedef Names = [string]

extension Names {
    fn joined(sep: string = ", ") -> string {
        var out = ""
        for n in self {
            if out.len > 0 {
                out += sep
            }
            out += n
        }
        return out
    }
}

fn main() {
    let names: Names = ["ann", "bo"]
    println(names.joined(), names.joined(sep: "/"))
    println(["x", "y"].joined())                 // any [string] has it
}
```

```text title="Output"
ann, bo ann/bo
x, y
```

## Extending interfaces

An extension of an interface adds methods to every type that implements it. The methods can use the interface's members, and they work on interface values, in generic code constrained by the interface, and on the implementing types themselves. An extension of an interface also reaches the interfaces that extend it:

```vex title="iface_ext.vx"
interface Shape {
    fn area() -> float
    fn name() -> string => "shape"
}

interface Solid: Shape {
    fn depth() -> float
}

extension Shape {
    fn isBig() -> bool => area() > 100.0
    fn report() -> string => "{name()}: {area()}, big: {isBig()}"
}

extension Solid {
    fn volume() -> float => area() * depth()
}

struct Circle: Shape {
    radius: float
    fn area() -> float => 3.0 * radius * radius
    fn name() -> string => "circle"
}

struct Cube: Solid {
    side: float
    fn area() -> float => side * side
    fn depth() -> float => side
}

enum Tile: Shape {
    small, large

    fn area() -> float => match self {
        small => 1.0
        large => 400.0
    }
}

fn bigOnes<T: Shape>(xs: [T]) -> [T] => xs.filter { it.isBig() }

fn main() {
    let shapes: [Shape] = [Circle(radius: 1), Cube(side: 20), Tile.large]
    for s in shapes {
        println(s.report())
    }
    println(Circle(radius: 9).isBig(), Cube(side: 3).volume())
    println(bigOnes([Circle(radius: 1), Circle(radius: 9)]))
}
```

```text title="Output"
circle: 3.0, big: false
shape: 400.0, big: true
shape: 400.0, big: true
true 27.0
[Circle(radius: 9.0)]
```

### Added methods can't be replaced

An interface's [default methods](/docs/language/interfaces#default-methods) are a starting point that each type may replace. A method added by an extension is the same for every type: a type that implements the interface can't declare a method with that name, and the extension can't reuse the name of a requirement. An extension of an interface adds methods only: no getters, setters, static members, constants or operators.

```vex title="iface_ext_errors.vx"
interface Shape {
    fn area() -> float
}

extension Shape {
    fn area() -> float => 1.0
    fn big() -> bool => area() > 9.0
    get size -> int => 1
    static fn unit() -> int => 1
    static const k = 1
}

extension Shape {
    fn big() -> bool => false
}

struct Square: Shape {
    fn area() -> float => 4.0
    fn big() -> bool => true
}

fn main() {}
```

```text title="Output"
 --> iface_ext_errors.vx:8:9

8 |     get size -> int => 1
  |         ^^^^ write a method instead: fn size() -> ...

  |               ^^^^ move it to the top level
```

A generic interface is extended without type arguments, `extension Store { ... }`, and the methods use the interface's own type parameters; they may also have their own. Writing `extension Store<int> { ... }` gives `an extension of a generic interface names it without type arguments`. Methods added to an interface can be torn off as function values, like other methods.

### Interface extensions across modules

The [module rules](#extensions-and-modules) apply as for other extensions: in other modules, an added method needs `pub` (or the whole extension `pub extension`), and the file using it must import the extension's module. The interface itself needs `pub` to be implemented elsewhere:

<Files>
  <File name="package.toml" />
  <File name="main.vx" />
  <Folder name="shapes" defaultOpen>
    <File name="shapes.vx" />
  </Folder>
</Files>

```vex title="shapes/shapes.vx"
pub interface Shape {
    fn area() -> float
}

extension Shape {
    pub fn isBig() -> bool => area() > 100.0
    fn half() -> float => area() / 2.0       // private to shapes
}
```

```vex
import "shapes"

struct Square: shapes.Shape {
    side: float
    fn area() -> float => side * side
}

fn main() {
    let s: shapes.Shape = Square(side: 20)
    println(s.isBig(), Square(side: 2).isBig())
}
```

```text title="Output"
true false
```

Calling `s.half()` from `main.vx` gives `method 'half' of the extension is private to shapes`, with the hint `mark it pub in shapes to use it from other modules`.

## What can't be extended

Optionals, records, function types and sets can't be extended:

```vex title="cant_extend.vx"
extension int? {
    fn f() {}
}

extension fn() {
    fn h() {}
}

fn main() {}
```

```text title="Output"
error: int? can't be extended
 --> cant_extend.vx:1:11
  |
1 | extension int? {
  |           ^^^^ extend a struct, an enum, an interface, int, float, bool, string, Bytes, a list or a map

error: fn() can't be extended
 --> cant_extend.vx:5:11
  |
5 | extension fn() {
  |           ^^^^ extend a struct, an enum, an interface, int, float, bool, string, Bytes, a list or a map

2 errors
```

To add behavior to an optional, unwrap it first; extension members of the inner type work through `?.`, as in `maybe?.shout()`.

## Extensions add, they don't replace

An extension can't change what a type already has. A member with the same name as an existing field, method or built-in member is an error, and so is the same member added twice:

```vex title="no_override.vx"
struct Point {
    x: int
}

extension Point {
    fn x() -> int => 1
}

extension string {
    fn upper() -> string => self
    fn shout() -> string => self
}

extension string {
    fn shout() -> string => self
}

fn main() {}
```

```text title="Output"
error: 'x' is already a field of Point
 --> no_override.vx:6:8
  |
6 |     fn x() -> int => 1
  |        ^

error: string already has a member 'upper'
  --> no_override.vx:10:8
   |
10 |     fn upper() -> string => self
   |        ^^^^^ choose another name

error: 'shout' is already declared for string on line 11
  --> no_override.vx:15:8
   |
15 |     fn shout() -> string => self
   |        ^^^^^

3 errors
```

This keeps a call's meaning stable: `s.upper()` always runs the built-in `upper`, wherever you read it.

## Extensions and modules

An extension works everywhere in the module that declares it. Other modules see only its `pub` members, and only in files that import the extension's module. `pub extension` makes every member public:

<Files>
  <File name="package.toml" />
  <File name="main.vx" />
  <Folder name="text" defaultOpen>
    <File name="text.vx" />
  </Folder>
</Files>

```vex title="text/text.vx"
pub extension string {
    fn shout() -> string => upper() + "!"
    get isBlank -> bool => trim().len == 0
}

extension string {
    fn wrap() -> string => "[" + self + "]"     // private to this module
    pub fn wrapped() -> string => wrap()        // public
}
```

```vex
import "text"

fn main() {
    println("hi".shout(), "  ".isBlank, "a".wrapped())
}
```

```text title="Output"
HI! true [a]
```

Using a private member from another module is an error:

```text
error: method 'wrap' of the extension is private to text
 --> main.vx:4:17
  |
4 |     println("a".wrap())
  |                 ^^^^ mark it pub in text to use it from other modules
```

A file that doesn't import `text` doesn't see `shout` at all: `string has no method 'shout'`. Two modules can each add a private member with the same name without clashing.

Extensions of types from other modules are written with the module name: `extension shapes.Point { ... }`. They can only use that type's `pub` fields and methods. See [Modules](/docs/projects/modules).

## Extension types

`extension type` makes a new type out of an existing one, as in Dart 3. It wraps exactly one value, named in parentheses, and costs nothing at run time: a `UserId` is compiled as a plain `int`, creating one and reading `.value` do no work, and its methods take the `int` itself. The compiler still keeps the two apart, so a user id can't be passed where an order id or a count is expected:

```vex title="exttype.vx"
extension type UserId(value: int): Hashable, Comparable {
    static const root = UserId(value: 0)

    fn isAdmin() -> bool => value < 100
}

extension type Email(value: string)

fn load(id: UserId) -> string => "user {id.value}"

fn main() {
    let id = UserId(value: 42)
    let n: int = id.value
    println(id, n, id.isAdmin(), load(id))
    println(Email(value: "ann@example.com"), UserId.root)

    let names = [UserId(value: 7): "ann", id: "bob"]
    println(names[UserId(value: 7)] ?? "?", id < UserId(value: 50))
    println(id.copy(value: 43))

    match id {
        UserId(value: 0) => println("root")
        UserId(:value) => println("id {value}")
    }
}
```

```text title="Output"
UserId(value: 42) 42 true user 42
Email(value: "ann@example.com") UserId(value: 0)
ann true
UserId(value: 43)
id 42
```

It is a distinct type in both directions: an `int` isn't a `UserId`, and a `UserId` isn't an `int`. Wrap a value with `UserId(value: ...)` and unwrap it with `.value`:

```vex title="exttype_mix.vx"
extension type UserId(value: int)

fn load(id: UserId) {}

fn main() {
    load(42)
}
```

```text title="Output"
error: argument 'id': expected UserId, found int
 --> exttype_mix.vx:6:10
  |
6 |     load(42)
  |          ^^ wrap it: UserId(value: 42)
```

Only the members in its body and in extensions of it are available: `id.abs()` gives `UserId has no method 'abs'`, even though `int` has `abs`. Write `id.value.abs()`.

`Codable` writes the plain value to JSON, not an object, and a `toString` method changes how it prints:

```vex title="exttype_json.vx"
import "vex:json"

extension type Email(value: string): Codable

struct Account: Codable {
    email: Email
}

extension type Celsius(value: float) {
    fn toString() -> string => "{value}°C"
}

fn main() throws {
    let text = json.encode(Account(email: Email(value: "ann@example.com")))
    println(text)
    let back: Account = try json.decode(text)
    println(back.email.value, Celsius(value: 21.5))
}
```

```text title="Output"
{"email":"ann@example.com"}
ann@example.com 21.5°C
```

- The body holds methods, getters, operators, static methods and constants, used without `self.` as in a struct. It has no other fields, no `init` block and no setters: the value never changes. `id.copy(value: 7)` makes a new one.
- The body is optional: `extension type Email(value: string)`. An `extension` of an extension type adds members as for a struct.
- `: Equatable`, `Hashable`, `Comparable` and `Codable` give it `==`, hashing (so it can be a map key), `<` and JSON from the value it wraps, which must have them.
- It prints like a struct, `UserId(value: 42)`, unless it has a `fn toString() -> string`.
- It works in lists, maps, optionals and records, can be generic (`extension type Box<T>(value: T)`), matches patterns such as `UserId(value: 42)` and `UserId(:value)`, and can be a constant: `static const root = UserId(value: 0)`.
- `pub extension type` makes the type and its value usable from other modules; its methods need their own `pub`.
- It can't list other interfaces, so it is never an interface value, and `is` and `as?` never name one: having no wrapper, its values don't carry a type tag. Listing one gives `an extension type can only list Equatable, Hashable, Comparable and Codable, which it gets from the value it wraps`, with the hint `use a struct to implement Shape`.

## Extension members as values

Extension methods can be torn off like built-in ones: with `let xs = [1, 2, 3]`, `xs.tail` is a function bound to `xs`. See [Closures](/docs/language/closures).

## Rules and edge cases

- Extensions add methods and getters to structs, enums and built-in types, static members and operators to structs and enums, and setters to structs. Extensions of interfaces add methods only.
- Extendable: structs, enums, extension types, interfaces, `int`, `float`, `bool`, `string`, `Bytes`, lists, maps, and type aliases of those. Not extendable: optionals, records, function types and sets.
- `extension type Name(value: T)` is a different declaration: a new, distinct type, compiled as the `T` it wraps. See [Extension types](#extension-types).
- A method added to an interface reaches every type that implements it, and every interface that extends it. It can't share a name with a requirement, and implementing types can't replace it.
- No fields. No replacing or shadowing existing members.
- A generic struct or enum is extended by its bare name; its type parameters are in scope.
- List and map extensions are for one element type or for all, with `extension<T: C> [T]`. The specific one wins over the generic one; two matching generic ones are ambiguous.
- An extension method can meet an interface requirement, but the struct must list the interface itself.
- Members are private to the module unless marked `pub` (or the extension is `pub extension`), and other modules see them only in files that import the module.
- `extension` is only a keyword at the start of a declaration, so it remains usable as a variable name.
