Functions are declared with `fn`, take typed parameters, and give their result type after `->`. At the call site, any argument can be named, and parameters can have defaults, so calls stay readable without builder objects or overloads.

## Declaring a function

```vex title="add.vx"
fn add(a: int, b: int) -> int {
    return a + b
}

fn greet(name: string) {
    println("Hello, {name}")
}

fn main() {
    println(add(2, 3))
    greet("Ann")
}
```

```text title="Output"
5
Hello, Ann
```

- Each parameter is `name: Type`. Parameter types are always written: `fn f(x)` gives `parameter 'x' needs a type`.
- `-> Type` gives the result type. A function that returns nothing leaves it out; there's no `void`.
- Functions are declared at the top level of a file, in any order. A function can call one declared after it. Functions declared inside other functions follow different rules; see [Local functions](#local-functions).

## Result types and return

A function with a result type must return a value on every path:

```vex title="missing.vx"
fn sign(n: int) -> int {
    if n > 0 {
        return 1
    } else if n < 0 {
        return -1
    }
}

fn main() {
    println(sign(5))
}
```

```text title="Output"
error: missing return: sign must return int
 --> missing.vx:7:1
  |
7 | }
  | ^ add a return statement before the closing }
```

The compiler understands that an `if` whose branches all return, a `match` whose arms all return, and a call to `panic(...)` all end the function. A function without a result type can use a bare `return` to leave early, but returning a value from it is an error: `log doesn't return a value`.

To return several values, return a [record](/docs/language/records):

```vex title="divmod.vx"
fn divmod(a: int, b: int) -> (int, int) {
    return (a / b, a % b)
}

fn main() {
    let (q, r) = divmod(17, 5)
    println(q, r)
}
```

```text title="Output"
3 2
```

## Expression bodies

When the body is a single expression, write `=>` and the expression instead of a block:

```vex title="arrow.vx"
fn square(x: int) -> int => x * x
fn isAdult(age: int) -> bool => age >= 18
fn log(message: string) => println("[log] {message}")

fn main() {
    log("starting")
    println(square(9), isAdult(15))
}
```

```text title="Output"
[log] starting
81 false
```

The `-> Type` is still needed to return the value. Without it, the function returns nothing and the expression's value is thrown away:

```vex title="noresult.vx"
fn one() => 1

fn main() {
    let x = one()
}
```

```text title="Output"
error: this expression has no value to store
 --> noresult.vx:4:13
  |
4 |     let x = one()
  |             ^^^^^
```

An [`if` with an `else`](/docs/language/control-flow#if-as-a-value) and a `match` both give a value, so either can be an `=>` body:

```vex title="matchbody.vx"
fn sign(n: int) -> string => if n < 0 { "negative" } else if n == 0 { "zero" } else { "positive" }

fn label(n: int) -> string => match n {
    0 => "none"
    1 => "one"
    _ => "many"
}

fn main() {
    println(sign(-3), sign(0), sign(8))
    println(label(0), label(1), label(5))
}
```

```text title="Output"
negative zero positive
none one many
```

A function whose body is `=> panic("...")` type-checks with any result type, which is handy for stubs: `fn later() -> int => panic("not yet")`.

## Named arguments

Arguments are positional by default, and any argument can also be given by its parameter's name:

```vex title="named.vx"
fn move(x: int, y: int, speed: int) -> string => "to ({x}, {y}) at {speed}"

fn main() {
    println(move(1, 2, 10))
    println(move(1, 2, speed: 10))
    println(move(x: 1, y: 2, speed: 10))
    println(move(speed: 10, y: 2, x: 1))
}
```

```text title="Output"
to (1, 2) at 10
to (1, 2) at 10
to (1, 2) at 10
to (1, 2) at 10
```

- The parameter name is the argument label; there are no separate external labels as in Swift.
- Named arguments can come in any order.
- Unnamed arguments come first. An unnamed argument after a named one is an error: `unnamed argument after a named one`.
- Naming an argument that was already given by position is an error: `argument 'a' is given twice`.

Name an argument when its meaning isn't obvious from the value: `resize(width: 200)` reads better than `resize(200)`, and `true` or `nil` arguments almost always deserve a name.

## Default values

A parameter can have a default value, which the caller may leave out:

```vex title="defaults.vx"
fn greet(name: string, greeting: string = "Hi", punct: string = "!") {
    println("{greeting}, {name}{punct}")
}

fn main() {
    greet("Sam")
    greet("Sam", greeting: "Welcome")
    greet("Sam", punct: "?")
    greet("Sam", "Yo", ".")
}
```

```text title="Output"
Hi, Sam!
Welcome, Sam!
Hi, Sam?
Yo, Sam.
```

With defaults, one function covers what other languages do with overloads. Leave out any defaulted argument and name the ones after it.

### Default value rules

- A default is evaluated at each call that leaves the argument out, so a default list is a new list every time:

```vex title="freshdefault.vx"
fn addTo(x: int, list: [int] = []) -> [int] {
    list.push(x)
    return list
}

fn main() {
    println(addTo(1), addTo(2))
}
```

```text title="Output"
[1] [2]
```

- A default can't refer to other parameters: `fn f(a: int, b: int = a + 1)` gives `unknown name 'a'`. It can use constants, literals, other functions and interpolation.
- A parameter with a default can come before one without. The later ones must then be named whenever the earlier one is left out: with `fn pad(a: int = 1, b: int)`, call `pad(b: 2)` or `pad(3, 4)`.
- Defaults belong to the declared function. A function stored in a variable takes every argument: see [Closures](/docs/language/closures).

## Calling mistakes

The compiler checks every call against the declaration:

```vex title="calls.vx"
fn greet(name: string, greeting: string = "Hi") {
    println("{greeting}, {name}")
}

fn main() {
    greet()
    greet("Ann", "Hello", "!")
    greet("Ann", greting: "Yo")
    greet(42)
}
```

```text title="Output"

6 |     greet()
  |     ^^^^^ e.g. greet(name: ...)
```

## Parameters

Parameters are like `let` variables: they can't be reassigned.

```vex title="param.vx"
fn countdown(from: int) {
    var n = from
    while n > 0 {
        print("{n} ")
        n -= 1
    }
    println()
}

fn main() {
    countdown(3)
}
```

```text title="Output"
3 2 1 
```

Assigning to a parameter gives `can't change parameter 'from'` with the hint `copy it first: var myFrom = from`.

### How arguments are passed

Arguments are passed the way assignment works. Numbers, booleans, strings, records and enums are values, so the function gets its own copy. Lists, maps and structs are references, so the function can change the caller's object, though it can't make the caller's variable point at a different one:

```vex title="passing.vx"
fn tryToChange(n: int, xs: [int]) {
    var local = n
    local += 100
    xs.push(local)
}

fn main() {
    let n = 1
    let xs = [0]
    tryToChange(n, xs)
    println(n, xs)
}
```

```text title="Output"
1 [0, 101]
```

Pass `xs.copy()` when the function shouldn't affect your list.

## Recursion

Functions can call themselves, and each other:

```vex title="recursion.vx"
fn factorial(n: int) -> int {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)
}

fn fib(n: int) -> int => match n {
    0 => 0
    1 => 1
    _ => fib(n - 1) + fib(n - 2)
}

fn main() {
    println(factorial(20), fib(20))
}
```

```text title="Output"
2432902008176640000 6765
```

`factorial(21)` doesn't fit in an `int`, so it stops with an overflow error rather than returning a wrong number. Recursion that never stops ends with a clear message instead of a crash:

```vex title="forever.vx"
fn forever(n: int) -> int => forever(n + 1) + 1

fn main() {
    println(forever(0))
}
```

```text title="Output"
error: stack overflow: too many nested function calls, probably a function that calls itself without stopping
```

## Local functions

A function can be declared inside another function, or inside any block. A local function sees the variables around it, like a [closure](/docs/language/closures), and can call itself:

```vex title="local.vx"
fn countLeaves(tree: [string: [string]], root: string) -> int {
    var leaves = 0

    fn visit(node: string) {
        let children = tree[node] ?? []
        if children.isEmpty {
            leaves += 1
        }
        for child in children {
            visit(child)
        }
    }

    visit(root)
    return leaves
}

fn main() {
    let tree = ["root": ["a", "b"], "a": ["a1", "a2"]]
    println(countLeaves(tree, "root"))

    fn double(x: int) -> int => x * 2
    fn quad(x: int) -> int => double(double(x))
    println(quad(3), [1, 2, 3].map(double))
    let f = quad
    println(f(5))
}
```

```text title="Output"
3
12 [2, 4, 6]
20
```

- A local function captures the variables declared before it by reference, as a closure does: `visit` above adds to the `leaves` of its own call of `countLeaves`. Inside a method, it can use the struct's fields too.
- It is a value: pass it as `xs.map(double)`, or store it in a variable. Like any function value, it is called with unnamed arguments: `add(a: 1, b: 2)` gives `function values don't have parameter names`.
- `async`, `throws` and `=>` bodies work as at the top level.

```vex title="local_kinds.vx"
import "vex:time"

fn sumDigits(s: string) throws -> int {
    fn digit(c: string) throws -> int {
        guard let d = int.parse(c) else {
            throw Error("not a digit: {c}")
        }
        return d
    }

    var total = 0
    for c in s.chars() {
        total += try digit(c)
    }
    return total
}

async fn main() {
    println(try? sumDigits("123"), try? sumDigits("1x"))

    async fn later(x: int) -> int {
        await time.sleep(1)
        return x + 1
    }
    println(await later(4))
}
```

```text title="Output"
6 nil
5
```

### Local function rules

Unlike top-level functions, a local function must be declared before it is used, so two local functions can't call each other. Its parameters can't have default values, and it can't have type parameters yet. It can't be assigned, and its name can't be declared again in the same block:

```vex title="local_errors.vx"
fn main() {
    fn first<T>(xs: [T]) -> T => xs[0]
    fn greet(name: string = "you") {}
    println(later())
    fn later() -> int => 1
    later = fn() => 2
    fn later() -> int => 3
}
```

```text title="Output"
error: local functions can't have type parameters yet
 --> local_errors.vx:2:14
  |
2 |     fn first<T>(xs: [T]) -> T => xs[0]
  |              ^ declare it at the top level

error: parameters of local functions can't have default values
 --> local_errors.vx:3:29
  |
3 |     fn greet(name: string = "you") {}
  |                             ^^^^^ remove the default, or declare the function at the top level

error: local function 'later' is used before it is declared
 --> local_errors.vx:4:13
  |
4 |     println(later())
  |             ^^^^^ move the declaration of later above this line

error: can't assign to local function 'later'
 --> local_errors.vx:6:5
  |
6 |     later = fn() => 2
  |     ^^^^^ declare a variable holding a function instead: var f = later

error: 'later' is already declared on line 5
 --> local_errors.vx:7:8
  |
7 |     fn later() -> int => 3
  |        ^^^^^ choose another name, or assign to it without let/var

5 errors
```

For functions that call each other, or that need defaults or type parameters, declare them at the top level and pass in what they need.

## No overloading

Two functions can't share a name, even with different parameter types: `function 'f' is already declared on line 1`. Use default values, named arguments, [generics](/docs/language/generics) or different names (`parseInt`, `parseFloat`) instead. There are no variadic parameters either; take a list.

## Static functions

Inside a struct or enum, `static fn` declares a function that belongs to the type rather than to a value. It's called through the type name, and is the usual way to write extra constructors:

```vex title="static.vx"
struct Temperature {
    celsius: float

    static fn fromFahrenheit(f: float) -> Temperature {
        return Temperature(celsius: (f - 32.0) * 5.0 / 9.0)
    }

    fn describe() -> string => "{celsius} C"
}

fn main() {
    let t = Temperature.fromFahrenheit(212.0)
    println(t.describe())
}
```

```text title="Output"
100.0 C
```

Methods, `static` members and getters are covered on the [Structs](/docs/language/structs) page.

## Rules and edge cases

- Parameter names in one function must differ: `parameter 'a' is declared twice`.
- A function with a result type and no `return` on some path: `missing return: f must return int`.
- Without `-> T`, a function returns nothing, even with an `=>` body.
- Function names can't be keywords or built-in function names such as `print` or `str`.
- A local variable can shadow a function's name for the rest of its block.
- Local functions are declared before use, capture the variables around them, and can't have default parameter values or type parameters yet.
- `main` takes no parameters and returns nothing; see [Basics](/docs/language/basics#program-structure).
