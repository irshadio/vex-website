This guide describes the Vex language as the compiler implements it today, version `0.1.0-dev`. It goes from the basics (variables, types, control flow) through functions and collections (lists, maps, sets and bytes) to structs, enums, pattern matching, error handling, generics, interfaces and extensions, and ends with the memory model. Each page explains a feature, shows complete programs with their real output, and lists the exact rules and error messages for the cases you'll want to look up.

If you're new to Vex, read the [Language tour](/docs/tour) first for a quick overview, then come back here for the details.

## Principles

Vex is designed to be readable at first sight for anyone who knows Swift, Kotlin, Dart, Go or TypeScript. A few principles explain most of its choices:

- **Familiar syntax.** `let` and `var`, `fn`, `name: Type`, and `if` and `for` without parentheses. If a construct looks like one from those languages, it usually means the same thing.
- **Low noise.** No semicolons, no parentheses around conditions, and no `self.` inside methods: fields and methods are in scope directly.
- **One way to create things.** A struct value is created as `User(name: "Ann")`, and every other type is created the same way. There's no `new`.
- **Readable calls.** Any argument can be named, and parameters can have defaults, so a call says what each value means.
- **Interpolation over concatenation.** `"Hi {name}"` instead of `"Hi " + name`. Strings join with `+` only to other strings.
- **Nothing silent.** Numbers never convert by themselves, integer overflow stops the program instead of wrapping, conditions must be `bool`, and `nil` only exists in optional types.
- **Visible failure.** A function that can fail says `throws`, and every call to it says `try`.
- **Helpful errors.** Diagnostics point at the exact spot and usually suggest the fix, including for habits from other languages such as `? :`, `count := 0` or `map.get(key)`.
- **Native speed.** Vex compiles to C and then to a native binary. Generics are specialized per type, errors are returned rather than unwound, and memory is managed by a fast garbage collector.

## How to read this guide

Pages are ordered so that each one only relies on the pages before it, but each also stands on its own for lookup.

- **Code blocks with a file name** (`title="hello.vx"`) are complete programs. Save one to a file and run it with `vex run hello.vx`. The output shown under it is the real output of the current compiler.
- **Code blocks without a file name** are fragments, meant to be read inside a `main` function or next to other declarations.
- **Error messages** are quoted exactly as the compiler prints them, so you can search for them. Compile errors show the line, the column and a hint; runtime errors show the source line and exit with code 1. See [Compile errors](/docs/tools/compile-errors) and [Runtime errors](/docs/tools/runtime-errors).
- **"Rules and edge cases"** sections near the end of each page list the precise behaviour: what's allowed, what isn't, and what happens at the boundaries.
- **"Comparison"** tables map Vex features to their counterparts in other languages, where that helps.
- **Planned** callouts mark features that are designed but not built yet. Anything not marked that way works today.

## Keywords

These 33 words are reserved and can't be used as names:

| Keyword | Use | Page |
|---|---|---|
| `as` | Rename an import; give an `extern` declaration its C name; `as?` casts an interface value | [Modules](/docs/projects/modules), [C interop](/docs/projects/c-interop), [Types](/docs/language/types#type-tests) |
| `async` | Declare a function that can `await` | [Async](/docs/concurrency/async) |
| `await` | Wait for a future without blocking | [Async](/docs/concurrency/async) |
| `break` | Leave the innermost loop, or a named one | [Control flow](/docs/language/control-flow#break-and-continue) |
| `catch` | Handle an error from `try` | [Errors](/docs/language/errors) |
| `const` | Declare a compile-time constant | [Constants](/docs/language/constants) |
| `continue` | Skip to the next iteration of the innermost loop, or of a named one | [Control flow](/docs/language/control-flow#break-and-continue) |
| `else` | Alternative branch of `if` and `guard` | [Control flow](/docs/language/control-flow) |
| `enum` | Declare an enum | [Enums](/docs/language/enums) |
| `extern` | Declare a C function or C pointer type | [C interop](/docs/projects/c-interop) |
| `false` | Boolean literal | [Types](/docs/language/types) |
| `fn` | Declare a function, closure or function type | [Functions](/docs/language/functions) |
| `for` | Loop over a range, list or map; produce collection elements | [Control flow](/docs/language/control-flow) |
| `guard` | Unwrap an optional or leave: `guard let` | [Control flow](/docs/language/control-flow) |
| `if` | Conditional, also as a value; `if let`, `if case`; collection elements | [Control flow](/docs/language/control-flow) |
| `import` | Use another module | [Modules](/docs/projects/modules) |
| `in` | Separate loop variables from the sequence in `for`; end the parameters of a trailing block: `{ a, b in ... }` | [Control flow](/docs/language/control-flow), [Closures](/docs/language/closures#blocks-with-parameters) |
| `interface` | Declare an interface | [Interfaces](/docs/language/interfaces) |
| `is` | Test which type an interface value holds | [Types](/docs/language/types#type-tests) |
| `let` | Declare a name that can't be reassigned, in a function or at the top level; a struct field that never changes after creation | [Basics](/docs/language/basics), [Structs](/docs/language/structs#let-fields) |
| `match` | Choose by pattern | [Patterns](/docs/language/patterns) |
| `nil` | The absent value of an optional | [Optionals](/docs/language/optionals) |
| `pub` | Make a declaration visible to other modules | [Modules](/docs/projects/modules) |
| `return` | Leave a function, with or without a value | [Functions](/docs/language/functions) |
| `static` | A member that belongs to the type: `static fn`, `static const`, `static var`; a static requirement of an interface | [Structs](/docs/language/structs), [Interfaces](/docs/language/interfaces#static-requirements-and-self) |
| `struct` | Declare a struct | [Structs](/docs/language/structs) |
| `throw` | Raise an error | [Errors](/docs/language/errors) |
| `throws` | Mark a function that can fail | [Errors](/docs/language/errors) |
| `true` | Boolean literal | [Types](/docs/language/types) |
| `try` | Call a function that can fail; `try?` | [Errors](/docs/language/errors) |
| `typedef` | Declare a type alias | [Types](/docs/language/types#type-aliases) |
| `var` | Declare a name that can be reassigned, in a function or at the top level | [Basics](/docs/language/basics) |
| `while` | Loop while a condition holds; `while let`; the end of `repeat { } while` | [Control flow](/docs/language/control-flow) |

### Contextual words

These words have a special meaning only in certain places, and are ordinary names everywhere else:

| Word | Special where | Page |
|---|---|---|
| `case` | `if value case pattern` | [Patterns](/docs/language/patterns) |
| `when` | A condition on a `match` arm or `if case` | [Patterns](/docs/language/patterns) |
| `get`, `set` | Start a getter or setter in a struct, interface or extension | [Structs](/docs/language/structs) |
| `didSet` | A block after a field that runs after each assignment | [Structs](/docs/language/structs) |
| `oldValue` | The previous value inside `didSet` | [Structs](/docs/language/structs) |
| `operator` | Define an operator in a struct or enum | [Structs](/docs/language/structs#operators), [Enums](/docs/language/enums#operators) |
| `extension` | Add members to an existing type or interface, at the top level; `extension type` declares a distinct wrapper type | [Extensions](/docs/language/extensions) |
| `sealed` | `sealed interface`: an interface only its own module can implement | [Interfaces](/docs/language/interfaces#sealed-interfaces) |
| `export` | `export fn`: a function callable from C | [C interop](/docs/projects/c-interop) |
| `type` | `extern type`: a C pointer type; `extension type`: a distinct type that wraps one value | [C interop](/docs/projects/c-interop), [Extension types](/docs/language/extensions#extension-types) |
| `new` | `Type.new`: a constructor as a function value | [Closures](/docs/language/closures#tear-offs) |
| `self` | The current value inside a method; can't be declared as a name | [Structs](/docs/language/structs) |
| `Self` | The type that implements an interface, in its requirements; a struct's or enum's own type, in its methods | [Interfaces](/docs/language/interfaces#static-requirements-and-self) |
| `init` | `init { ... }`: a block in a struct that runs at each creation | [Structs](/docs/language/structs#init-blocks) |
| `private` | `private(set)`: a field only the struct can assign | [Structs](/docs/language/structs#privateset-fields) |
| `it` | The unnamed parameter of a trailing block that takes one | [Closures](/docs/language/closures#blocks-with-parameters) |
| `repeat` | `repeat { ... } while condition`: a loop that runs at least once | [Control flow](/docs/language/control-flow#repeat-while) |
| `defer` | `defer { ... }`: a block that runs when the block around it ends | [Control flow](/docs/language/control-flow#defer) |
| `_` | Skips a value in patterns and loops | [Patterns](/docs/language/patterns) |

The built-in type names (`int`, `float`, `bool`, `string`), the built-in functions (`print`, `println`, `input`, `panic`, `assert`, `str`, `int`, `float`) and `Error` aren't keywords, but they can't be used as names of your own either. See [Basics](/docs/language/basics#reserved-names).
