Vex has a small set of operators, and each one works only on the types it makes sense for. Numbers don't convert silently, integer overflow stops the program instead of producing a wrong number, and comparisons can't be chained by accident. This page lists every operator, its exact behaviour and the order in which operators combine.

## Arithmetic

| Operator | Meaning | Works on |
|---|---|---|
| `a + b` | Addition | `int`, `float`; also joins two `string`s |
| `a - b` | Subtraction | `int`, `float` |
| `a * b` | Multiplication | `int`, `float` |
| `a / b` | Division | `int` (truncating), `float` |
| `a % b` | Remainder | `int` only |
| `-a` | Negation | `int`, `float` |
| `a &+ b`, `a &- b`, `a &* b` | Wrapping addition, subtraction, multiplication | `int` only |

Both operands must have the same type. An `int` and a `float` don't mix, but a whole-number literal adapts to a float, so `price * 2` works when `price` is a `float`:

```vex title="arith.vx"
fn main() {
    let price = 2.5
    let count = 4
    println(price * 2, 1 + 2.5, float(count) * price, count * 3)
}
```

```text title="Output"
5.0 3.5 10.0 12
```

Structs and enums can define `+`, `-`, `*`, `/`, `%`, unary `-`, `==`, `<` and indexing for themselves. See [Structs](/docs/language/structs#operators) and [Enums](/docs/language/enums#operators).

## Integer arithmetic

`int` is 64 bits wide. Integer arithmetic is checked: every result is either exact or the program stops with a message naming the operation.

### Division and remainder

`/` on integers truncates toward zero, and `%` gives a remainder with the same sign as the left operand, as in C, Go, Swift and Java:

```vex title="divide.vx"
fn main() {
    println(7 / 2, -7 / 2, 7 / -2)
    println(7 % 3, -7 % 3, 7 % -3)
}
```

```text title="Output"
3 -3 -3
1 -1 1
```

For a floor division or a remainder that's never negative, adjust the result yourself: `((a % n) + n) % n`.

### Overflow

When a result doesn't fit in an `int`, the program stops with the operands in the message:

```vex title="intoverflow.vx"
fn main() {
    var big = 9223372036854775807
    println(big * 2)
}
```

```text title="Output"
error: integer overflow: 9223372036854775807 * 2 doesn't fit in an int; use &* to wrap around
 --> intoverflow.vx:3
```

Every case that can overflow is checked:

| Expression | Result |
|---|---|
| `9223372036854775807 + 1` | `integer overflow: 9223372036854775807 + 1 doesn't fit in an int; use &+ to wrap around` |
| `-9223372036854775808 - 1` | `integer overflow: -9223372036854775808 - 1 doesn't fit in an int; use &- to wrap around` |
| `9223372036854775807 * 2` | `integer overflow: 9223372036854775807 * 2 doesn't fit in an int; use &* to wrap around` |
| `-x` where `x` is `-9223372036854775808` | `integer overflow: -(-9223372036854775808) doesn't fit in an int` |
| `-9223372036854775808 / -1` | `integer overflow: -9223372036854775808 / -1 doesn't fit in an int` |
| `-9223372036854775808 % -1` | `0`, which is exact, so no error |

The checks are cheap: one flag test after each operation, with the failure path kept out of the way. A [constant](/docs/language/constants) that overflows is caught at compile time instead: `this constant overflows int`.

### Division by zero

Integer division or remainder by zero stops the program:

```vex title="divzero.vx"
fn main() {
    var zero = 0
    println(10 % 3)
    println(10 / zero)
}
```

```text title="Output"
1
error: division by zero
 --> divzero.vx:4
```

For `%`, the message is `division by zero in %`. Float division by zero doesn't stop the program; it gives `inf`, `-inf` or `nan` (see [Floats](/docs/language/types#float-arithmetic)).

### Wrapping operators

`&+`, `&-` and `&*` do two's complement arithmetic that wraps around instead of stopping. They exist for code that wants modular arithmetic, such as hashes and random number generators, and for tight loops where you have proved the values stay in range and want the checks gone. They work only on `int`.

```vex title="wrap.vx"
fn nextRandom(seed: int) -> int => seed &* 6364136223846793005 &+ 1442695040888963407

fn main() {
    let max = 9223372036854775807
    println(max &+ 1, -max &- 2, max &* 2)
    var h = 0
    h &+= max
    h &+= 1
    println(h)
    var seed = 42
    for i in 0..3 {
        seed = nextRandom(seed)
        print("{(seed % 100 + 100) % 100} ")
    }
    println()
}
```

```text title="Output"
-9223372036854775808 9223372036854775807 -2
-9223372036854775808
77 20 75 
```

`&+` and `&-` have the same precedence as `+` and `-`, and `&*` the same as `*`.

## Bitwise operators

| Operator | Meaning |
|---|---|
| `a & b` | And |
| `a \| b` | Or |
| `a ^ b` | Exclusive or |
| `~a` | Not: flips every bit |
| `a << n` | Shift left by `n` bits |
| `a >> n` | Shift right by `n` bits, keeping the sign |

They work only on `int`, for colors, option masks for UIKit and Android, flags, hashing and binary formats:

```vex title="bits.vx"
const HIDDEN = 1 << 0
const SELECTED = 1 << 1

fn main() {
    let argb = 0xFF336699
    println((argb >> 16) & 0xFF, (argb >> 8) & 0xFF, argb & 0xFF)
    var flags = 0
    flags |= HIDDEN | SELECTED
    flags &= ~HIDDEN
    println(flags, flags & SELECTED != 0, flags ^ 0b11)
    println(1 << 62, 1 << 63, -16 >> 2)
}
```

```text title="Output"
51 102 153
2 true 1
4611686018427387904 -9223372036854775808 -4
```

- As in Swift, `<<` and `>>` bind tightest, `&` binds like `*`, and `|` and `^` like `+`. All of them bind tighter than comparisons, so `flags & SELECTED != 0` means `(flags & SELECTED) != 0`.
- Bits shifted out of the top are lost, as in Swift and Go, so `1 << 63` is the smallest int. `>>` copies the sign bit in, so `-16 >> 2` is `-4`.
- A shift by less than 0 or more than 63 stops the program with `shift by 64, outside 0 to 63`. A constant shift out of that range is a compile error: `this constant shifts by 64, outside 0 to 63`.
- Constants can use them: `const MASK = ~0xF0 & 0xFF` is computed when compiling.
- A single `&` or `|` between two bools is an error with a hint: `'&' works only on int, found bool`, `use && for logical and`.

## Comparison

| Operator | Meaning |
|---|---|
| `a == b`, `a != b` | Equal, not equal |
| `a < b`, `a <= b`, `a > b`, `a >= b` | Ordering |
| `a === b`, `a !== b` | Same object, not the same object |

Which types can be compared:

| Type | `==` `!=` | `<` `<=` `>` `>=` |
|---|---|---|
| `int`, `float` | yes | yes |
| `string` | yes, by text | yes, code point by code point |
| `bool` | yes | no |
| enum whose cases carry no values | yes | yes, in declaration order |
| enum whose cases carry values | if it lists `Equatable` or `Hashable`: the case, then its values; or if it defines `operator ==` | if it defines `operator <` |
| record | yes, field by field, if every field can be compared | no |
| struct | if it lists `Equatable` or `Hashable`, which compare every field, or defines `operator ==` | if it defines `operator <` |
| list | yes, element by element, if the elements can be compared | no |
| map | yes, entry by entry whatever their order, if the values can be compared | no |
| set | yes, item by item whatever their order | no |
| `Bytes` | yes, byte by byte | no |
| optional | yes: equal when both are `nil` or both hold equal values | no |
| function, interface value | no | no |

Both sides must have the same type. `1 < 2.5` works because the literal `1` adapts, but an `int` variable compared with a `float` is an error (`can't compare int with float`). An optional can be compared with `nil` or with a plain value; it equals the value only when it isn't `nil` and holds that value:

```vex title="optcompare.vx"
fn main() {
    let a: int? = 5
    let b: int? = nil
    println(a == 5, a == 6, b == 5, b == nil)
    println(a ?? 0 > 3)
}
```

```text title="Output"
true false false true
true
```

Ordering doesn't work on optionals: `a < 3` gives `can't compare int? with int`. Write `a ?? 0 < 3`, or unwrap with `if let`. Floats compare by IEEE 754 rules: `nan` isn't equal to anything, and `-0.0 == 0.0`.

### Identity

`===` and `!==` tell whether two references point to the same object. `==` asks whether two values are equal, which for a struct means it lists `Equatable` or defines `==`:

```vex title="identity.vx"
struct Point: Equatable {
    x: int
    y: int
}

fn main() {
    let p = Point(x: 1, y: 2)
    let q = Point(x: 1, y: 2)
    println(p == q, p === q, p === p)
    let xs = [1, 2]
    let ys = xs
    println(xs == [1, 2], xs === [1, 2], xs === ys)
    println(["a": 1, "b": 2] == ["b": 2, "a": 1])
}
```

```text title="Output"
true false true
true false true
true
```

- `===` works on structs, lists, maps, sets, `Bytes`, interface values, C handles and enums whose cases carry values. Any struct can use it, whether or not it has `==`.
- Ints, strings, functions and other values have no identity: `n === 1` gives `'===' compares references, but an int is a value`, with the hint `use == to compare values`.
- `===` has the same precedence as `==`, and doesn't chain either.

### Comparisons don't chain

`a < b < c` is an error rather than a surprise:

```vex title="chain.vx"
fn main() {
    let x = 5
    println(1 < x < 10)
}
```

```text title="Output"
error: comparisons can't be chained
 --> chain.vx:3:19
  |
3 |     println(1 < x < 10)
  |                   ^ use a < b && b < c
```

The same applies to `a == b == c`. Mixing the two levels is allowed, since they have different precedence: `1 < 2 == true` is `(1 < 2) == true`.

## Logical operators

| Operator | Meaning |
|---|---|
| `!a` | Not |
| `a && b` | And |
| `a \|\| b` | Or |

The operands must be `bool`. `&&` and `||` short-circuit: the right side runs only when it can change the result.

```vex title="logic.vx"
fn check(label: string, v: bool) -> bool {
    println("checked {label}")
    return v
}

fn main() {
    println(check("a", false) && check("b", true))
    println(check("c", true) || check("d", true))
    println(!true || true, true || false && false)
}
```

```text title="Output"
checked a
false
checked c
true
true true
```

`&&` binds tighter than `||`, so `true || false && false` is `true || (false && false)`. `&` and `|` are [bitwise operators](#bitwise-operators) on ints; between two bools they're an error with a hint to write `&&` or `||`.

## Assignment

`=` assigns to a `var`, a list element, a map entry or a struct field. Compound assignment operators combine an operation with assignment:

| Operator | Same as | Works on |
|---|---|---|
| `a += b` | `a = a + b` | `int`, `float`, `string` |
| `a -= b`, `a *= b`, `a /= b` | `a = a - b` and so on | `int`, `float` |
| `a %= b` | `a = a % b` | `int` |
| `a &+= b`, `a &-= b`, `a &*= b` | `a = a &+ b` and so on | `int` |
| `a &= b`, `a \|= b`, `a ^= b`, `a <<= b`, `a >>= b` | `a = a & b` and so on | `int` |

```vex title="assign.vx"
fn main() {
    var x = 10
    x += 5
    x -= 3
    x *= 2
    x /= 4
    x %= 4
    var s = "ab"
    s += "c"
    var xs = [1, 2, 3]
    xs[1] += 10
    println(x, s, xs)
}
```

```text title="Output"
2 abc [1, 12, 3]
```

- Assignment is a statement, not an expression. `let y = (x = 3)` and `if x = 1` don't compile; in a condition, the compiler reports `use == to compare in a condition`.
- There is no `++` or `--`. Write `x += 1`.
- A map entry can't use a compound operator, because the key may be missing: `m["a"] += 1` gives `the key may be missing, so '+=' can't be used on a map entry`. Write `m["a"] = (m["a"] ?? 0) + 1`. See [Maps](/docs/language/maps).
- Only a variable, element or field can be assigned to: `can't assign to this expression`.

## Ranges

`a..b` is the integers from `a` up to but not including `b`. `a..=b` includes `b`. A range is a value of type `Range`: it drives `for` loops, slices lists and strings, can be stored and passed around, and also appears in [patterns](/docs/language/patterns). [Ranges](/docs/language/lists#ranges) covers its members, `step`, `reversed` and slicing.

```vex title="ranges.vx"
fn main() {
    for i in 0..3 { print("{i} ") }
    for i in 1..=3 { print("{i} ") }
    for i in 5..2 { print("never ") }
    let n = 4
    for i in n - 2..n { print("{i} ") }
    println()
    let r = 0..n + 1
    println(r, r.len, r.contains(n))
    let grade = match 85 {
        90..=100 => "A"
        80..90 => "B"
        _ => "C"
    }
    println(grade)
}
```

```text title="Output"
0 1 2 1 2 3 2 3 
0..5 5 true
B
```

- `..` and `..=` bind looser than arithmetic and `is`, and tighter than `??` and comparisons: `0..n + 1` is `0..(n + 1)`, `r ?? 0..1` is `r ?? (0..1)`, and `0..3 == 0..=2` compares two ranges.
- Bounds must be `int`: `range bounds must be int, found float`. In patterns, ranges also match floats.
- A range whose end is before its start is empty: the loop body doesn't run.
- In a `for` loop, both bounds are evaluated once, before the loop starts.
- Ranges don't chain: `0..5..9` gives `ranges can't be chained`, with the hint `use one range, e.g. a..c`.
- Only inside `[ ]` can an end be left out: `xs[2..]`, `xs[..2]`. Elsewhere, `0..` gives `a range needs an end`.

## Optional operators

`??` gives a fallback for `nil`, `?.` reads a member only when the value isn't `nil`, and `?[ ]` indexes only when it isn't. Both are covered in full on the [Optionals](/docs/language/optionals) page.

```vex title="optional.vx"
fn fallback() -> int {
    println("fallback ran")
    return 0
}

fn main() {
    let some: int? = 7
    let none: int? = nil
    println(some ?? fallback())
    println(none ?? fallback())
    println(none ?? some ?? 0)
    let words: [string]? = nil
    println(words?.len ?? 0, words?[0] ?? "none")
}
```

```text title="Output"
7
fallback ran
0
7
0 none
```

- `a ?? b` runs `b` only when `a` is `nil`.
- `??` groups to the right: `a ?? b ?? c` is `a ?? (b ?? c)`, and tries each in turn.
- `??` binds tighter than comparisons and looser than arithmetic and ranges: `a ?? 0 > 5` is `(a ?? 0) > 5`, and `a ?? 1 + 2` is `a ?? (1 + 2)`.
- The right side of `??` can be `return`, `throw`, `break` or `continue`, which leaves when the left side is `nil`: `let n = int.parse(text) ?? return 0`. See [Leaving early](/docs/language/optionals#leaving-early).
- `x?.name` is `nil` when `x` is `nil`, and otherwise the member wrapped in an optional. A call through `?.`, such as `user?.greet()`, runs only when `user` isn't `nil`.
- `xs?[i]` is `nil` when `xs` is `nil`, and otherwise `xs[i]` as an optional; an index out of range still stops the program. See [Optional indexing](/docs/language/optionals#optional-indexing).

## Type tests

`x is T` asks whether an interface value holds a `T`, and `x as? T` gives it as a `T`, or `nil`. Both are covered on the [Types](/docs/language/types#type-tests) page.

```vex
if shape is Circle { println(shape.radius) }
let r = (shape as? Rect)?.width ?? 0.0
```

`is` and `as?` bind looser than `+` and tighter than `??`, so the parentheses around `shape as? Rect` are needed before `?.`.

## Precedence

From highest (binds tightest) to lowest:

| Level | Operators | Grouping |
|---|---|---|
| 1 | Postfix: call `f(x)`, index `a[i]`, member `a.b`, optional member `a?.b`, optional index `a?[i]` | left to right |
| 2 | Prefix: `-a`, `!a`, `~a`, `await a`, `try a` | right to left |
| 3 | `<<` `>>` | left to right |
| 4 | `*` `/` `%` `&*` `&` | left to right |
| 5 | `+` `-` `&+` `&-` `\|` `^` | left to right |
| 6 | `is` `as?` | left to right |
| 7 | `..` `..=` | don't chain |
| 8 | `??` | right to left |
| 9 | `<` `<=` `>` `>=` | don't chain |
| 10 | `==` `!=` `===` `!==` | don't chain |
| 11 | `&&` | left to right |
| 12 | `\|\|` | left to right |

Assignment (`=`, `+=` and the rest) isn't an expression and so has no precedence: it's always the whole statement.

```vex title="precedence.vx"
fn main() {
    let a: int? = nil
    let x = 2
    println(2 + 3 * 4, (2 + 3) * 4, 10 - 4 - 3, 100 / 10 / 5)
    println(-x * 3, 7 - 2 - 1, 2 * 3 % 4)
    println(a ?? 1 + 1, (a ?? 1) + 1)
    println(1 + 2 == 3 && 4 > 3 || false)
}
```

```text title="Output"
14 20 3 2
-6 4 2
2 2
true
```

`try` is special: it covers arithmetic after it but not `??` or comparisons. `try a() + b()` handles errors from both calls, and `try? parse(s) ?? 0` gives `0` when parsing fails. See [Errors](/docs/language/errors).

When an expression mixes levels in a way that isn't obvious, add parentheses. They never change the meaning of an already-correct expression and cost nothing.

## Operators Vex doesn't have

| Operator | In Vex |
|---|---|
| `x++`, `x--` | `x += 1`, `x -= 1` |
| `c ? a : b` | `if c { a } else { b }`; the compiler suggests it. See [if as a value](/docs/language/control-flow#if-as-a-value) |
| `a ** b` | `math.pow(a, b)` for `int`, `math.powf(a, b)` for `float`, from [`vex:math`](/docs/stdlib/math) |
| `a % b` on floats | not supported |
| `cond = x` in a condition | `==` |

## Rules and edge cases

- Arithmetic operands must have the same type: `can't use '*' with int and float`.
- `+` on a string and anything else: `can't use '+' with string and int`.
- `%`, `%=`, the wrapping operators and the bitwise operators reject floats: `'%' can't be used with float`, `&+= can't be used with float`, `'&' works only on int, found float`.
- `!` needs a `bool`: `'!' needs a bool, found int`.
- Lists, maps and sets have no arithmetic operators: `[1] + [2]` gives `'+' can't be used with [int]`. They compare with `==` and `===`.
- Operands run left to right, including for operators that structs define.
