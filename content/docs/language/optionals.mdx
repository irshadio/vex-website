A type ending in `?` holds either a value of that type or `nil`. Every other type always has a value. The compiler makes you check an optional before you use the value inside, so a missing value can't crash the program.

```vex title="find.vx"
struct User {
    name: string
    manager: User? = nil
}

fn findUser(users: [User], name: string) -> User? {
    for u in users {
        if u.name == name {
            return u
        }
    }
    return nil
}

fn main() {
    let ann = User(name: "Ann")
    let bob = User(name: "Bob", manager: ann)
    let users = [ann, bob]

    if let u = findUser(users, "Bob") {
        println("found {u.name}")
    }
    let boss = findUser(users, "Bob")?.manager?.name ?? "nobody"
    println("Bob reports to {boss}")
    println(findUser(users, "Zed"))
}
```

```text title="Output"
found Bob
Bob reports to Ann
nil
```

## Optional types and nil

Write `?` after any type to make it optional: `int?`, `string?`, `User?`, `[int]?`. `nil` is the absence of a value.

```vex title="declare.vx"
fn main() {
    let age: int? = 31                    // a plain value becomes an optional where one is expected
    var picked: string? = nil             // nil needs a known type
    println(age, picked)
    picked = "blue"
    println(picked)
    picked = nil
    println(picked)
}
```

```text title="Output"
31 nil
blue
nil
```

`nil` needs a type to belong to, and it can only go where an optional is expected:

```vex title="nil_errors.vx"
fn main() {
    let a = nil
    let b: int = nil
}
```

```text title="Output"
error: can't tell the type of nil
 --> nil_errors.vx:2:13
  |
2 |     let a = nil
  |             ^^^ write the type, e.g. let user: User? = nil

error: nil can't be used as int, which always has a value
 --> nil_errors.vx:3:18
  |
3 |     let b: int = nil
  |                  ^^^ make the type optional: int?

2 errors
```

A function returning `T?` can return a plain `T` or `nil`; the value is wrapped for you. The same happens when you pass a `T` to a `T?` parameter, or store it in a `T?` field or list.

### Where the ? goes

`?` applies to the whole type to its left, and comes last:

| Type | Meaning |
|---|---|
| `[int?]` | a list whose elements may be `nil` |
| `[int]?` | a list, or `nil` |
| `[string: int]` | lookups give `int?` already; values can't be optional |
| `fn()?` | an optional function |
| `(fn() -> int)?` | an optional function that returns `int`; the parentheses are required |

A type can be optional only once: `int??` is reported as `a type can only be optional once`.

### Where optionals come from

Besides your own functions, optionals come from:

- map lookups: `ages["ann"]` is `int?`
- `map.remove(key)`
- `string.indexOf(x)`
- `?.` chains and `try?` (see [Errors](/docs/language/errors))
- `extern fn` declarations that return `string?` or a handle `Db?` (see [C interop](/docs/projects/c-interop))

## You must check before using

An optional value can't be used as if it were the plain type. Reading a field, calling a method, doing arithmetic or passing it where a plain type is expected are all errors:

```vex title="unchecked.vx"
struct User {
    name: string
}

fn find(id: int) -> User? => nil

fn main() {
    let u = find(1)
    println(u.name)
    let n: int? = 5
    println(n + 1)
}
```

```text title="Output"
error: can't read 'name' from a User?: it may be nil
 --> unchecked.vx:9:15
  |
9 |     println(u.name)
  |               ^^^^ use ?.name, or unwrap it first with if let

error: can't use '+' with int? and int
  --> unchecked.vx:11:13
   |
11 |     println(n + 1)
   |             ^^^^^

2 errors
```

There is no force unwrap operator (no `!` as in Swift or Kotlin's `!!`). Every optional is checked with one of the forms below. If a missing value really is a bug, write that decision down: `guard let x = maybe else { panic("...") }`.

## if let

`if let name = optional { ... }` runs the block only when the value isn't `nil`, with `name` bound to the plain value inside. An `else` block runs when it is `nil`:

```vex title="if_let.vx"
fn main() {
    let ages = ["ann": 31, "bob": 25]
    if let a = ages["ann"] {
        println("ann is {a}")                 // a is an int here
    }
    if let z = ages["zoe"] {
        println("zoe is {z}")
    } else {
        println("no age for zoe")
    }
    if let a = ages["cat"] {
        println(a)
    } else if let b = ages["bob"] {
        println("bob is {b}")
    }
}
```

```text title="Output"
ann is 31
no age for zoe
bob is 25
```

- The name is a new constant, only visible inside the block. It may reuse the optional's name: `if let user = user { ... }`, or in short, `if let user { ... }`.
- Several bindings and conditions can follow, separated by commas; see [Several conditions](#several-conditions).
- The value must be optional:

```vex title="if_let_plain.vx"
fn main() {
    let n = 5
    if let x = n {
        println(x)
    }
}
```

```text title="Output"
error: if let needs an optional value, but this is int
 --> if_let_plain.vx:3:16
  |
3 |     if let x = n {
  |                ^ it always has a value, so a plain let works
```

## guard let

`guard let name = optional else { ... }` is the early-exit form. When the value is `nil`, the `else` block runs and must leave: with `return`, `break`, `continue`, `throw` or `panic(...)`. After the `guard`, `name` is the plain value for the rest of the enclosing block:

```vex title="guard.vx"
fn parseAge(text: string) -> int? {
    if text == "" || text.contains(" ") {
        return nil
    }
    return int(text)
}

fn describe(text: string) -> string {
    guard let age = parseAge(text) else {
        return "'{text}' isn't an age"
    }
    // age is an int from here on
    if age < 18 {
        return "{age}: minor"
    }
    return "{age}: adult"
}

fn main() {
    for t in ["31", "", "12", "4 2"] {
        println(describe(t))
    }
}
```

```text title="Output"
31: adult
'' isn't an age
12: minor
'4 2' isn't an age
```

`guard let` keeps the main path of a function unindented: check the inputs at the top, then work with plain values. `guard` also works with a plain condition, as in `guard b != 0 else { return nil }`; see [Control flow](/docs/language/control-flow#guard).

An `else` block that can fall through is an error, since the name would have no value after it:

```vex title="guard_leave.vx"
fn main() {
    let maybe: int? = nil
    guard let y = maybe else {
        println("none")
    }
}
```

```text title="Output"
error: the else block of guard must leave, so 'y' always has a value after it
 --> guard_leave.vx:3:30
  |
3 |     guard let y = maybe else {
  |                              ^ end it with return, break, continue or panic(...)
```

## while let

`while let name = optional { ... }` evaluates the optional before each pass and stops at the first `nil`. It is the natural loop for linked structures and for functions that return `nil` when they run out:

```vex title="while_let.vx"
struct Node {
    value: int
    next: Node? = nil
}

fn main() {
    let list = Node(value: 1, next: Node(value: 2, next: Node(value: 3)))
    var cur: Node? = list
    var total = 0
    while let n = cur {
        total += n.value
        cur = n.next
    }
    println(total)
}
```

```text title="Output"
6
```

`break` and `continue` work inside as in any loop.

## Several conditions

`if let`, `guard let` and `while let` can unwrap several values and check conditions in one header, separated by commas. They are checked left to right, and each name is visible to the conditions after it, so a later binding can use an earlier one. The block runs only when every value is there and every condition holds; the first that fails stops the check:

```vex title="if_let_many.vx"
struct User {
    name: string
    email: string? = nil
}

fn notify(user: User?, enabled: bool) {
    if let user, let email = user.email, enabled {
        println("sending to {user.name} <{email}>")
    } else {
        println("nothing sent")
    }
}

fn main() {
    let ann = User(name: "Ann", email: "ann@example.com")
    notify(ann, true)
    notify(ann, false)
    notify(User(name: "Bob"), true)
    notify(nil, true)
}
```

```text title="Output"
sending to Ann <ann@example.com>
nothing sent
nothing sent
nothing sent
```

`if let user` is short for `if let user = user`: it unwraps a variable under the same name. The shorthand works in every position, and in `guard` and `while` too. The variable must be optional, as with the long form: `if let name` on a `string` gives `if let needs an optional value, but this is string`.

With `guard`, every name it binds is a plain value after it, for the rest of the block:

```vex title="guard_many.vx"
fn area(width: string, height: string) -> string {
    guard let w = int.parse(width), let h = int.parse(height), w > 0, h > 0 else {
        return "bad size"
    }
    return "area {w * h}"
}

fn main() {
    println(area("3", "4"))
    println(area("3", "x"))
    println(area("0", "4"))
}
```

```text title="Output"
area 12
bad size
bad size
```

- A `guard` adds its names to the block it is in, so it can't reuse the name of a variable already declared there. A function's parameters count as declared in its body, which rules out `guard let name` for a parameter `name`:

```vex title="guard_same.vx"
fn greet(name: string?) -> string {
    guard let name else {
        return "hello, stranger"
    }
    return "hello, {name}"
}

fn main() {
    println(greet("Ann"))
}
```

```text title="Output"
error: 'name' is already declared on line 1
 --> guard_same.vx:2:15
  |
2 |     guard let name else {
  |               ^^^^
```

Pick a new name, `guard let n = name`, or use `if let name`, whose name lives only in its block.

- A line break may follow a comma, so `if let a = x,` can have its next condition on the next line.
- The names exist only where every condition has held: inside the first block of `if` and `while`, and after a `guard`. The `else` block of an `if` or a `guard` can't use them; in a `guard`'s `else`, a bound name gives `unknown name`.
- A plain condition must be a `bool`. An optional `bool` needs unwrapping too: `if let done = flag, done`.
- `if value case pattern` can't take more conditions after a comma; add them with `when` (see [Control flow](/docs/language/control-flow#if-case)).

## Optional chaining with ?.

`a?.b` reads `b` from `a` when `a` has a value, and gives `nil` when `a` is `nil`. The result is always optional. It works for fields, getters and method calls:

```vex title="chaining.vx"
struct Person {
    name: string
    manager: Person? = nil
    email: string? = nil

    fn greet() {
        println("hi, {name}")
    }
}

fn main() {
    let maya = Person(name: "Maya", email: "maya@example.com")
    let omar = Person(name: "Omar", manager: maya)
    let lena = Person(name: "Lena", manager: omar)

    println(lena.manager?.name)                 // string?
    println(lena.manager?.manager?.name)        // each optional step needs ?.
    println(maya.manager?.manager?.name)        // stops at the first nil
    println(lena.manager?.email)                // a field that is itself optional

    let nobody: Person? = nil
    nobody?.greet()                             // not called
    lena.manager?.greet()                       // called
}
```

```text title="Output"
Omar
Maya
nil
nil
hi, Omar
```

- A method call through `?.` runs only when the value isn't `nil`. Its result, if any, becomes optional.
- **Each step after an optional needs its own `?.`**. `?.` doesn't skip the rest of the chain the way Swift's does. In `s?.upper().len`, `s?.upper()` is a `string?`, so `.len` must be `?.len`:

```vex title="chain_step.vx"
fn main() {
    let s: string? = "a"
    let t = s?.upper().len
}
```

```text title="Output"
error: can't read 'len' from a string?: it may be nil
 --> chain_step.vx:3:24
  |
3 |     let t = s?.upper().len
  |                        ^^^ use ?.len, or unwrap it first with if let
```

The fixed version is `s?.upper()?.len`.

- `?.` is only for optional values: `"hi"?.len` is an error that suggests `.`.
- You can't assign through `?.`: `user?.name = "x"` is an error. Unwrap with `if let` first, then assign.
- There is no optional call (`f?()`). Unwrap first with `if let`.
- `x?.method` without a call gives a function bound to the value, or `nil` (see [Closures](/docs/language/closures)).

## Optional indexing

`xs?[i]` indexes an optional list, map or string. It gives `nil` when the value is `nil`, and otherwise what `xs[i]` gives, as an optional:

```vex title="optindex.vx"
fn main() {
    var scores: [int]? = nil
    println(scores?[0])
    scores = [90, 75, 60]
    println(scores?[1], scores?[1..], scores?[0] ?? 0)

    let ages: [string: int]? = ["ann": 31]
    println(ages?["ann"], ages?["zoe"])

    let title: string? = "hello"
    println(title?[0..=0])
    if let first = scores?[0] {
        println("first {first}")
    }
}
```

```text title="Output"
nil
75 [75, 60] 90
31 nil
h
first 90
```

- An index out of range still stops the program: `?[ ]` only checks for `nil`, as `?.` does.
- On a map, `m?[k]` is `nil` when the map is `nil` or the key is missing.
- Ranges work too, and so does a struct that defines `operator []`.
- It chains with `?.`: `user?.tags?[0]`.
- Assigning through it is an error, `can't assign through ?[ ]`, with the hint `unwrap it first with if let`.

## Default values with ??

`a ?? b` gives the value inside `a`, or `b` when `a` is `nil`. When `b` is a plain value the result is plain, so `??` is the usual way to leave optional-land:

```vex title="default.vx"
fn expensive() -> int {
    println("computing the default")
    return 0
}

fn main() {
    let ages = ["ann": 31]
    let a = ages["ann"] ?? 0                    // int, not int?
    let z = ages["zoe"] ?? 0
    println(a, z)

    let present: int? = 1
    println(present ?? expensive())             // the right side doesn't run
    let missing: int? = nil
    println(missing ?? expensive())             // it runs only for nil

    let first: int? = nil
    let second: int? = nil
    println(first ?? second ?? 7)               // tries each in turn
}
```

```text title="Output"
31 0
1
computing the default
0
7
```

- The right side runs only when the left side is `nil`.
- `??` groups to the right, so `a ?? b ?? c` tries `a`, then `b`, then `c`. If the last one is optional, so is the result.
- The left side must be optional, and the default must have the matching type:

```vex title="default_errors.vx"
struct User {
    name: string
}

fn main() {
    let n = 5
    let c = n ?? 0
    let u: User? = nil
    let h = u?.name ?? 3
}
```

```text title="Output"
error: ?? needs an optional on the left, but this is int
 --> default_errors.vx:7:13
  |
7 |     let c = n ?? 0
  |             ^ it always has a value, so ?? isn't needed

error: the default after ?? must be string, found int
 --> default_errors.vx:9:24
  |
9 |     let h = u?.name ?? 3
  |                        ^ convert it with str(...) or "{...}"

2 errors
```

`?.` and `??` are often used together: `user?.manager?.name ?? "nobody"`.

### Leaving early

The right side of `??` can be `return`, `throw`, `break` or `continue` instead of a default. It runs when the left side is `nil`, and otherwise the result is the plain value, so one line unwraps a value or leaves:

```vex title="leave.vx"
fn port(text: string) -> int {
    let n = int.parse(text) ?? return 80
    return n
}

fn load(settings: [string: string], key: string) throws -> string {
    let value = settings[key] ?? throw Error("missing {key}")
    return value.upper()
}

fn main() {
    println(port("8080"), port("web"))

    var total = 0
    for word in ["4", "x", "7", "stop", "9"] {
        if word == "stop" { break }
        let n = int.parse(word) ?? continue
        total += n
    }
    println(total)

    let settings = ["mode": "dark"]
    println(try? load(settings, "mode"))
    println(try? load(settings, "font"))

    let codes: [string: int] = ["a": 1]
    for key in ["a", "b", "a"] {
        let code = codes[key] ?? break
        print("{code} ")
    }
    println()
}
```

```text title="Output"
8080 80
11
DARK
nil
1 
```

- The statement follows the usual rules: `return` gives what the function returns, `throw` needs a function that throws, and `break` and `continue` need a loop, and can name one, as in `?? continue outer`.
- It takes the rest of the expression: in `a ?? return n + 1`, the function returns `n + 1`. Wrap it in parentheses to use the value in a larger expression: `(a ?? return 0) * 2`.
- It ends a chain: `a ?? b ?? return` tries `a`, then `b`, then leaves.
- It works only after `??`. Anywhere else, such as `let y = return`, it gives `return can only be used as a statement or after ??`. In a constant outside a function it gives `return after ?? only works inside a function`.

## Comparing with nil

An optional can be compared with `nil`, with a plain value or with another optional, using `==` and `!=`. Two optionals are equal when both are `nil` or both hold equal values, and an optional equals a plain value only when it isn't `nil` and holds that value:

```vex title="nil_compare.vx"
fn main() {
    var selected: string? = nil
    println(selected == nil, selected == "Lena")
    selected = "Lena"
    println(selected != nil, selected == "Lena")
    let other: string? = "Lena"
    println(selected == other)
}
```

```text title="Output"
true false
true true
true
```

Comparing doesn't unwrap the optional, so its value still can't be used as a plain one:

```vex title="compare_errors.vx"
fn main() {
    let a: int? = 5
    if a == 5 {
        println(a + 1)
    }
}
```

```text title="Output"
error: can't use '+' with int? and int
 --> compare_errors.vx:4:17
  |
4 |         println(a + 1)
  |                 ^^^^^
```

To use the value after a check, use `if let`, which checks and unwraps in one step.

Comparing a plain value with `nil` is an error: `can't compare int with nil: only optional values can be nil`.

## Printing

An optional prints as its value, or `nil`:

```vex title="print.vx"
fn main() {
    let a: int? = 3
    let s: string? = nil
    println(a, s, "{s}", [s, "x"])
}
```

```text title="Output"
3 nil nil [nil, "x"]
```

Note that a string inside an optional prints without quotes on its own, like any string, and with quotes inside a list.

## Optional fields

A field of optional type usually defaults to `nil`, so callers can leave it out:

```vex title="fields.vx"
struct Person {
    name: string
    email: string? = nil

    fn contact() -> string => email ?? "no email"
}

fn main() {
    println(Person(name: "Omar").contact())
    println(Person(name: "Maya", email: "maya@example.com").contact())
}
```

```text title="Output"
no email
maya@example.com
```

An optional field without a default must be passed explicitly, even as `nil`.

## Optionals in collections

A list can hold optionals: `[int?]`. Map values can't be optional, since a missing key already reads as `nil`. A `...?` spread adds the elements of an optional list, or nothing when it is `nil`:

```vex title="collections.vx"
fn main() {
    let maybes: [int?] = [1, nil, 3]
    var total = 0
    for m in maybes {
        total += m ?? 0
    }
    println(maybes, total)

    let extra: [int]? = nil
    let more: [int]? = [8, 9]
    println([0, ...?extra, ...?more])
}
```

```text title="Output"
[1, nil, 3] 4
[0, 8, 9]
```

`?x` inside a list or map literal adds an optional value only when it isn't `nil`, as in Dart: `[primary, ?secondary]` is a `[string]` without the `nil`. See [Null-aware elements](/docs/language/lists#null-aware-elements) and [Null-aware entries](/docs/language/maps#null-aware-entries).

## Rules and edge cases

- Only `T?` can hold `nil`. A plain `T` always has a value, and `nil` needs a known optional type.
- A `T` is accepted wherever `T?` is expected.
- No force unwrap. Use `if let`, `guard let`, `while let`, `?.` or `??`.
- `if let`, `guard let` and `while let` take several bindings and conditions separated by commas; every bound value must be optional. `if let x` is short for `if let x = x`.
- The `else` of `guard` must leave the enclosing block, and can't use the names the `guard` binds.
- Each step after an optional in a chain needs `?.`; the result of `?.` is always optional.
- No assignment through `?.` or `?[ ]`, and no optional calls.
- `??` evaluates its right side only for `nil`, and groups to the right. The right side can be `return`, `throw`, `break` or `continue`.
- Optionals compare with `nil` only; `x != nil` doesn't unwrap `x`.
- `T??` doesn't exist, and map values can't be optional.
- `nil` isn't a `match` pattern.
