A struct groups named values, called fields, into one type, and can carry methods that work on them. Structs are the main way to model data in Vex.

```vex title="user.vx"
struct User {
    name: string
    age: int = 18

    fn greet() -> string => "Hi, I'm {name}"
    fn isAdult() -> bool => age >= 18
}

fn main() {
    let ann = User(name: "Ann", age: 30)
    println(ann.greet())
    println(ann.isAdult())
    println(ann)
}
```

```text title="Output"
Hi, I'm Ann
true
User(name: "Ann", age: 30)
```

## Declaring a struct

A struct declaration lists its fields as `name: Type`, one per line. A field can have a default value after `=`.

```vex
struct Account {
    owner: string
    balance: float = 0.0
    history: [string] = []
    nickname: string? = nil
}
```

Fields on one line are separated by commas:

```vex
struct Point { x: int, y: int }
```

A struct can have no fields at all: `struct Marker {}` is created with `Marker()`.

### Fields typed by their defaults

A field with a default can leave out its type, which then comes from the default:

```vex title="inferred.vx"
struct Settings {
    volume = 5                            // an int
    theme = "dark"                        // a string
    recent = ["home"]                     // a [string]
    ratio = 1.5                           // a float
}

fn main() {
    let s = Settings(volume: 8)
    s.recent.push("search")
    println(s)
}
```

```text title="Output"
Settings(volume: 8, theme: "dark", recent: ["home", "search"], ratio: 1.5)
```

A field needs a type whenever its default doesn't say which: `nil`, an empty `[]` or an empty `[:]`. Fields of a generic struct always need a type:

```vex title="needs_type.vx"
struct Node {
    parent = nil
    items = []
    counts = [:]
}

struct Box<T> {
    value: T
    label = "box"
}

fn main() {}
```

```text title="Output"
error: can't tell the type of nil
 --> needs_type.vx:2:14
  |
2 |     parent = nil
  |              ^^^ write the type, e.g. let user: User? = nil

error: can't tell the type of an empty list
 --> needs_type.vx:3:13
  |
3 |     items = []
  |             ^^ give the field a type, e.g. items: [int] = []

error: can't tell the type of an empty map
 --> needs_type.vx:4:14
  |
4 |     counts = [:]
  |              ^^^ give the field a type, e.g. counts: [string: int] = [:]

error: fields of a generic struct need a type
 --> needs_type.vx:9:5
  |
9 |     label = "box"
  |     ^^^^^ write its type: label: T = ...

4 errors
```

Write them as `parent: Node? = nil`, `items: [string] = []` and `label: string = "box"`. A field with neither a type nor a default is an error too: `field 'y' needs a type`, with the hint `write it as y: int, or give it a value: y = 0`.

### `let` fields

A field declared with `let` is set when the struct is created and never changes afterwards. Fields without `let` can change (see [Mutability](#mutability)):

```vex title="let_fields.vx"
struct User {
    let id: int                           // set at creation, never changed
    name: string
    tags = ["new"]
}

fn main() {
    let u = User(id: 1, name: "Ann")
    u.name = "Ann Lee"
    u.tags.push("admin")                  // the list itself can still change
    println(u)
}
```

```text title="Output"
User(id: 1, name: "Ann Lee", tags: ["new", "admin"])
```

Assigning a `let` field is an error, from outside the struct and from its own methods alike:

```vex title="let_assign.vx"
struct User {
    let id: int
    name: string

    fn reset() {
        id = 0
    }
}

fn main() {
    let u = User(id: 1, name: "Ann")
    u.id = 2
}
```

```text title="Output"
error: can't change 'id': it's a let field of User
 --> let_assign.vx:6:9
  |
6 |         id = 0
  |         ^^ set it when creating the User, or make a changed copy with copy(id: ...)

error: can't change 'id': it's a let field of User
  --> let_assign.vx:12:7
   |
12 |     u.id = 2
   |       ^^ set it when creating the User, or make a changed copy with copy(id: ...)

2 errors
```

- `let` stops the field from being assigned, not the value inside it from changing: a `let` list can still be pushed to.
- A `let` field can have a default, a type or both, like any field. The one place it can be assigned is the struct's [`init` block](#init-blocks).
- A `let` field can't have a [`didSet`](#observing-changes-with-didset) block: `a let field never changes, so it can't have didSet`.
- A `let` field can't meet an interface's `set` requirement: `field 'name' is a let field, so it can't provide the setter Named requires`.
- Fields don't use `var`: `fields don't use 'var'`, with the hint `fields change unless declared with let: write name: type`.

### `private(set)` fields

A field marked `private(set)` can be read wherever the field is visible, but only assigned inside the struct's own methods:

```vex title="private_set.vx"
struct Counter {
    private(set) count = 0
    step = 1

    fn tap() {
        count += step
    }
}

fn main() {
    let c = Counter(step: 2)
    c.tap()
    c.tap()
    println(c.count)
    c.count = 10
}
```

```text title="Output"
error: can't set 'count' outside Counter: it's private(set)
  --> private_set.vx:15:7
   |
15 |     c.count = 10
   |       ^^^^^ call a method of Counter that changes it
```

- Creating the struct, or a [copy](#copies) of it, can still give the field a value: `Counter(count: 5)` and `c.copy(count: 0)` both work.
- [Extensions](/docs/language/extensions) of the struct in its own module count as inside it. Extensions in other modules don't.
- A field that is public and only changed by the struct is written `pub private(set) count = 0`. Other modules can read it but not assign it.
- A `let` field can't also be `private(set)`: `a let field can't be private(set)`, since it can't be set at all after creation.

Type names are written in `UpperCamelCase` and fields and methods in `lowerCamelCase`.

## Creating values

Every struct gets a constructor with the same name as the struct. It takes one parameter per field, in the order the fields are declared, and fields with defaults become optional parameters.

```vex title="create.vx"
struct User {
    name: string
    age: int = 18
    tags: [string] = []
}

fn main() {
    println(User(name: "Ann"))
    println(User(name: "Bob", age: 40))
    println(User(age: 25, name: "Cy"))     // named arguments in any order
    println(User("Dee", age: 3))           // positional, then named
    println(User("Eve", 50))               // positional, in field order
}
```

```text title="Output"
User(name: "Ann", age: 18, tags: [])
User(name: "Bob", age: 40, tags: [])
User(name: "Cy", age: 25, tags: [])
User(name: "Dee", age: 3, tags: [])
User(name: "Eve", age: 50, tags: [])
```

The rules are the same as for [function calls](/docs/language/functions): positional arguments come first, named arguments after them, and a named argument can't be followed by an unnamed one. Named arguments are the usual style, since they keep the call readable when fields change order.

There is no `new` keyword. To check or adjust the fields each time a value is created, give the struct an [`init` block](#init-blocks). For creation that can fail, write a [static method](#static-members) that builds the value.

### Missing and unknown arguments

A field without a default must be given:

```vex title="missing.vx"
struct User {
    name: string
    age: int = 18
}

fn main() {
    let a = User(age: 30)
}
```

```text title="Output"
error: missing argument 'name' in call to User
 --> missing.vx:7:13
  |
7 |     let a = User(age: 30)
  |             ^^^^ e.g. User(name: ...)
```

An argument that names no field is an error, with a suggestion when the name is close:

```vex title="unknown.vx"
struct Point { x: int, y: int }

fn main() {
    let p = Point(x: 1, y: 2, z: 3)
}
```

```text title="Output"
error: Point has no parameter 'z'
 --> unknown.vx:4:31
  |
4 |     let p = Point(x: 1, y: 2, z: 3)
  |                               ^ did you mean 'x'?
```

### Default values

A default is an expression that runs each time a value is created without that argument. Each value gets its own result, so a list default is a fresh list for every value, and a default that calls a function calls it every time:

```vex title="defaults.vx"
fn nextId() -> int {
    println("nextId called")
    return 7
}

struct Bag {
    items: [string] = []
    id: int = nextId()
}

fn main() {
    let a = Bag()
    let b = Bag()
    a.items.push("apple")
    println(a.items, b.items)
    let c = Bag(id: 1)                    // nextId isn't called
    println(c.id)
}
```

```text title="Output"
nextId called
nextId called
["apple"] []
1
```

A default can't refer to other fields of the same struct; it is evaluated before the value exists.

```vex title="default_field.vx"
struct R { a: int, b: int = a * 2 }

fn main() {}
```

```text title="Output"
error: unknown name 'a'
 --> default_field.vx:1:29
  |
1 | struct R { a: int, b: int = a * 2 }
  |                             ^
```

A default can create another struct, but not one that would create itself forever:

```vex title="loop_default.vx"
struct S { a: S? = S() }

fn main() {}
```

```text title="Output"
error: the default of 'a' creates another S that uses the same default, so it never ends
 --> loop_default.vx:1:20
  |
1 | struct S { a: S? = S() }
  |                    ^^^ pass that field explicitly, or default it to nil
```

### Trailing blocks

When the last field has a function type, a `{ ... }` block after the call is passed as that field, as with any call:

```vex title="button.vx"
struct Button {
    title: string
    onTap: fn()
}

fn main() {
    var taps = 0
    let add = Button(title: "Add") { taps += 1 }
    add.onTap()
    add.onTap()
    println(add.title, taps)
}
```

```text title="Output"
Add 2
```

See [Closures](/docs/language/closures) for trailing blocks and builder blocks.

## `init` blocks

An `init` block runs each time the struct is created, after its fields are set. It can check them, adjust them, and set `let` fields that have no default:

```vex title="init.vx"
struct Span {
    let low: int
    let high: int
    let size: int
    label: string = ""

    init {
        assert(low <= high, "low must not exceed high")
        label = label.trim()
        size = high - low
    }
}

fn main() {
    let week = Span(low: 2, high: 9, label: "  week ")
    println(week)
    println(Span(low: 5, high: 1))
}
```

```text title="Output"
Span(low: 2, high: 9, size: 7, label: "week")
error: assertion failed: low must not exceed high
 --> init.vx:8
  at Span.init (init.vx:8)
  at main (init.vx:17)
```

- A `let` field without a default that `init` sets in one of its own top-level statements, such as `size` above, is worked out by `init` and isn't a parameter of the constructor. Passing it is an error: `Span has no parameter 'size'`.
- `init` can assign every field of its struct, `let` fields included, though not from a closure inside it.
- Until `init` has set all of the `let` fields it owns, it can't read them, use `self` or call methods.
- `init` takes no parameters: the fields are its input, already set when it runs. It can't be called, can't be `pub`, and a struct has only one.
- `init` can't throw, and can't pass up an error with `try`. Check with `assert`, handle errors with `try?` or `try ... catch`, or create the value in a `static fn` that throws.
- `init` also runs on every [copy](#copies).

The compiler reports each of these:

```vex title="init_errors.vx"
struct Early {
    let size: int
    let twice: int

    init {
        println(size)
        show()
        size = 1
        twice = size * 2
    }

    fn show() {}
}

struct Order {
    total: int

    init {
        if total < 0 {
            throw Error("negative")
        }
    }
}

fn main() {
    let e = Early(size: 1)
}
```

```text title="Output"
error: 'size' is read before init sets it
 --> init_errors.vx:6:17
  |
6 |         println(size)
  |                 ^^^^ set it first in init

error: init can't call method 'show' before it sets every let field
 --> init_errors.vx:7:9
  |
7 |         show()
  |         ^^^^ set 'size' and 'twice' first

error: init can't throw
  --> init_errors.vx:20:13
   |
20 |             throw Error("negative")
   |             ^^^^^^^^^^^^^^^^^^^^^^^ check with assert, or create the struct in a static fn that throws

error: Early has no parameter 'size'
  --> init_errors.vx:26:19
   |
26 |     let e = Early(size: 1)
   |                   ^^^^

4 errors
```

Other mistakes are reported as `init takes no parameters` (for `init(x: int) { }`), `a struct has only one init block; the first is on line 3`, `init can't be marked pub`, and `'init' is reserved for the struct's init block` (for a method named `init`).

## Reading and changing fields

Fields are read and assigned with `.`:

```vex title="fields_rw.vx"
struct Point { x: int, y: int }

fn main() {

    p.x = 10
    p.y += 5
```


## Methods

A method is a function declared inside the struct. Inside a method, the struct's fields and other methods are used by name, without `self.`:

```vex title="account.vx"
struct Account {
    owner: string
    balance: float = 0.0
    history: [string] = []

    fn deposit(amount: float) {
        balance += amount
        history.push("+{amount}")
    }

    fn withdraw(amount: float) -> bool {
        if amount > balance {
            history.push("declined {amount}")
            return false
        }
        balance -= amount
        history.push("-{amount}")
        return true
    }

    fn summary() -> string => "{owner}: {balance}"
}

fn main() {
    let acct = Account(owner: "Ann")
    acct.deposit(50)
    acct.withdraw(20)
    acct.withdraw(500)
    println(acct.summary())
    println(acct.history)
}
```

```text title="Output"
Ann: 30.0
["+50.0", "-20.0", "declined 500.0"]
```

Methods can use every form a function can: parameters with defaults, named arguments, `=>` bodies, `throws` and `async`. See [Functions](/docs/language/functions).

### `self`

`self` is the value the method was called on. You need it in two cases: to pass the whole value somewhere, and to reach a field that a parameter or local variable hides.

```vex title="self.vx"
struct Text {
    value: string

    fn set(value: string) {
        self.value = value                // the parameter hides the field
    }

    fn show() -> string => describe()     // same as self.describe()
    fn describe() -> string => "<{value}>"
}

fn main() {
    let t = Text(value: "a")
    t.set("hi")
    println(t.show())
}
```

```text title="Output"
<hi>
```

Leaving out `self.` keeps methods short. It is safe because a field and a method of the same struct can't share a name, and a local name that hides a field is always visible right there in the method.

`self` itself can't be reassigned; change its fields instead:

```vex title="assign_self.vx"
struct Point {
    x: int
    y: int
    fn reset() {
        self = Point(x: 0, y: 0)
    }
}

fn main() {}
```

```text title="Output"
error: can't assign to self
 --> assign_self.vx:5:9
  |
5 |         self = Point(x: 0, y: 0)
  |         ^^^^ change its fields instead, e.g. self.name = ...
```

## Static members

`static fn` declares a method that belongs to the type rather than to a value. It is called on the type name. `static const` declares a [constant](/docs/language/constants) that belongs to the type.

```vex title="static.vx"
struct Circle {
    static const pi = 3.14159
    radius: float

    fn area() -> float => pi * radius * radius

    static fn unit() -> Circle => Circle(radius: 1)
    static fn ofDiameter(d: float) -> Circle => Circle(radius: d / 2.0)
}

fn main() {
    println(Circle.pi)
    println(Circle.unit().area())
    println(Circle.ofDiameter(4))
}
```

```text title="Output"
3.14159
3.14159
Circle(radius: 2.0)
```

Inside the struct, static members are used by name too: `pi` above, or `unit()` from another method.

Static methods are the place for named constructors. A common pattern is a static method that checks its input before creating the value:

```vex title="factory.vx"
struct Port {
    number: int

    static fn parse(s: string) -> Port? {
        let n = int(s)
        if n < 1 || n > 65535 {
            return nil
        }
        return Port(number: n)
    }
}

fn main() {
    println(Port.parse("8080"), Port.parse("70000"))
}
```

```text title="Output"
Port(number: 8080) nil
```

A static method has no `self`, so it can't use fields, and instance methods can't be called on the type. The compiler explains each mistake:

```vex title="static_errors.vx"
struct User {
    name: string
    age: int = 18

    fn greet() -> string => "Hi, {name}"
    static fn guest() -> User => User(name: "Guest", age: age)
}

fn main() {
    let u = User(name: "Ann")
    println(User.greet())
    println(u.guest())
}
```

```text title="Output"
error: static method guest can't use field 'age'
 --> static_errors.vx:6:59
  |
6 |     static fn guest() -> User => User(name: "Guest", age: age)
  |                                                           ^^^ static methods have no instance; pass the value in as a parameter

  --> static_errors.vx:11:18
   |
11 |     println(User.greet())
   |                  ^^^^^ call it on a value, e.g. user.greet(), or declare it static fn

  --> static_errors.vx:12:15
```

A `const` inside a struct must be `static`.

### `Self`

Inside a struct's methods, `Self` is another name for the struct's own type. It saves repeating a long name, and is how [interfaces](/docs/language/interfaces#static-requirements-and-self) refer to the type that implements them:

```vex title="self_type.vx"
struct Money {
    cents: int

    static fn zero() -> Self => Money(cents: 0)
    fn plus(other: Self) -> Self => Money(cents: cents + other.cents)
}

fn main() {
    println(Money.zero().plus(Money(cents: 250)))
}
```

```text title="Output"
Money(cents: 250)
```

`Self` works in the parameters and results of methods of structs and enums, and in interface requirements. Anywhere else, such as a field type or a top-level function, it is an error: `Self can only be used in the requirements of an interface and in the methods of a struct or enum`. In a generic struct, `Self` includes the type arguments: in `Box<T>`, it is `Box<T>`.

### Static variables

`static var` and `static let` declare a variable that belongs to the type, with one copy shared by the whole program. Unlike a `static const`, the starting value can be anything, function calls included:

```vex title="statics.vx"
struct Router {
    static var stack: [string] = []
    static let home = "/"

    static fn push(page: string) {
        stack.push(page)
    }
}

enum Level {
    low
    high

    static var changes = 0
}

fn main() {
    Router.push(Router.home)
    Router.push("/settings")
    println(Router.stack)
    Router.stack = []
    Level.changes += 1
    println(Router.stack, Level.changes)
}
```

```text title="Output"
["/", "/settings"]
[] 1
```

Static variables follow the rules of [top-level variables](/docs/language/basics#top-level-variables):

- Each one is set up the first time it is used, and each [isolate](/docs/concurrency/isolates) has its own copy.
- Inside the type they are used by name, as `stack` above; outside it, through the type: `Router.stack`.
- A `static let` can't be assigned again: `can't change 'Router.home': it's declared with let`.
- Generic structs and enums can't have static variables (`a generic struct can't have static variables`), and neither can extensions of built-in types.

<Callout type="warn" title="Not yet">
Static methods of a generic struct, such as `Box<T>`, can be declared but not called yet: `Box<int>.make()` is reported as `'Box' is a type, not a value`. Use a top-level generic function instead. Static methods of generic enums work.
</Callout>

## Mutability

Vex has one rule for structs: **`let` and `var` control the name, not the value.**

- `let p = Point(...)` means `p` always refers to the same struct. `var p` lets you point `p` at a different struct later.
- The fields of a struct can be changed through any name that refers to it: a `let`, a `var`, a parameter, a list element or `self` in a method. Only the struct itself decides otherwise, with [`let` fields](#let-fields) and [`private(set)`](#privateset-fields).

```vex title="mutability.vx"
struct Point { x: int, y: int }

fn moveRight(p: Point) {
    p.x += 10                             // changes the caller's struct
}

fn main() {
    let p = Point(x: 1, y: 2)
    p.y = 7                               // allowed: p still names the same struct
    moveRight(p)
    println(p)

    var q = Point(x: 0, y: 0)
    q = Point(x: 5, y: 5)                 // allowed: q is var
    println(q)
}
```

```text title="Output"
Point(x: 11, y: 7)
Point(x: 5, y: 5)
```

Reassigning a `let` name is the error, not changing a field:

```vex title="reassign.vx"
struct Point { x: int, y: int }

fn main() {
    let p = Point(x: 1, y: 2)
    p = Point(x: 0, y: 0)
}
```

```text title="Output"
error: can't change 'p': it's declared with let
 --> reassign.vx:5:5
  |
5 |     p = Point(x: 0, y: 0)
  |     ^ declare it with var p = ... to make it changeable
```

Methods don't need a `mutating` or `mut` marker either. Any method can change fields, and it can be called on a value held by `let`.

<Callout title="Why no read-only structs">
Swift's value-type structs make every change explicit, but they also copy on every assignment and need `mutating`, `inout` and copy-on-write to stay fast. Vex structs are references, like classes in Dart, Kotlin and TypeScript, so a value passed to a function or stored in a list is the same value everywhere. Fields that must not change are declared [`let`](#let-fields). If you want a value that can't change at all, use a [record](/docs/language/records) or an [enum](/docs/language/enums), whose fields are fixed once created.
</Callout>

## Structs are shared references

Assigning a struct, passing it to a function, or putting it in a list doesn't copy it. All of these give another name for the same struct, so a change through one name is seen through every other.

```vex title="shared.vx"
struct Point { x: int }

fn main() {
    let a = Point(x: 1)
    var b = a                             // b and a are the same struct
    b.x = 5
    println(a.x)

    b = Point(x: 9)                       // b now names a new struct; a is unchanged
    println(a.x, b.x)

    let list = [a, a]                     // two references to one struct
    list[0].x = 100
    println(a, list)
}
```

```text title="Output"
5
5 9
Point(x: 100) [Point(x: 100), Point(x: 100)]
```

### Copies

Every struct has a `copy` method that makes a new struct. Named arguments change some fields, and the others are copied as they are:

```vex title="copy.vx"
struct User {
    let id: int
    name: string
    tags: [string] = []
}

fn main() {
    let ann = User(id: 1, name: "Ann", tags: ["admin"])
    let bo = ann.copy(id: 2, name: "Bo")
    println(ann)
    println(bo)
    bo.tags.push("new")                   // the list is shared
    println(ann.tags)
    println(ann.copy() === ann)
}
```

```text title="Output"
User(id: 1, name: "Ann", tags: ["admin"])
User(id: 2, name: "Bo", tags: ["admin"])
["admin", "new"]
false
```

- `copy` takes one optional argument per field, checked like a constructor call: `User.copy has no parameter 'nam'`. `let` and `private(set)` fields can be given new values this way.
- The copy is shallow: list, map and struct fields still refer to the same objects in both.
- The struct's [`init` block](#init-blocks) runs on the copy, and the `let` fields that `init` sets are worked out again rather than copied, so they can't be passed to `copy`.
- A struct that declares its own `copy` method uses that one instead, for example to make a deep copy.
- From another module, `copy` can only change `pub` fields: `field 'note' of bank.Account is private to bank`.

```vex title="copy_init.vx"
struct Span {
    let low: int
    let high: int
    let size: int

    init {
        size = high - low
    }
}

struct Deck {
    cards: [string] = []

    fn copy() -> Deck => Deck(cards: cards.copy())
}

fn main() {
    let s = Span(low: 2, high: 9)
    let wider = s.copy(high: 20)
    println(s.size, wider.size)

    let a = Deck(cards: ["A"])
    let b = a.copy()
    b.cards.push("K")
    println(a.cards, b.cards)
}
```

```text title="Output"
7 18
["A"] ["A", "K"]
```

See [Memory](/docs/language/memory) for how references, values and the garbage collector fit together.

## Printing and string conversion

`println`, `str(...)` and string interpolation all show a struct as its type name followed by every field in declaration order, with strings quoted, unless the struct has a [`toString`](#tostring) method:

```vex title="print.vx"
struct Inner {
    label: string
    weight: float
}

struct Outer {
    inner: Inner
    counts: [string: int]
    maybe: int?
    pair: (int, string)
}

fn main() {
    let o = Outer(inner: Inner(label: "a \"b\"", weight: 2), counts: ["x": 1], maybe: nil, pair: (1, "z"))
    println(o)
    let i = Inner(label: "c", weight: 1.5)
    println("value: {i}", str(i) == "{i}")
}
```

```text title="Output"
Outer(inner: Inner(label: "a \"b\"", weight: 2.0), counts: ["x": 1], maybe: nil, pair: (1, "z"))
value: Inner(label: "c", weight: 1.5) true
```

- Floats always show a decimal point: `2.0`.
- Optional fields show their value or `nil`.
- A generic struct includes its type arguments: `Pair<string, int>(first: "ann", second: 31)`.
- A struct that refers back to itself shows the repeat as `Name(...)` instead of looping forever:

```vex title="cycle_print.vx"
struct Node {
    value: int
    next: Node? = nil
}

fn main() {
    let a = Node(value: 1)
    a.next = a
    println(a)
}
```

```text title="Output"
Node(value: 1, next: Node(...))
```

### `toString`

A struct or enum with a `toString()` method shows as what it returns instead, wherever the value is shown: `println`, `str(...)`, interpolation, and inside lists, maps, optionals, other structs and interface values:

```vex title="to_string.vx"
struct Money {
    cents: int

    fn toString() -> string => "${cents / 100}.{cents % 100}"
}

struct Order {
    item: string
    price: Money
}

fn main() {
    let m = Money(cents: 1250)
    println(m)
    println("cost: {m}")
    println(str(m).len)
    println([m, m], ["lunch": m])
    let maybe: Money? = m
    println(maybe)
    println(Order(item: "tea", price: m))
}
```

```text title="Output"
$12.50
cost: $12.50
6
[$12.50, $12.50] ["lunch": $12.50]
$12.50
Order(item: "tea", price: $12.50)
```

`toString` must be written exactly `fn toString() -> string`. Anything else is an error, since printing calls it with no arguments:

```vex title="to_string_errors.vx"
struct A {
    static fn toString() -> string => "a"
}

struct B {
    fn toString(full: bool) -> string => "b"
}

struct C {
    fn toString() -> int => 1
}

struct D {
    async fn toString() -> string => "d"
}

struct E {
    fn toString() throws -> string => "e"
}

fn main() {}
```

```text title="Output"
error: toString can't be static
 --> to_string_errors.vx:2:15
  |
2 |     static fn toString() -> string => "a"
  |               ^^^^^^^^ printing calls it: write fn toString() -> string

error: toString takes no parameters
 --> to_string_errors.vx:6:17
  |
6 |     fn toString(full: bool) -> string => "b"
  |                 ^^^^^^^^^^ printing calls it: write fn toString() -> string

error: toString must return string, found int
  --> to_string_errors.vx:10:8
   |
10 |     fn toString() -> int => 1
   |        ^^^^^^^^ printing calls it: write fn toString() -> string

error: toString can't be async
  --> to_string_errors.vx:14:14
   |
14 |     async fn toString() -> string => "d"
   |              ^^^^^^^^ printing calls it: write fn toString() -> string

error: toString can't throw
  --> to_string_errors.vx:18:19
   |
18 |     fn toString() throws -> string => "e"
   |                   ^^^^^^ printing calls it: write fn toString() -> string

5 errors
```

- A generic `toString<T>()` is an error too: `toString can't have type parameters`.
- An [extension](/docs/language/extensions) of a struct or enum can add `toString`, with the same effect. Built-in types always print the built-in way, so an extension can't add `toString` to `int`, `string` or another built-in type: `int always prints in its built-in form, so an extension can't add toString`.
- `toString` is also an ordinary method, so `m.toString()` calls it directly.
- Showing `self` inside `toString`, as in `"Money {self}"`, calls `toString` again without end and stops the program with a stack overflow. Show the fields instead.

## Equality

Two struct values are only compared with `==` when the struct asks for it. Without that, `==` is an error and the compiler suggests the fix:

```vex title="equality.vx"
struct Point {
    x: int
    y: int
}

fn main() {
    let p = Point(x: 1, y: 2)
    let q = Point(x: 1, y: 2)
    println(p == q)
}
```

```text title="Output"
error: values of type Point can't be compared with ==
 --> equality.vx:9:13
  |
9 |     println(p == q)
  |             ^^^^^^ list Equatable on it to compare the fields: struct Point: Equatable
```

### Identity

Any struct can be compared with `===` and `!==`, which tell whether two names refer to the same object:

```vex title="identity.vx"
struct Point {
    x: int
    y: int
}

fn main() {
    let p = Point(x: 1, y: 2)
    let same = p
    let other = Point(x: 1, y: 2)
    println(p === same, p === other, p !== other)
}
```

```text title="Output"
true false true
```

### Equatable and Hashable

Listing `Equatable` after a `:` gives a struct an `==` that compares every field. Listing `Hashable` does the same and adds a hash, so its values can be [map keys](/docs/language/maps#structs-enums-and-records-as-keys):

```vex title="hashable.vx"
struct Point: Hashable {
    x: int
    y: int
}

fn main() {
    let a = Point(x: 1, y: 2)
    let b = Point(x: 1, y: 2)
    println(a == b, a != b, a === b)
    var labels = [a: "home"]
    labels[Point(x: 0, y: 0)] = "origin"
    println(labels[b] ?? "?", labels.len)
    println([a, b].contains(Point(x: 1, y: 2)))
}
```

```text title="Output"
true false false
home 2
true
```

`!=`, `list.contains`, `list.indexOf` and the `Equatable` constraint come with it. Enums can list them too; their `==` compares the case and then its values.

- `Equatable` needs every field to have `==`. A field such as a function or an interface value doesn't:

```vex title="eqerr.vx"
struct Button: Equatable {
    title: string
    onTap: fn()
}

fn main() {}
```

```text title="Output"
error: field 'onTap' is fn(), which has no ==, so Button can't be Equatable
 --> eqerr.vx:3:12
  |
3 |     onTap: fn()
  |            ^^^^ write your own operator ==
```

- `Hashable` needs every field to be hashable, or a `float`.
- A generic struct lists the constraint on its parameter: `struct Box<T: Equatable>: Equatable`.
- A struct can contain itself, such as `next: Node?`; the comparison follows the fields.

### Writing your own == and hash

To decide what equal means, define `operator ==`. A struct with its own `==` is `Equatable` without listing it. To also list `Hashable`, write `fn hash() -> int` so that equal values hash the same. The built-in `hash(a, b, ...)` combines the hashes of its arguments:

```vex title="custom.vx"
struct Email: Hashable {
    address: string

    operator ==(other: Email) -> bool => address.lower() == other.address.lower()
    fn hash() -> int => hash(address.lower())
}

fn main() {
    let owners = [Email(address: "Ann@Example.com"): "ann"]
    println(owners[Email(address: "ann@example.com")] ?? "nobody")
    println(Email(address: "A@b.c") == Email(address: "a@B.C"))
}
```

```text title="Output"
ann
true
```

Leaving out `hash` gives `Email writes its own ==, so it needs a matching fn hash() -> int to be Hashable`. `hash` takes no parameters and returns `int`.

## Properties: getters and setters

A getter is read like a field but computed each time. A setter runs when the property is assigned. Both use the property's name:

```vex title="temperature.vx"
struct Temperature {
    celsius: float

    get fahrenheit -> float => celsius * 9.0 / 5.0 + 32.0
    set fahrenheit(f: float) {
        celsius = (f - 32.0) * 5.0 / 9.0
    }

    get isFreezing -> bool => celsius <= 0.0
}

fn main() {
    let t = Temperature(celsius: 100)
    println(t.fahrenheit, t.isFreezing)
    t.fahrenheit = 32                     // runs the setter
    println(t.celsius, t.isFreezing)
    t.fahrenheit += 18                    // reads with the getter, then sets
    println(t.celsius)
    println(t)                            // only stored fields are printed
}
```

```text title="Output"
212.0 false
0.0 true
10.0
Temperature(celsius: 10.0)
```

- A getter has a result type and no parameters, and is read without `()`.
- A setter takes exactly one parameter, the new value, of the getter's type.
- A property with only a getter is read-only. One with only a setter can't be read.
- Getters and setters can't throw.

```vex title="readonly.vx"
struct T {
    c: float
    get f -> float => c
}

fn main() {
    let t = T(c: 1)
    t.f = 3
}
```

```text title="Output"
error: can't assign to 'f': it has a getter but no setter
 --> readonly.vx:8:7
  |
8 |     t.f = 3
  |       ^ add a setter: set f(value: ...) { ... }
```

A common pattern stores the real value in a field with a leading underscore and exposes it through a property. The underscore is only a naming convention; [`pub`](/docs/projects/modules) is what controls visibility.

## Observing changes with didSet

A block after a field runs after every assignment to that field, with the previous value in `oldValue`:

```vex title="didset.vx"
struct Counter {
    count: int = 0 {
        didSet {
            println("count: {oldValue} -> {count}")
        }
    }

    fn bump() { count += 1 }
}

fn main() {
    let c = Counter(count: 5)             // not run when the struct is created
    c.bump()
    c.count = 10
}
```

```text title="Output"
count: 5 -> 6
count: 6 -> 10
```

- It runs for assignments from outside (`c.count = ...`) and inside methods (`count = ...`), but not when the struct is created.
- Assigning the field inside its own `didSet` doesn't run it again, so a `didSet` can clamp the value.
- Changing what a field refers to, such as pushing to a list field, isn't an assignment and doesn't run it.

## Operators

A struct can define operators like methods. `self` is the left operand and the parameter is the right one:

```vex title="vec.vx"
struct Vec {
    x: float
    y: float

    operator +(other: Vec) -> Vec => Vec(x: x + other.x, y: y + other.y)
    operator -() -> Vec => Vec(x: -x, y: -y)
    operator *(k: float) -> Vec => Vec(x: x * k, y: y * k)
    operator ==(other: Vec) -> bool => x == other.x && y == other.y
}

struct Version {
    major: int
    minor: int

    operator ==(other: Version) -> bool => major == other.major && minor == other.minor
    operator <(other: Version) -> bool =>
        major < other.major || (major == other.major && minor < other.minor)
}

fn main() {
    let a = Vec(x: 1, y: 2)
    var v = a + Vec(x: 3, y: 4) * 2
    println(v, -a, v == Vec(x: 7, y: 10))
    v += a                                // v = v + a
    println(v)

    let old = Version(major: 1, minor: 2)
    let new = Version(major: 1, minor: 10)
    println(old < new, old >= new)        // >= comes from <
}
```

```text title="Output"
Vec(x: 7.0, y: 10.0) Vec(x: -1.0, y: -2.0) true
Vec(x: 8.0, y: 12.0)
true false
```

| You define | You get |
|---|---|
| `+ - * / %` (one parameter, any type) | the operator, and its compound assignment (`+=` ...) when it returns the struct |
| unary `-` (no parameter) | `-value` |
| `==` (takes the struct, returns `bool`) | `==`, `!=`, `contains`, the `Equatable` constraint; add `fn hash() -> int` to list `Hashable` |
| `<` and `==` | `<`, `<=`, `>`, `>=`, the `Comparable` constraint |
| `[]` and `[]=` | indexing, `value[i]` and `value[i] = x` |

`!=`, `>`, `<=` and `>=` are derived, so they can't be defined themselves. Operators can't be static, generic, async or throwing, and their parameters have no defaults. See [Operators](/docs/language/operators) for the full list.

## Recursive structs

A struct can contain itself through an optional field or a list, which is how linked lists and trees are built:

```vex title="tree.vx"
struct Node {
    name: string
    children: [Node] = []
    parent: Node? = nil

    fn add(child: Node) {
        child.parent = self
        children.push(child)
    }

    fn depth() -> int {
        var d = 0
        var cur = parent
        while let p = cur {
            d += 1
            cur = p.parent
        }
        return d
    }
}

fn main() {
    let root = Node(name: "root")
    let docs = Node(name: "docs")
    let file = Node(name: "intro.md")
    root.add(docs)
    docs.add(file)
    println(file.depth(), root.children.len, file.parent?.name ?? "-")
}
```

```text title="Output"
2 1 docs
```

The parent and child refer to each other. That cycle is fine: the [garbage collector](/docs/language/memory) frees it once nothing else refers to it, so there is no `weak` keyword.

## Structs and other features

- **Interfaces.** A struct lists the interfaces it implements after a `:`, as in `struct Circle: Shape`. See [Interfaces](/docs/language/interfaces).
- **Generics.** `struct Stack<T> { items: [T] = [] }`. See [Generics](/docs/language/generics).
- **Extensions.** Methods, getters and static members can be added to a struct after it is declared. See [Extensions](/docs/language/extensions).
- **Patterns.** `match p { Point(x: 0, :y) => ... }` tests and takes apart a struct. See [Patterns](/docs/language/patterns).
- **Tear-offs.** `User.new` is the constructor as a function value, and `user.greet` is a method bound to `user`. See [Closures](/docs/language/closures).
- **Modules.** Structs, fields and methods are private to their module unless marked `pub`. Another module can only create a struct whose private fields all have defaults; otherwise it reports `lib.Wall can't be created outside lib because field 'secret' is private`. See [Modules](/docs/projects/modules).

## Rules and edge cases

- Every field has a type, written or taken from its default. A default of `nil`, `[]` or `[:]`, and every field of a generic struct, needs the type written.
- A `let` field is set at creation and, after that, only by `init`. `private(set)` fields are assigned only inside the struct and its extensions in the same module.
- `init` runs after the fields are set, at every creation and every copy. It takes no parameters and can't throw.
- Every struct has `copy(field: value, ...)`, a shallow copy with some fields changed, unless it declares its own `copy`.
- A `fn toString() -> string` method replaces the built-in format wherever the value is shown.
- A field and a method can't have the same name: `'x' is already a field of Point`.
- `let` and `var` on a variable apply to the name, not the struct's fields.
- A `const` inside a struct must be written `static const`.
- Parameters, loop variables and `self` can't be reassigned, but the fields of a struct they refer to can be changed.
- `==` works only on structs that list `Equatable` or `Hashable` or define `operator ==`. `===` works on every struct.
- A struct can be a map key when it lists `Hashable`.
- Default values are evaluated at each creation, can't use other fields, and can't recreate the struct endlessly.
- `didSet` doesn't run during creation, and getters and setters can't throw.
- Structs can't inherit from other structs. Share behavior with [interfaces](/docs/language/interfaces) and their default methods, or by holding another struct in a field.
