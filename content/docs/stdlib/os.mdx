---
title: vex:os
description: API reference for vex:os, which reads command-line arguments and environment variables, finds the working folder, exits, runs shell commands, and names the system the program is built for.
---

`vex:os` gives a program access to its surroundings: the arguments it was started with, environment variables, the folder it runs in, its exit status, other programs it can start through the shell, and the system it is built for.

```vex title="greet.vx"
import "vex:os"

fn main() {
    let args = os.args()
    if args.len == 0 {
        println("usage: greet <name>")
        os.exit(2)
    }
    let greeting = os.env("GREETING") ?? "Hello"
    println("{greeting}, {args[0]}")
}
```

```sh
vex run greet.vx Ann
GREETING=Hi vex run greet.vx Ann
```

```text title="Output"
Hello, Ann
Hi, Ann
```

## Summary

| Group | Function | Result |
|---|---|---|
| Arguments | [`args()`](#args) | The command-line arguments |
| Environment | [`env(name)`](#env) | A variable's value, or `nil` |
| | [`setEnv(name, value)`](#setenv) | Sets a variable |
| Process | [`cwd()`](#cwd) | The current folder; throws |
| | [`exit(code)`](#exit) | Ends the program with an exit status |
| Commands | [`run(command)`](#run) | Runs a shell command; returns its exit status; throws |
| | [`output(command)`](#output) | Runs a shell command; returns what it printed; throws |
| System | [`target`](#target) | The operating system the program is built for, an `os.Target` |
| | [`arch`](#arch) | The processor architecture the program is built for, an `os.Arch` |

Functions marked "throws" need `try`, `try?` or `try ... catch`. They throw a plain `Error` whose message names what failed and the reason the system gave.

## Arguments

### args

```vex
pub fn args() -> [string]
```

Returns the arguments the program was started with, without the program's own name.

- **Parameters:** none.
- **Returns:** A new list of strings, in order. Empty when there were no arguments.
- **Errors:** None.

With a built program, the arguments are the words after its name: `./tool a b` gives `["a", "b"]`. With `vex run`, they are the words after the file or folder; a `--` right after the file is removed, which lets you pass arguments that start with `-`. A later `--` reaches the program like any other argument. See [Passing arguments](/docs/tools/cli#passing-arguments-to-the-program).

```vex title="args.vx"
import "vex:os"

fn main() {
    let args = os.args()
    println(args.len, args)
}
```

```sh
vex run args.vx one "two words" -- --flag
```

```text title="Output"
4 ["one", "two words", "--", "--flag"]
```

There is no flag parser in the standard library yet. Loop over the list and match on the strings you expect.

## Environment

### env

```vex
pub fn env(name: string) -> string?
```

Returns the environment variable `name`, or `nil` if it isn't set.

- **Parameters:** `name`, the variable's name, such as `"HOME"`.
- **Returns:** The value as a string, which may be `""` if the variable is set to nothing, or `nil` when it isn't set at all.
- **Errors:** None.

Give a default with `??`, or unwrap it with `if let` or `guard let`.

### setEnv

```vex
pub fn setEnv(name: string, value: string)
```

Sets the environment variable `name` to `value`, for this program and the programs it starts afterwards with [`run`](#run) and [`output`](#output).

- **Parameters:** `name`, the variable's name; `value`, its new value. An existing value is replaced.
- **Returns:** nothing.
- **Errors:** None. The change never reaches the shell that started the program.

There is no function to unset a variable yet.

```vex title="env.vx"
import "vex:os"

fn main() throws {
    println(os.env("VEX_DEMO") ?? "unset", os.env("NOT_SET_ANYWHERE"))
    os.setEnv("GREETING", "hello")
    println(os.env("GREETING"))
    let status = try os.run("echo $GREETING from the shell")
    println(status)
}
```

```sh
VEX_DEMO=yes vex run env.vx
```

```text title="Output"
yes nil
hello
hello from the shell
0
```

## Process

### cwd

```vex
pub fn cwd() throws -> string
```

Returns the folder the program runs in, the current working directory, as an absolute path.

- **Parameters:** none.
- **Returns:** The path, without a trailing `/`.
- **Errors:** Throws `can't read the current folder: <reason>` if the system can't report it, for example when the folder has been deleted while the program runs.

Relative paths given to [`vex:fs`](/docs/stdlib/fs) are resolved against this folder. It is the folder you ran the program from, not the folder of the source file or the executable.

```vex title="where.vx"
import "vex:os"

fn main() throws {
    let dir = try os.cwd()
    println(dir.startsWith("/"), dir.endsWith("/"))
}
```

```text title="Output"
true false
```

### exit

```vex
pub fn exit(code: int)
```

Stops the program at once with exit status `code`.

- **Parameters:** `code`, the exit status. 0 means success; any other value means failure. Shells see only the low 8 bits, so use 0 to 255.
- **Returns:** never.
- **Errors:** None.

Output already printed is flushed first. Tasks and timers still pending are dropped, and nothing after the call runs. Under `vex run`, the program's exit status becomes the exit status of `vex` itself.

```vex title="exit.vx"
import "vex:os"

fn main() {
    println("checking")
    os.exit(7)
    println("not reached")
}
```

```text title="Output"
checking
```

```sh
vex run exit.vx; echo "status $?"
```

```text
checking
status 7
```

A `fn main() throws` that lets an error escape exits with status 1 instead, after printing `error: <message>`.

## Commands

<Callout type="warn" title="Shell injection">
`run` and `output` pass the command to `/bin/sh` exactly as written. Never build a command from text a user typed or a file provided: a value such as `x; rm -rf ~` would run as a second command.
</Callout>

### run

```vex
pub fn run(command: string) throws -> int
```

Runs `command` with the shell and returns its exit status. The command shares the program's terminal: it reads the same standard input and prints straight to the same standard output and error.

- **Parameters:** `command`, a shell command line. Pipes, redirections and `&&` work, since the shell interprets it.
- **Returns:** The command's exit status, 0 to 255. A command stopped by a signal gives 128 plus the signal number, the same convention shells use. A command that doesn't exist gives 127, the status the shell reports.
- **Errors:** Throws `can't run '<command>': <reason>` only if the shell itself can't be started. A command that runs and fails is not an error: check the status.

`run` waits for the command to finish, and it blocks the whole isolate meanwhile, including other async tasks.

### output

```vex
pub fn output(command: string) throws -> string
```

Runs `command` with the shell and returns what it printed to standard output.

- **Parameters:** `command`, a shell command line.
- **Returns:** Everything the command wrote to standard output, including the final line ending. Its standard error still goes to the terminal; add `2>&1` to the command to capture it too.
- **Errors:** Throws `can't run '<command>': <reason>` if the shell can't be started, and `'<command>' failed with exit status <n>` if the command exits with any status other than 0. The output is lost in that case; use `run` with a redirect to a file if you need both.

```vex title="commands.vx"
import "vex:os"

fn main() throws {
    let status = try os.run("echo from the shell; exit 3")
    println("status", status)

    let out = try os.output("printf 'a\\nb\\n'")
    println(out.lines())

    let failed = try? os.output("exit 4")
    println(failed)

    try os.output("echo hi; exit 5") catch e {
        println(e.message)
    }
    try os.output("nosuchcommand 2>/dev/null") catch e {
        println(e.message)
    }
}
```

```text title="Output"
from the shell
status 3
["a", "b"]
nil
'echo hi; exit 5' failed with exit status 5
'nosuchcommand 2>/dev/null' failed with exit status 127
```

Use `lines()` or `trim()` on the result of `output` to drop the final line ending, as in `try os.output("git rev-parse HEAD").trim()`.

## System

`target` and `arch` are constants, not functions: write `os.target` without `()`. Their values are known when the program is compiled, so an `if` or `match` that tests them compiles only the branch for that system. See [Platform conditionals](#platform-conditionals).

### target

```vex
pub enum Target {
    macos, linux, windows
}

pub const target: Target
```

The operating system the program is built for.

- **Value:** `.macos`, `.linux` or `.windows`.
- **Errors:** None. Assigning to it is a compile error: `can't change constant 'target'`.

### arch

```vex
pub enum Arch {
    arm64, x64
}

pub const arch: Arch
```

The processor architecture the program is built for.

- **Value:** `.arm64` or `.x64`.
- **Errors:** None.

The program is built for the system the compiler runs on, so these name the machine that ran `vex run` or `vex build`. There is no option to build for another system yet.

```vex title="platform.vx"
import "vex:os"

fn main() {
    println(os.target, os.arch)
    let name = match os.target {
        macos => "a Mac"
        linux => "Linux"
        windows => "Windows"
    }
    let bits = if os.arch == .arm64 { "ARM" } else { "x86" }
    println("built for {name} on {bits}")
}
```

On a Mac with Apple silicon it prints:

```text title="Output"
Target.macos Arch.arm64
built for a Mac on ARM
```

On Linux on an Intel or AMD processor, it prints `Target.linux Arch.x64` and `built for Linux on x86`.

`os.Target` and `os.Arch` are ordinary enums whose cases carry no values. They compare with `==`, work in `match`, and can be stored: `let t: os.Target = os.target`. Comparing them with anything else is a compile error, such as `can't compare os.Target with string` for `os.target == "macos"`.

### Platform conditionals

An `if` whose condition is made only of constants, such as `os.target == .windows`, is decided when the program is compiled. Only the branch taken generates C code. The same goes for a `match` on `os.target` or `os.arch`, and for `&&`, `||` and `!` of such tests:

```vex title="fold.vx"
import "vex:os"

extern fn GetTickCount64() -> uint64

const verbose = false

fn main() {
    if os.target == .windows {
        println(GetTickCount64())
    } else {
        println("not Windows")
    }
    if verbose {
        println("details")
    }
    let sep = match os.target {
        windows => "\\"
        _ => "/"
    }
    println(sep)
}
```

On macOS and Linux it prints:

```text title="Output"
not Windows
/
```

`GetTickCount64` exists only in the Windows C library. The program still builds on macOS and Linux, because the branch that calls it generates no code there and nothing refers to the missing function. `if verbose { ... }` generates nothing at all.

- Every branch is still type-checked, so a mistake in code for another system shows up on yours:

  ```text
  error: expected int, found string
   --> err.vx:5:22
    |
  5 |         let n: int = "not checked away"
    |                      ^^^^^^^^^^^^^^^^^^ parse it with int(...)
  ```

- A `match` on `os.target` must handle every system, or have a `_` arm: `match doesn't handle 'windows'`.
- C code that only one system has goes in the [`[c.macos]`, `[c.linux]` or `[c.windows]`](/docs/projects/c-interop#c-code-for-one-system) section of `package.toml`.
