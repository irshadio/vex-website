---
title: vex:time
description: API reference for vex:time, which reads the monotonic and wall clocks, gives futures that complete after a delay, and puts a time limit on a future.
---

`vex:time` reads the clock. It has four functions: `nanos` for measuring how long code takes, `unix` for the current date and time as a number, `sleep` for waiting inside async code, and `timeout` for giving up on a future that takes too long.

```vex title="timing.vx"
import "vex:time"

fn work() -> int {
    var total = 0
    for i in 0..1000000 {
        total += i
    }
    return total
}

fn main() {
    let start = time.nanos()
    let total = work()
    let ms = (time.nanos() - start) / 1000000
    println(total, ms >= 0)
}
```

```text title="Output"
499999500000 true
```

## Summary

| Function | Result |
|---|---|
| [`nanos()`](#nanos) | Nanoseconds from a fixed point, for measuring intervals |
| [`unix()`](#unix) | Seconds since 1970-01-01 UTC |
| [`sleep(ms)`](#sleep) | A `Future<void>` that completes after `ms` milliseconds |
| [`timeout(future, ms)`](#timeout) | The future's value as an optional, `nil` if `ms` milliseconds pass first |

For dates, calendar fields, time zones, durations and ISO 8601 text, use [vex:datetime](/docs/stdlib/datetime). `vex:time` stays the module for measuring and waiting; `time.sleep(d.inMillis)` waits for a `datetime.Duration`.

## nanos

```vex
pub extern fn nanos() -> int as "vx_time_ns"
```

Returns nanoseconds from a fixed point in the past.

- **Parameters:** none.
- **Returns:** An `int` from the system's monotonic clock (`CLOCK_MONOTONIC`). The starting point is arbitrary, often the time the machine booted, so a single reading means nothing. Subtract two readings to get the time between them.
- **Errors:** None.

The monotonic clock never jumps backward when the system time is changed, which makes it right for measuring how long code takes. Divide by `1000000` for milliseconds or by `1000000000` for seconds; use `float(...)` first if you want a fraction:

```vex title="elapsed.vx"
import "vex:time"

fn main() {
    let start = time.nanos()
    var words: [string] = []
    for i in 0..10000 {
        words.push("word {i}")
    }
    let seconds = float(time.nanos() - start) / 1000000000.0
    println(words.len, seconds < 1.0)
}
```

```text title="Output"
10000 true
```

## unix

```vex
pub extern fn unix() -> int as "vx_time_unix"
```

Returns the seconds since 1970-01-01 00:00:00 UTC, the Unix timestamp.

- **Parameters:** none.
- **Returns:** An `int` from the system's wall clock (C `time(NULL)`). It follows the system time, so it can jump if the clock is changed. Use `nanos` to measure intervals.
- **Errors:** None.

```vex title="now.vx"
import "vex:time"

fn main() {
    let now = time.unix()
    let days = now / 86400
    println(now > 1700000000, days > 19000)
}
```

```text title="Output"
true true
```

## sleep

```vex
pub extern fn sleep(ms: int) -> Future<void> as "vx_sleep"
```

Returns a future that completes after `ms` milliseconds.

- **Parameters:** `ms`, the delay in milliseconds. 0 or a negative number completes on the next turn of the event loop.
- **Returns:** A `Future<void>`.
- **Errors:** None.

`await time.sleep(ms)` pauses only the async function it is in. Other tasks and timers keep running meanwhile, so two sleeps started together take as long as the longer one, not the sum:

```vex title="sleep.vx"
import "vex:time"

async fn step(name: string, ms: int) -> string {
    await time.sleep(ms)
    println("{name} done")
    return name
}

async fn main() {
    let start = time.nanos()
    let a = step("slow", 200)
    let b = step("fast", 100)
    let names = await all([a, b])
    println(names)
    let elapsed = (time.nanos() - start) / 1000000
    println(elapsed >= 200 && elapsed < 300)
}
```

```text title="Output"
fast done
slow done
["slow", "fast"]
true
```

Calling `time.sleep` starts the timer at once, even before you await it. A task waiting for a timer keeps the program alive: the program ends only when `main` is done and no tasks are left running. A timer that nothing awaits doesn't keep it alive.

To wait in code that isn't async, pass the future to `run`, which runs the event loop until it completes:

```vex title="pause.vx"
import "vex:time"

fn main() {
    let start = time.nanos()
    run(time.sleep(50))
    println((time.nanos() - start) / 1000000 >= 50)
}
```

```text title="Output"
true
```

`await` outside an async function is a compile error, with a hint to make the function async:

```text
error: await is only allowed in async functions
 --> wait.vx:4:5
  |
4 |     await time.sleep(10)
  |     ^^^^^^^^^^^^^^^^^^^^ make main async: async fn main()
```

## timeout

```vex
timeout(future: Future<T>, ms: int) -> Future<T?>
```

Waits at most `ms` milliseconds for `future`. It is built into the compiler rather than written in `time.vx`, since it works for a future of any type.

- **Parameters:** `future`, the future to wait for, such as the result of an async call without `await`; `ms`, the time limit in milliseconds.
- **Returns:** A future of the value as an optional: the value when `future` finishes in time, otherwise `nil`. For a `Future<void>` it gives a `Future<bool>`, which tells whether the future finished.
- **Errors:** The errors of `future`, if it can fail. A `Future<T, E>` gives a `Future<T?, E>`, so the `await` needs `try`, `try?` or `try ... catch`.

When the time runs out, the late task is cancelled: it stops at its next `await`, and the code after it never runs.

```vex title="timeout.vx"
import "vex:time"

async fn fetch(name: string, ms: int) -> string {
    await time.sleep(ms)
    println("{name} finished")
    return name
}

async fn main() {
    let quick = await time.timeout(fetch("quick", 10), 200)
    println(quick)
    let slow = await time.timeout(fetch("slow", 500), 50) ?? "offline"
    println(slow)
    let done = await time.timeout(time.sleep(10), 100)
    println(done)
}
```

```text title="Output"
quick finished
quick
offline
true
```

`slow finished` is never printed: the timeout cancelled `fetch("slow", 500)` while it slept.

A future whose value is already optional can't be timed out, since `nil` would mean both a timeout and a missing value:

```text
error: time.timeout gives nil when the time runs out, so the future's value can't be optional itself
 --> timeout.vx:4:32
  |
4 |     let x = await time.timeout(maybe(), 10)
  |                                ^^^^^^^ wrap the value, e.g. in a record, to tell nil from a timeout
```

See [Timeouts](/docs/concurrency/async#timeouts) for more examples, and [Cancellation](/docs/concurrency/async#cancellation) for cancelling futures yourself with `cancel()`.
