This tour shows every major feature of Vex with a short, complete program and its output. It moves fast: each section links to the page in the [language guide](/docs/language) that covers the topic in depth. Every program here compiles with the current compiler, so you can paste any of them into a `.vx` file and run it with `vex run`.

If you haven't installed Vex yet, start with [Install](/docs/install) and [Your first program](/docs/first-program).

## Hello, world

```vex title="hello.vx"
fn main() {
    println("Hello, world!")
}
```

```text title="Output"
Hello, world!
```

A program starts at `fn main()`. A new line ends a statement, so there are no semicolons. `//` starts a line comment, `/* */` a block comment (which can nest), and `///` a doc comment.

More: [Basics](/docs/language/basics).

## Variables and constants

`let` declares a name that can't be reassigned, `var` one that can. The type is inferred from the value, or written after a colon. `const` declares a value computed when the program is compiled.

```vex title="variables.vx"
const maxUsers = 100

fn main() {
    let name = "Vex"            // string, can't be reassigned
    var count = 0               // int, can change
    let price: float = 9.99     // type written out
    let tags: [string] = []     // an empty list needs its type

    count += 1
    println(name, count, price, tags, maxUsers)
}
```

```text title="Output"
Vex 1 9.99 [] 100
```

`println` takes any number of values and prints them separated by spaces.

Constants can be built from literals, other constants, operators, interpolation, records, enum cases, lists and maps. They can be used as patterns in `match`, and structs can have `static const` members. Constant lists and maps are frozen; `.copy()` gives a changeable copy.

```vex title="constants.vx"
const maxUsers = 100
const limit = maxUsers * 2 + 1
const greeting = "hello from vex"
const primes = [2, 3, 5, 7]
const okCode = 200

struct Circle {
    static const pi = 3.14159
    radius: float

    fn area() -> float => pi * radius * radius
}

fn status(code: int) -> string => match code {
    okCode => "ok"
    _ => "other"
}

fn main() {
    println(limit, greeting, primes, Circle.pi, Circle(radius: 2).area())
    println(status(200), status(500))
    var mine = primes.copy()
    mine.push(11)
    println(mine)
}
```

```text title="Output"
201 hello from vex [2, 3, 5, 7] 3.14159 12.56636
ok other
[2, 3, 5, 7, 11]
```

Changing a constant list directly is a compile error:

```vex title="frozen.vx"
const primes = [2, 3, 5, 7]

fn main() {
    primes.push(11)
}
```

```text
error: can't change a constant list: 'primes' is constant
 --> frozen.vx:4:5
  |
4 |     primes.push(11)
  |     ^^^^^^ change a copy instead: var mine = primes.copy()
```

**Top-level and static variables.** `let` and `var` outside a function, and `static var` inside a type, hold state the whole program shares. Each one is set up the first time it is used, so its starting value can call functions, and each isolate has its own copy.

```vex title="globals.vx"
var visits = 0
let greeting = makeGreeting()

fn makeGreeting() -> string {
    println("making greeting")
    return "hello"
}

struct Router {
    static var stack: [string] = []

    static fn push(page: string) {
        stack.push(page)
        visits += 1
    }
}

fn main() {
    println("start")
    Router.push("/home")
    Router.push("/settings")
    println(Router.stack, visits)
    println(greeting, greeting)
}
```

```text title="Output"
start
["/home", "/settings"] 2
making greeting
hello hello
```

## Numbers

`int` and `float` are both 64 bits. They never mix silently: convert with `float(x)` or `int(x)`. A whole-number literal adapts to `float` where a float is expected.

```vex title="numbers.vx"
fn main() {
    let count = 3
    let price = 2.5
    let total = float(count) * price
    println(total)
    println(int(total))
    println(7 / 2, 7 % 2, 7.0 / 2)
    let big = 9223372036854775807
    println(big &+ 1)
    let mask = 0xFF
    println(1_000_000, mask, 0b1010, 2.5e-3)
}
```

```text title="Output"
7.5
7
3 1 3.5
-9223372036854775808
1000000 255 10 0.0025
```

Mixing them is a compile error, with a hint:

```vex title="mix.vx"
fn main() {
    let count = 3
    let price = 2.5
    println(count * price)
}
```

```text
error: can't use '*' with int and float
 --> mix.vx:4:13
  |
4 |     println(count * price)
  |             ^^^^^^^^^^^^^ convert the int with float(...)
```

Integer overflow stops the program instead of giving a wrong number. When you want wrap-around, as in hashes, use `&+`, `&-` and `&*`, as the program above does.

```vex title="overflow.vx"
fn main() {
    let big = 9223372036854775807
    println(big + 1)
}
```

```text
error: integer overflow: 9223372036854775807 + 1 doesn't fit in an int; use &+ to wrap around
 --> overflow.vx:3
```

More: [Types](/docs/language/types), [Operators](/docs/language/operators).

## Strings

Strings are UTF-8 and immutable. `{expr}` inside a string inserts any value. `"""` starts a multi-line string whose indentation follows the closing quotes, and `r"..."` is a raw string with no escapes or interpolation.

```vex title="strings.vx"
fn main() {
    let name = "Ann"
    let items = 3
    println("Hi {name}, you have {items * 2} points")

    let s = "  Hello, Vex  "
    println(s.trim().upper(), s.len, s.contains("Vex"))
    println("a,b,c".split(","), "hello".replace("l", "L"))
    println("hello".indexOf("l"), "hello".indexOf("z"), "hello".substring(1, 3))
    println("héllo".len, "héllo".chars())

    let usage = """
        Usage: vex <command>
          run    build and run {name}
        """
    println(usage)
    println(r"\d+\.\d+ and {not interpolated}")
}
```

```text title="Output"
Hi Ann, you have 6 points
HELLO, VEX 14 true
["a", "b", "c"] heLLo
2 nil el
5 ["h", "é", "l", "l", "o"]
Usage: vex <command>
  run    build and run Ann
\d+\.\d+ and {not interpolated}
```

`len` and all string indexes count Unicode code points, not bytes. `indexOf` returns an optional `int?`, which is `nil` when the text isn't found. `+` joins only strings with strings; for anything else, use interpolation.

**Format specs.** An interpolated value can take a format spec after a `:`, as in Python and Rust: digits after the point, a width, zero padding, alignment with a fill character, thousands separators and other bases. The spec is checked when compiling. `upper` and `lower` follow Unicode for every script, and `graphemeCount` counts the characters a reader sees.

```vex title="format.vx"
fn main() {
    let price = 9.987
    let n = 42
    println("{price:.2} {n:04} [{n:6}] {n:x} {n:#b} {1234567:,}")

    let rows = [("pen", 3), ("notebook", 12), ("ruler", 105)]
    for (item, cost) in rows {
        println("{item:.<10}{cost:>5}")
    }
    let label = "total"
    println("{label:*^12}")

    println("straße".upper(), "👍🏽".len, "👍🏽".graphemeCount, "7".padStart(3, with: "0"))
}
```

```text title="Output"
9.99 0042 [    42] 2a 0b101010 1,234,567
pen.......    3
notebook..   12
ruler.....  105
***total****
STRASSE 2 1 007
```

## Control flow

Conditions need no parentheses and must be `bool`. Braces are always required, and `else` goes on the same line as the closing `}`. `for` loops over ranges, lists and maps; `0..3` excludes the end and `1..=3` includes it.

```vex title="control.vx"
fn grade(score: int) -> string {
    if score >= 90 {
        return "A"
    } else if score >= 75 {
        return "B"
    }
    return "C"
}

fn main() {
    println(grade(95), grade(80), grade(40))

    var upTo: [int] = []
    for i in 0..3 { upTo.push(i) }        // 0 to 2
    var through: [int] = []
    for i in 1..=3 { through.push(i) }    // 1 to 3
    println(upTo, through)

    let fruits = ["apple", "kiwi", "plum"]
    for i, fruit in fruits {
        println("{i}: {fruit}")
    }

    var odd: [int] = []
    var n = 0
    while true {
        n += 1
        if n % 2 == 0 { continue }
        if n > 7 { break }
        odd.push(n)
    }
    println(odd)
}
```

```text title="Output"
A B C
[0, 1, 2] [1, 2, 3]
0: apple
1: kiwi
2: plum
[1, 3, 5, 7]
```

An `if` with an `else` also gives a value, so it can pick one in a `let`, a `return` or an interpolation. There is no `? :` operator.

```vex title="ifvalue.vx"
fn main() {
    let score = 82
    let grade = if score >= 90 { "A" } else if score >= 75 { "B" } else { "C" }
    let items = 3
    println(grade, "{items} {if items == 1 { "item" } else { "items" }}")
}
```

```text title="Output"
B 3 items
```

**Loops and `defer`.** `repeat { } while cond` runs its body at least once. A name before a loop, such as `outer:`, lets `break` and `continue` leave an outer loop from inside an inner one. A `defer` block runs when the block it is in ends, however it ends; several run last first.

```vex title="loops.vx"
fn process(name: string) {
    println("open {name}")
    defer { println("close {name}") }
    defer { println("flush {name}") }
    if name == "" { return }
    println("write {name}")
}

fn main() {
    var n = 100
    repeat {
        n /= 3
    } while n > 5
    println(n)

    let grid = [[1, 2, 3], [4, -1, 6], [7, 8, 9]]
    var seen: [int] = []
    outer: for row in grid {
        for cell in row {
            if cell < 0 { continue outer }
            if cell == 8 { break outer }
            seen.push(cell)
        }
    }
    println(seen)

    process("log.txt")
}
```

```text title="Output"
3
[1, 2, 3, 4, 7]
open log.txt
write log.txt
flush log.txt
close log.txt
```

More: [Control flow](/docs/language/control-flow), [Named loops](/docs/language/control-flow#named-loops), [defer](/docs/language/control-flow#defer).

## Functions

Parameters have types, `-> T` gives the result type, and `=>` makes a one-line body. Parameters can have default values, and any argument can be passed by name, as in `greet(name: "Ann")`.

```vex title="functions.vx"
fn add(a: int, b: int) -> int {
    return a + b
}

fn square(x: int) -> int => x * x

fn greet(name: string, greeting: string = "Hi") {
    println("{greeting}, {name}!")
}

fn main() {
    println(add(2, 3), square(4))
    greet("Sam")
    greet("Sam", greeting: "Welcome")
}
```

```text title="Output"
5 16
Hi, Sam!
Welcome, Sam!
```

The compiler checks that a function with a result type returns a value on every path.

**Local functions.** A function can be declared inside another. It sees the variables around it, like a closure, and can call itself. It is declared before it is used, and it is a value that can be passed on.

```vex title="local.vx"
struct Dir {
    name: string
    files: int
    subdirs: [Dir] = []
}

fn countFiles(root: Dir) -> int {
    var total = 0

    fn visit(dir: Dir) {
        total += dir.files
        for sub in dir.subdirs {
            visit(sub)
        }
    }

    visit(root)
    return total
}

fn main() {
    let tree = Dir(name: "src", files: 2, subdirs: [Dir(name: "lib", files: 5), Dir(name: "app", files: 1, subdirs: [Dir(name: "ui", files: 4)])])
    println(countFiles(tree))

    fn square(x: int) -> int => x * x
    println([1, 2, 3].map(square))
}
```

```text title="Output"
12
[1, 4, 9]
```

More: [Functions](/docs/language/functions).

## Closures

A closure is a function without a name, written like a declaration. Parameter types can be left out where the expected type gives them, and closures capture variables by reference.

A `{ }` block after a call is passed as its last argument, a trailing block. It names its parameters before `in`, as in `{ a, b in a < b }`. A block for a function of one parameter can leave it unnamed and call it `it`. When the function returns a value, the block's last expression is that value.

```vex title="closures.vx"
fn repeat(times: int, action: fn()) {
    for i in 0..times { action() }
}

fn makeCounter() -> fn() -> int {
    var count = 0
    return fn() -> int {
        count += 1
        return count
    }
}

fn main() {
    let double = fn(x: int) -> int => x * 2
    let nums = [1, 2, 3, 4, 5, 6]
    let evens = nums.filter { x in x % 2 == 0 }
    let labels = evens.map { "#{double(it)}" }
    println(evens, labels)

    var words = ["kiwi", "fig", "banana"]
    words.sort { a, b in a.len < b.len }
    let sizes = words.map { w in
        let n = w.len
        "{w}={n}"
    }
    println(sizes)

    var taps = 0
    repeat(3) { taps += 1 }
    println(taps)

    let next = makeCounter()
    next()
    println(next())
}
```

```text title="Output"
[2, 4, 6] ["#4", "#8", "#12"]
["fig=3", "kiwi=4", "banana=6"]
3
2
```

Function types are written `fn(int) -> bool`, or `fn()` for a function that takes and returns nothing.

**Tear-offs.** A method, static method, enum case or constructor named without a call is a function value. A method torn off a value stays bound to it. Constructors are written `Type.new`.

```vex title="tearoffs.vx"
struct User {
    name: string
    fn greet(other: string) -> string => "{name} greets {other}"
}

enum Shape {
    circle(radius: float)
}

fn main() {
    let names = ["ann", "bo"]
    let host = User(name: "Kim")
    println(names.map(host.greet))
    println(names.map(User.new))
    println([1.0, 2.5].map(Shape.circle))
    let shout = "hi".upper
    println(shout())
}
```

```text title="Output"
["Kim greets ann", "Kim greets bo"]
[User(name: "ann"), User(name: "bo")]
[Shape.circle(radius: 1.0), Shape.circle(radius: 2.5)]
HI
```

More: [Closures](/docs/language/closures), [Trailing blocks](/docs/language/closures#trailing-blocks).

## Lists and maps

Lists `[T]` grow as needed and check every index. Maps `[K: V]` keep keys in the order they were added, and reading a key gives an optional, since the key may be missing. Inside list and map literals, `if`, `for` and `...` (spread) produce elements, as in Dart.

```vex title="collections.vx"
fn main() {
    var nums = [3, 1, 2]
    nums.push(4)
    let last = nums.pop()
    nums[0] = 10
    println(nums, nums.len, nums.contains(2), last)

    var ages = ["ann": 31, "bob": 25]
    ages["cat"] = 40
    println(ages["ann"], ages["zoe"] ?? 0, ages.len)
    for name, age in ages {
        println(name, age)
    }

    let loggedIn = true
    let extras = ["help", "about"]
    let menu = ["home", if loggedIn "profile" else "login", for n in [1, 2] "tab{n}", ...extras]
    println(menu)
}
```

```text title="Output"
[10, 1, 2] 3 true 4
31 0 3
ann 31
bob 25
cat 40
["home", "profile", "tab1", "tab2", "help", "about"]
```

Lists and maps are shared references: assigning one to another name doesn't copy it. Use `.copy()` for a separate collection.

**Null-aware elements and map helpers.** `?x` in a literal adds an optional only when it isn't `nil`, and `?` before a map value leaves the entry out when the value is `nil`. `xs?[i]` indexes a list or map that may itself be `nil`. `getOrPut` and `update` change an entry without spelling out the missing-key case.

```vex title="nullaware.vx"
struct User {
    name: string
    nickname: string? = nil
}

fn main() {
    let user = User(name: "Ann")
    let page: string? = "2"
    let lang: string? = nil

    let tags = ["member", ?user.nickname, ?lang]
    let query = ["q": "vex", "lang": ?lang, "page": ?page]
    println(tags, query)

    let recent: [string]? = ["a.vx", "b.vx"]
    println(recent?[0] ?? "none")

    var groups: [string: [string]] = [:]
    for w in ["apple", "avocado", "banana"] {
        groups.getOrPut(w.substring(0, 1)) { [] }.push(w)
    }
    var stock = ["apple": 3, "pear": 0]
    stock.update("apple") { it - 1 }
    println(groups, stock, stock.filter { name, n in n > 0 })
}
```

```text title="Output"
["member"] ["q": "vex", "page": "2"]
a.vx
["a": ["apple", "avocado"], "b": ["banana"]] ["apple": 2, "pear": 0] ["apple": 2]
```

The element type is the type inside the optional, so `tags` is a `[string]`. `update` never adds a key: on a missing one it does nothing and gives `nil`.

More: [Lists](/docs/language/lists), [Maps](/docs/language/maps).

## Sets

A `Set<T>` holds values without repeats, as in Swift. A list literal makes a set wherever a set is expected, and sets keep the order items were first added, so loops and printing are predictable.

```vex title="sets.vx"
fn main() {
    let primes: Set<int> = [2, 3, 5, 7]
    var seen = Set<string>()
    for name in ["ann", "bo", "ann"] {
        if seen.insert(name) {
            println("first visit: {name}")
        }
    }
    println(seen, seen.len, primes.contains(4))

    let odd = Set([1, 3, 5, 7, 9])
    println(primes.intersection(odd), primes.union(odd), primes.subtracting([2]))
    println(primes.isSubset(of: [1, 2, 3, 5, 7]), primes == [7, 5, 3, 2])
}
```

```text title="Output"
first visit: ann
first visit: bo
["ann", "bo"] 2 false
[3, 5, 7] [2, 3, 5, 7, 1, 9] [3, 5, 7]
true true
```

`insert` and `remove` give whether the set changed. Two sets are `==` when they hold the same items, whatever their order. Items can be any type a map key can be.

More: [Maps](/docs/language/maps).

## Bytes

`Bytes` holds binary data, such as file contents or network packets, like Swift's `Data` or Dart's `Uint8List`. Each byte reads as an `int` from 0 to 255, and slices, loops and `==` work as they do for lists.

```vex title="bytes.vx"
fn main() {
    var header = Bytes([0x89, 0x50, 0x4e, 0x47])
    header.push(0x0d)
    println(header.len, header[1], header[1..3])

    let text = "Hello".toBytes()
    println(text.toHex(), text.decodeUtf8() ?? "binary")
    println(text)

    let key = Bytes.fromHex("48690aff")
    println(key?.toList(), Bytes.fromHex("xyz"))

    var sum = 0
    for b in text { sum += b }
    println(sum)
}
```

```text title="Output"
5 80 Bytes(2 bytes: 50 4e)
48656c6c6f Hello
Bytes(5 bytes: 48 65 6c 6c 6f)
[72, 105, 10, 255] nil
500
```

Storing a value outside 0 to 255 stops the program, as an index out of range does. `vex:fs` reads and writes files as `Bytes` with `readBytes` and `writeBytes`, and JSON holds them as base64.

More: [Types](/docs/language/types), [vex:fs](/docs/stdlib/fs).

## Ranges and slicing

`a..b` counts from `a` up to, not including, `b`, and `a..=b` includes `b`. Besides driving `for` loops, a range is a value of type `Range` with `len`, `contains`, `step`, `reversed` and `toList`. A range inside `[ ]` copies part of a list, or the characters of a string, and either end can be left out there.

```vex title="ranges.vx"
fn main() {
    let hours = 0..24
    println(hours, hours.len, hours.contains(23), hours.contains(24))
    println((0..10).step(3).toList(), (1..=5).reversed().toList())
    for i in (0..=10).reversed().step(5) {
        println("countdown", i)
    }

    let xs = [10, 20, 30, 40, 50]
    println(xs[1..3], xs[1..=3], xs[2..], xs[..2], xs[(0..5).step(2)])
    let word = "héllo"
    println(word[1..3], word[..1], word[4..=4])
}
```

```text title="Output"
0..24 24 true false
[0, 3, 6, 9] [5, 4, 3, 2, 1]
countdown 10
countdown 5
countdown 0
[20, 30] [20, 30, 40] [30, 40, 50] [10, 20] [10, 30, 50]
él h o
```

A slice is a new list or string, so changing it doesn't change the original. A range that reaches outside the list or string stops the program, as an index does.

More: [Ranges](/docs/language/lists#ranges), [Slicing](/docs/language/lists#slicing).

## Records

A record groups a few values without declaring a type, which is handy for returning several values. Positional fields are read as `$1`, `$2` and so on; named fields by name. Records are values, compared field by field, and can be taken apart with patterns.

```vex title="records.vx"
fn divmod(a: int, b: int) -> (int, int) {
    return (a / b, a % b)
}

fn bounds(xs: [int]) -> ({int min, int max}) {
    return (min: xs[0], max: xs[xs.len - 1])
}

fn main() {
    let r = divmod(17, 5)
    println(r, r.$1, r.$2)

    let (q, rem) = divmod(9, 4)
    println(q, rem)

    let b = bounds([1, 5, 9])
    let (:min, :max) = b
    println(b, min, max)
    println((a: 1, b: 2) == (b: 2, a: 1))

    for (name, score) in [("ann", 3), ("bob", 5)] {
        println(name, score)
    }
}
```

```text title="Output"
(3, 2) 3 2
2 1
(max: 9, min: 1) 1 9
true
ann 3
bob 5
```

More: [Records](/docs/language/records).

## Structs

A struct has fields, which can have defaults, and methods. Methods use fields and other methods directly, without `self.`. `static fn` belongs to the type. A struct is created by calling its name with the fields as named arguments.

```vex title="structs.vx"
struct User {
    name: string
    age: int = 18

    fn isAdult() -> bool => age >= 18
    fn birthday() { age += 1 }

    static fn guest() -> User => User(name: "Guest")
}

fn main() {
    let ann = User(name: "Ann", age: 30)
    ann.birthday()
    println(ann)
    println(User.guest().age)

    let same = ann
    same.name = "Annie"
    println(ann.name)
}
```

```text title="Output"
User(name: "Ann", age: 31)
18
Annie
```

Struct values are shared references: `same` and `ann` are the same object. `let` stops the name from being reassigned, not the fields from changing.

**`let` fields, `init` and `copy`.** A `let` field is set when the struct is created and never changes afterwards; a field with a default can leave out its type. An `init` block runs each time the struct is created, after its fields are set, and can set `let` fields that have no default. Every struct has `copy`, which makes a new struct with some fields changed.

```vex title="letfields.vx"
struct Account {
    let id: int
    owner: string
    balance = 0
    let tags = ["new"]
}

struct Span {
    let low: int
    let high: int
    let size: int

    init {
        assert(low <= high, "low must not exceed high")
        size = high - low
    }
}

fn main() {
    let a = Account(id: 1, owner: "Ann")
    a.owner = "Ann Lee"
    a.tags.push("vip")
    println(a)

    let b = a.copy(id: 2, balance: 50)
    println(b.id, b.owner, b.balance, a.balance)

    let s = Span(low: 2, high: 9)
    println(s.size, s.copy(high: 20).size)
}
```

```text title="Output"
Account(id: 1, owner: "Ann Lee", balance: 0, tags: ["new", "vip"])
2 Ann Lee 50 0
7 18
```

`size` is set by `init`, so it isn't a constructor parameter, and `init` runs again on the copy. `let` stops the field from being assigned, not its list from changing, so `tags.push` works. Assigning a `let` field is a compile error:

```text
error: can't change 'id': it's a let field of Account
 --> letfield_err.vx:8:7
  |
8 |     a.id = 2
  |       ^^ set it when creating the Account, or make a changed copy with copy(id: ...)
```

**Printing.** A struct shows as its name and fields. A `fn toString() -> string` method replaces that wherever the value is shown: `println`, `str`, interpolation, and inside lists, maps, optionals and other structs.

```vex title="tostring.vx"
struct Money {
    cents: int

    fn toString() -> string {
        let rest = cents % 100
        return "${cents / 100}.{if rest < 10 { "0" } else { "" }}{rest}"
    }
}

struct Line {
    item: string
    price: Money
}

fn main() {
    let m = Money(cents: 1250)
    println(m)
    println("cost: {m}")
    println([m, Money(cents: 305)], Line(item: "pen", price: m))
}
```

```text title="Output"
$12.50
cost: $12.50
[$12.50, $3.05] Line(item: "pen", price: $12.50)
```


**Properties and operators.** A getter is read like a field and a setter runs on assignment. A `didSet` block after a field runs after each change, with the previous value in `oldValue`. Structs can define arithmetic, comparison and indexing operators.

```vex title="properties.vx"
struct Rect {
    width: float
    height: float

    get area -> float => width * height
}

struct Temperature {
    _celsius: float = 0

    get celsius -> float => _celsius
    set celsius(v: float) {
        if v < -273.15 { _celsius = -273.15 } else { _celsius = v }
    }
}

struct Counter {
    count: int = 0 {
        didSet { println("{oldValue} -> {count}") }
    }
}

struct Vec {
    x: float
    y: float

    operator +(other: Vec) -> Vec => Vec(x: x + other.x, y: y + other.y)
    operator *(k: float) -> Vec => Vec(x: x * k, y: y * k)
}

fn main() {
    println(Rect(width: 2, height: 3).area)

    let t = Temperature()
    t.celsius = -500
    println(t.celsius)

    let c = Counter()
    c.count += 1
    c.count = 5

    let a = Vec(x: 1, y: 2)
    let b = Vec(x: 3, y: 4)
    println(a + b * 2.0)
}
```

```text title="Output"
6.0
-273.15
0 -> 1
1 -> 5
Vec(x: 7.0, y: 10.0)
```

**Equality and hashing.** A struct listing `Equatable` gets an `==` that compares its fields; `Hashable` also lets it be a map key. Without either, `==` on a struct is a compile error. `===` and `!==` tell whether two names refer to the same object, for any struct.

```vex title="equality.vx"
struct Point: Hashable {
    x: int
    y: int
}

struct Tag {
    name: string
}

fn main() {
    let a = Point(x: 1, y: 2)
    let b = Point(x: 1, y: 2)
    println(a == b, a === b)

    var labels = [a: "home"]
    labels[Point(x: 0, y: 0)] = "origin"
    println(labels[b] ?? "?", labels.len)

    let t = Tag(name: "new")
    let same = t
    println(t === same, t === Tag(name: "new"))
}
```

```text title="Output"
true false
home 2
true false
```

Lists compare element by element and maps entry by entry, and records of keys such as `(int, int)` work as map keys too.

## Enums and match

An enum value is one of several cases. Cases are lowercase and can carry values. Enums can have methods. `match` picks the first arm that fits, can be used as a value, and must handle every case. Where the enum type is known, `.case` is enough.

```vex title="enums.vx"
enum Shape {
    circle(radius: float)
    rect(width: float, height: float)
    empty

    fn area() -> float => match self {
        circle(r) => 3.14 * r * r
        rect(w, h) => w * h
        empty => 0.0
    }
}

enum Light { red, yellow, green }

fn main() {
    let s: Shape = .rect(width: 2, height: 3)
    println(s, s.area())
    println(Shape.circle(radius: 1).area())

    let light = Light.yellow
    let action = match light {
        red => "stop"
        yellow => "slow down"
        green => "go"
    }
    println(action, light == .yellow, Light.red < Light.green)
}
```

```text title="Output"
Shape.rect(width: 2.0, height: 3.0) 6.0
3.14
slow down true true
```

Leaving out a case is a compile error that names it:

```vex title="lights.vx"
enum Light { red, yellow, green }

fn action(light: Light) -> string => match light {
    red => "stop"
    green => "go"
}

fn main() {
    println(action(.red))
}
```

```text
error: match doesn't handle 'yellow'
 --> lights.vx:3:38
  |
3 | fn action(light: Light) -> string => match light {
  |                                      ^^^^^ add yellow => ..., or _ => ...
```

**Raw values.** An enum whose cases carry no values can give each case a fixed `int` or `string`, as in Swift. An `int` counts up from the case before, and a `string` defaults to the case's name. `Type(rawValue:)` finds a case, `allCases` lists them, and every enum value has its case's `.name`. A Codable enum with raw values is written to JSON as its raw value.

```vex title="rawvalues.vx"
import "vex:json"

enum Status: int {
    ok = 200
    created
    notFound = 404
}

enum Level: string, Codable {
    low = "L"
    high = "H"
    unknown
}

fn main() {
    println(Status.created.rawValue, Status(rawValue: 404)?.name, Status(rawValue: 500))
    for level in Level.allCases {
        println(level.name, level.rawValue)
    }
    println(json.encode([Level.high, Level.unknown]))
}
```

```text title="Output"
201 notFound nil
low L
high H
unknown unknown
["H","unknown"]
```

`Status(rawValue: 500)` is `nil`, since no case has that value. Enums can also define operators, as structs do.

More: [Enums](/docs/language/enums).

## Patterns

Patterns test the shape of a value and take it apart in one step. They work in `match`, `if case`, `let`, `var` and `for`, and nest freely: literals, ranges, comparisons, enum cases, struct fields, records and lists, with `when` guards and `||` alternatives.

```vex title="patterns.vx"
struct Point {
    x: int
    y: int
}

fn describe(p: Point) -> string => match p {
    Point(x: 0, y: 0) => "origin"
    Point(x: 0, :y) => "on the y axis at {y}"
    Point(:x, :y) when x == y => "on the diagonal"
    _ => "somewhere else"
}

fn grade(score: int) -> string => match score {
    90..=100 => "A"
    80..90 => "B"
    > 100 => "bonus"
    _ => "C"
}

fn summary(xs: [int]) -> string => match xs {
    [] => "empty"
    [one] => "just {one}"
    [first, ...rest] => "{first} then {rest.len} more"
}

fn main() {
    println(describe(Point(x: 0, y: 0)), "|", describe(Point(x: 0, y: 4)), "|", describe(Point(x: 3, y: 3)))
    println(grade(95), grade(85), grade(120), grade(10))
    println(summary([]), "|", summary([7]), "|", summary([1, 2, 3]))

    let pair = (3, true)
    if pair case (n, true) when n > 1 {
        println("matched {n}")
    }
}
```

```text title="Output"
origin | on the y axis at 4 | on the diagonal
A B bonus C
empty | just 7 | 1 then 2 more
matched 3
```

The compiler checks that a `match` covers every value, including nested shapes, and reports arms that can never run. On an interface value, struct patterns and typed patterns such as `t: Text` also test which type it holds; see [Interfaces](#interfaces) below.

More: [Patterns](/docs/language/patterns).

## Optionals

A type ending in `?` holds a value or `nil`. Every other type always holds a value, so there are no null crashes: you must check an optional before using it, with `if let`, `guard let`, `?.` or `??`. There is no force unwrap.

```vex title="optionals.vx"
struct User {
    name: string
    manager: User? = nil
}

fn findUser(id: int) -> User? {
    if id == 1 { return User(name: "Ann", manager: User(name: "Bo")) }
    return nil
}

fn greet(id: int) {
    guard let user = findUser(id) else {
        println("no user {id}")
        return
    }
    println("hi {user.name}")
}

fn main() {
    if let u = findUser(1) {
        println(u.name)
    }
    greet(1)
    greet(2)
    println(findUser(1)?.manager?.name ?? "nobody")
    println(findUser(2)?.manager?.name ?? "nobody")
}
```

```text title="Output"
Ann
hi Ann
no user 2
Bo
nobody
```

Reading a field straight from an optional is a compile error:

```vex title="unchecked.vx"
struct User {
    name: string
}

fn findUser(id: int) -> User? => nil

fn main() {
    let u = findUser(1)
    println(u.name)
}
```

```text
error: can't read 'name' from a User?: it may be nil
 --> unchecked.vx:9:15
  |
9 |     println(u.name)
  |               ^^^^ use ?.name, or unwrap it first with if let
```

**Several conditions.** `if`, `while` and `guard` take conditions and bindings separated by commas. They are checked left to right, each name is visible to the conditions after it, and the block runs only when all hold. `if let user` is short for `if let user = user`. The right side of `??` can also be `return`, `throw`, `break` or `continue`, which runs when the left side is nil.

```vex title="conditions.vx"
struct User {
    name: string
    email: string? = nil
}

fn notify(user: User?) {
    if let user, let email = user.email, email.contains("@") {
        println("mail {user.name} at {email}")
    } else {
        println("can't mail")
    }
}

fn port(text: string) -> int {
    guard let n = int.parse(text), n > 0, n < 65536 else {
        return 80
    }
    return n
}

fn total(lines: [string]) -> int {
    var sum = 0
    for line in lines {
        let n = int.parse(line) ?? continue
        sum += n
    }
    return sum
}

fn firstWord(text: string) -> string {
    let space = text.indexOf(" ") ?? return text
    return text.substring(0, space)
}

fn main() {
    notify(User(name: "Ann", email: "ann@vex.dev"))
    notify(User(name: "Bo", email: "bo"))
    notify(nil)
    println(port("8080"), port("x"), port("0"))
    println(total(["4", "x", "6"]))
    println(firstWord("hello world"), firstWord("hi"))
}
```

```text title="Output"
mail Ann at ann@vex.dev
can't mail
can't mail
8080 80 80
10
hello hi
```

## Errors

A function that can fail declares `throws`, and every call to it needs `try`, so you can see each line that may fail. Handle an error with `try ... catch`, turn it into `nil` with `try?`, or pass it up with plain `try`. `throws(E)` names an enum of error kinds that callers can `match`.

```vex title="errors.vx"
fn parsePort(s: string) throws -> int {
    if s == "" { throw Error("empty port") }
    let n = int(s)
    if n < 1 || n > 65535 { throw Error("port {n} out of range") }
    return n
}

enum LoadError {
    notFound(path: string)
    denied
}

fn open(path: string) throws(LoadError) -> string {
    if path == "secret" { throw .denied }
    throw .notFound(path: path)
}

fn main() throws {
    let port = try parsePort("8080")
    let fallback = try parsePort("99999") catch e {
        println("bad port: {e.message}")
        3000
    }
    let maybe = try? parsePort("")
    println(port, fallback, maybe)

    try open("notes.txt") catch e {
        match e {
            notFound(p) => println("missing {p}")
            denied => println("denied")
        }
    }

    try parsePort("0")
}
```

```text title="Output"
bad port: port 99999 out of range
8080 3000 nil
missing notes.txt
error: port 0 out of range
 --> errors.vx:4
  at parsePort (errors.vx:4)
  at main (errors.vx:34)
```

When an error reaches the top of `fn main() throws`, the program prints it, with where it was thrown and the calls that led there, and exits with code 1. Errors are returned like values rather than unwinding the stack, so code that doesn't throw pays nothing.

More: [Errors](/docs/language/errors).

## Generics

Functions, structs, enums and methods take type parameters. The types are usually inferred. Constraints such as `Comparable`, `Equatable`, `Hashable` or an interface say what the generic code needs. Each use compiles to its own specialized copy, so generic code runs as fast as code written for one type.

```vex title="generics.vx"
fn largest<T: Comparable>(xs: [T]) -> T? {
    if xs.len == 0 { return nil }
    var best = xs[0]
    for x in xs {
        if x > best { best = x }
    }
    return best
}

struct Stack<T> {
    items: [T] = []

    fn push(item: T) { items.push(item) }
    fn pop() -> T? {
        if items.len == 0 { return nil }
        return items.pop()
    }
}

enum Result<T> {
    ok(value: T)
    err(message: string)

    fn map<U>(f: fn(T) -> U) -> Result<U> => match self {
        ok(v) => .ok(f(v))
        err(m) => .err(m)
    }
}

fn main() {
    println(largest([4, 17, 9]), largest(["kiwi", "apple"]))

    let s = Stack<string>()
    s.push("a")
    s.push("b")
    println(s.pop(), s.items)

    let r = Result.ok(5).map { "#{it}" }
    println(r)
}
```

```text title="Output"
17 kiwi
b ["a"]
Result<string>.ok(value: "#5")
```

Generic code is checked once, for every type that meets its constraints. Using `>` on an unconstrained `T` is an error that names the missing constraint:

```vex title="bigger.vx"
fn bigger<T>(a: T, b: T) -> T {
    if a > b { return a }
    return b
}

fn main() {
    println(bigger(1, 2))
}
```

```text
error: values of type T can't be ordered with >
 --> bigger.vx:2:8
  |
2 |     if a > b { return a }
  |        ^^^^^ require it: <T: Comparable>
```

More: [Generics](/docs/language/generics).

## Interfaces

An interface lists methods and properties. A struct or enum names the interfaces it implements after a `:`, and the compiler checks it there. Methods with a body are defaults. Interfaces work as types, such as `[Shape]`, and as generic constraints.

```vex title="interfaces.vx"
interface Shape {
    fn area() -> float
    fn name() -> string => "shape"
    fn summary() -> string => "{name()}: {area()}"
}

struct Circle: Shape {
    radius: float
    fn area() -> float => 3.14 * radius * radius
    fn name() -> string => "circle"
}

struct Square: Shape {
    side: float
    fn area() -> float => side * side
}

interface Sized {
    get size -> int
}

enum Suit: Sized {
    hearts
    spades
    get size -> int => 1
}

struct Block: Sized {
    size: int
}

fn total(xs: [Sized]) -> int {
    var n = 0
    for x in xs { n += x.size }
    return n
}

fn main() {
    let shapes: [Shape] = [Circle(radius: 1), Square(side: 2)]
    for s in shapes {
        println(s.summary())
    }
    println(total([Suit.hearts, Block(size: 4)]))
}
```

```text title="Output"
circle: 3.14
shape: 4.0
5
```

A property in an interface can be met by a getter or by a stored field, as `Block` does. A missing method is reported at the declaration:

```vex title="missing.vx"
interface Shape {
    fn area() -> float
}

struct Square: Shape {
    side: float
}

fn main() {
    println(Square(side: 1))
}
```

```text
error: Square doesn't implement 'area' from Shape
 --> missing.vx:5:8
  |
5 | struct Square: Shape {
  |        ^^^^^^ add fn area() -> float
```

**Type tests.** `x is T` asks whether an interface value holds a `T`. After the test, `x` has type `T` in the code it guards, so its fields can be used directly. `x as? T` gives the value as a `T`, or `nil`. In a `match`, `r: Rect` matches a `Rect` and binds it as one; interfaces are open, so a match on one needs a `_` arm unless the interface is sealed.

```vex title="typetests.vx"
interface Shape {
    fn area() -> float
}

struct Circle: Shape {
    radius: float
    fn area() -> float => 3.14 * radius * radius
}

struct Rect: Shape {
    width: float
    height: float
    fn area() -> float => width * height
}

fn describe(s: Shape) -> string {
    if s is Circle {
        return "circle, radius {s.radius}"
    }
    return match s {
        Rect(:width, :height) when width == height => "square, side {width}"
        r: Rect => "rect, {r.width} by {r.height}"
        _ => "shape"
    }
}

fn main() {
    let shapes: [Shape] = [Circle(radius: 1), Rect(width: 2, height: 2), Rect(width: 2, height: 3)]
    for s in shapes {
        println(describe(s))
    }
    let wide = (shapes[2] as? Rect)?.width ?? 0.0
    println(wide)
}
```

```text title="Output"
circle, radius 1.0
square, side 2.0
rect, 2.0 by 3.0
2.0
```

**Sealed interfaces.** `sealed interface` closes an interface: only types in the same module can implement it, so the compiler knows every type a value can be, as with Kotlin's and Dart's sealed types. A `match` on it needs no `_` once every type has an arm.

```vex title="sealed.vx"
sealed interface Result {}

struct Ok: Result { value: int }
struct Failed: Result { message: string }
struct Loading: Result {}

fn show(r: Result) -> string => match r {
    Ok(:value) => "got {value}"
    f: Failed => "failed: {f.message}"
    Loading() => "loading"
}

fn main() {
    let results: [Result] = [Ok(value: 7), Failed(message: "timeout"), Loading()]
    for r in results {
        println(show(r))
    }
}
```

```text title="Output"
got 7
failed: timeout
loading
```

Leaving out a type is a compile error that names it, as for enum cases:

```text
error: match doesn't handle 'Loading'
 --> sealed.vx:7:33
  |
7 | fn show(r: Result) -> string => match r {
  |                                 ^^^^^ add l: Loading => ..., or _ => ...
```

**Static requirements and interface extensions.** An interface can require a `static fn`, and `Self` in a requirement stands for the type that implements it. Generic code calls a static requirement through its type parameter, as in `T.parse(text: t)`. Such an interface can only be a constraint, not the type of a value. `extension Shape { ... }` adds methods to every type that implements `Shape`, usable on interface values, in generic code and on the types themselves.

```vex title="static.vx"
interface Parse {
    static fn parse(text: string) -> Self?
}

struct Point: Parse {
    x: int
    y: int

    static fn parse(text: string) -> Point? {
        let parts = text.split(",")
        guard parts.len == 2, let x = int.parse(parts[0]), let y = int.parse(parts[1]) else {
            return nil
        }
        return Point(x: x, y: y)
    }
}

fn readAll<T: Parse>(texts: [string]) -> [T] {
    var out: [T] = []
    for t in texts {
        if let v = T.parse(text: t) { out.push(v) }
    }
    return out
}

interface Shape {
    fn area() -> float
}

struct Circle: Shape {
    radius: float
    fn area() -> float => 3.14 * radius * radius
}

struct Square: Shape {
    side: float
    fn area() -> float => side * side
}

extension Shape {
    fn isBig() -> bool => area() > 100.0
}

fn main() {
    let points: [Point] = readAll(texts: ["1,2", "oops", "3,4"])
    println(points)

    let shapes: [Shape] = [Circle(radius: 9), Square(side: 2)]
    println(shapes.map { it.isBig() }, Square(side: 11).isBig())
}
```

```text title="Output"
[Point(x: 1, y: 2), Point(x: 3, y: 4)]
[true, false] true
```

More: [Interfaces](/docs/language/interfaces), [Extensions](/docs/language/extensions), [Types](/docs/language/types#type-tests), [Patterns](/docs/language/patterns#type-patterns).

## Extensions

`extension` adds methods and getters to a type that already exists, including built-in types such as `string`, `int` and lists. Inside, members of the type are used without `self.`, as in a struct.

```vex title="extensions.vx"
extension string {
    fn shout() -> string => upper() + "!"
    get isBlank -> bool => trim().len == 0
}

extension<T: Comparable> [T] {
    fn largest() -> T? {
        if len == 0 { return nil }
        var best = self[0]
        for x in self {
            if x > best { best = x }
        }
        return best
    }
}

extension int {
    get isEven -> bool => self % 2 == 0
}

fn main() {
    println("hi".shout(), "   ".isBlank, [3, 9, 2].largest(), 4.isEven)
}
```

```text title="Output"
HI! true 9 true
```

Extensions can't add fields or replace existing members.

**Extension types.** `extension type` makes a new, distinct type from an existing one, as in Dart 3. It wraps one value and costs nothing at run time: a `UserId` is compiled as a plain `int`. An `int` can't be passed where a `UserId` is expected, or the other way round, and only the members written for it are available. Listing `Equatable`, `Hashable`, `Comparable` or `Codable` takes them from the wrapped value.

```vex title="exttypes.vx"
extension type UserId(value: int): Hashable {
    fn isAdmin() -> bool => value < 100
}

extension type Email(value: string)

fn load(id: UserId) -> string => "user {id.value}"

fn main() {
    let id = UserId(value: 42)
    println(id, id.isAdmin(), load(id))
    var names = [id: "Ann"]
    names[UserId(value: 7)] = "Bo"
    println(names[UserId(value: 42)] ?? "?", Email(value: "ann@vex.dev").value)
}
```

```text title="Output"
UserId(value: 42) true user 42
Ann ann@vex.dev
```

Passing a plain `int` is a compile error with the fix:

```text
error: argument 'id': expected UserId, found int
 --> exttype_err.vx:6:18
  |
6 |     println(load(42))
  |                  ^^ wrap it: UserId(value: 42)
```

More: [Extensions](/docs/language/extensions).

## Type aliases

`typedef` gives a long type a short name. An alias is the same type as the one it names, and it can take type parameters.

```vex title="aliases.vx"
typedef Handler = fn(string) -> bool
typedef Pair<T> = (T, T)

fn on(event: string, handler: Handler) -> bool => handler(event)

fn main() {
    let p: Pair<int> = (1, 2)
    println(p, on("tap", fn(e) => e == "tap"))
}
```

```text title="Output"
(1, 2) true
```

Because an alias is the same type, `typedef UserId = int` still accepts any `int`. For a distinct type, use an [extension type](#extensions).

More: [Types](/docs/language/types).

## Builder blocks

When a function's last parameter is a list, a trailing block builds that list: each line is one element, and `let`, `if`, `for` and `...` work inside. It works for any list type, including lists of your own structs.

```vex title="builders.vx"
struct Item {
    label: string
}

struct Menu {
    title: string
    items: [Item]
}

fn main() {
    let admin = true
    let pages = ["Home", "Docs"]
    let menu = Menu(title: "Main") {
        Item(label: "Start")
        for p in pages {
            Item(label: p)
        }
        if admin {
            Item(label: "Settings")
        }
    }
    println(menu.items.map { it.label })
}
```

```text title="Output"
["Start", "Home", "Docs", "Settings"]
```

More: [Closures](/docs/language/closures).

## Async and await

An `async fn` can wait with `await` without blocking the program; other tasks and timers run meanwhile. Calling an async function without `await` starts it and gives a `Future<T>`, so several can run at once. `all` waits for a list of futures. The event loop is built into every program.

```vex title="async.vx"
import "vex:time"

async fn fetch(url: string) throws -> string {
    await time.sleep(100)
    return "page of {url}"
}

async fn main() throws {
    let page = try await fetch("a.com")
    println(page)

    let start = time.nanos()
    let a = fetch("b.com")
    let b = fetch("c.com")
    let pages = try await all([a, b])
    let ms = (time.nanos() - start) / 1_000_000
    println(pages, ms < 150)
}
```

```text title="Output"
page of a.com
["page of b.com", "page of c.com"] true
```

The two fetches sleep at the same time, so together they take about 100 ms, not 200. Async code runs on one thread; for parallel work, use isolates.

A `Stream<T>` gives many values over time. An `async fn` that returns a stream gives each value with `yield`, and `for await` reads them. A `StreamController<T>` makes a stream that other code fills with `add` and ends with `close`.

```vex title="streams.vx"
import "vex:time"

async fn ticks(n: int) -> Stream<int> {
    for i in 0..n {
        await time.sleep(10)
        yield i
    }
}

async fn main() {
    for await t in ticks(3) {
        println("tick", t)
    }

    let messages = StreamController<string>()
    messages.add("hello")
    messages.add("bye")
    messages.close()
    for await m in messages.stream {
        println(m)
    }
}
```

```text title="Output"
tick 0
tick 1
tick 2
hello
bye
```

A stream function starts when its stream is first read and pauses at each `yield` until the reader takes the value. Leaving a `for await` loop early stops it.

More: [Async](/docs/concurrency/async), [Streams](/docs/concurrency/async#streams), [vex:time](/docs/stdlib/time).

## Isolates

Isolates run code in parallel on other cores. Each has its own memory, so there are no locks and no data races: values are copied between isolates. `isolate.run` runs one function and gives back its result. `isolate.spawn` starts a long-running isolate, and channels carry messages to and from it.

```vex title="isolates.vx"
import "vex:isolate"

fn countPrimes(limit: int) -> int {
    var count = 0
    for n in 2..limit {
        var prime = true
        var d = 2
        while d * d <= n {
            if n % d == 0 {
                prime = false
                break
            }
            d += 1
        }
        if prime { count += 1 }
    }
    return count
}

fn worker(jobs: Channel<int>, out: Channel<string>) {
    while let n = jobs.receiveSync() {
        out.send("{n} squared is {n * n}")
    }
    out.close()
}

async fn main() {
    let limit = 100_000
    let primes = await isolate.run(fn() -> int {
        return countPrimes(limit)
    })
    println("primes below {limit}: {primes}")

    let jobs = Channel<int>()
    let out = Channel<string>()
    isolate.spawn(fn() { worker(jobs, out) })
    jobs.send(3)
    jobs.send(4)
    jobs.close()
    while let msg = await out.receive() {
        println(msg)
    }
}
```

```text title="Output"
primes below 100000: 9592
3 squared is 9
4 squared is 16
```

The compiler rejects values that can't be copied between isolates, such as functions and futures, at compile time.

More: [Isolates](/docs/concurrency/isolates), [vex:isolate](/docs/stdlib/isolate).

## Modules

A folder is a module, and a project is a folder with a `package.toml`. Files in one folder share their names. Code in another module uses a name through the module, as in `models.Cart`, and only names marked `pub` are visible there. Imports name the standard library with `vex:`, and project folders by their path relative to the importing file.

Here is part of the `store` example from the language repository:

<Files>
  <Folder name="store" defaultOpen>
    <File name="package.toml" />
    <File name="main.vx" />
    <File name="totals.vx" />
    <Folder name="models" defaultOpen>
      <File name="item.vx" />
      <File name="cart.vx" />
      <File name="shapes.vx" />
    </Folder>
    <Folder name="format" defaultOpen>
      <File name="receipt.vx" />
    </Folder>
  </Folder>
</Files>

```vex title="models/cart.vx"
pub struct Cart {
    pub owner: string

    // Private: other modules go through the methods.
    items: [Item] = []

    pub fn add(item: Item) {
        items.push(item)
    }

    pub fn list() -> [Item] => items

    pub fn total() -> int {
        var sum = 0
        for it in items {
            sum += it.price
        }
        return sum
    }
}
```

```vex title="main.vx"
import "vex:math"
import "models"
import "format" as fmt

fn main() {
    let cart = models.Cart(owner: "Ana")
    cart.add(models.Item(name: "pen", price: 3, kind: .tool))
    cart.add(models.Item(name: "notebook", price: 12, kind: .paper))
    cart.add(models.Item(name: "ruler", price: 5, kind: models.Kind.tool))
    println(fmt.receipt(cart))

    // Interfaces and generics work across modules too.
    let shapes: [models.Shape] = [models.Square(side: 3), models.Rect(w: 2, h: 5)]
    var area = 0
    for s in shapes {
        area += s.area()
    }
    println("area: {area}")
    let best = models.Pair<string, int>(first: "most", second: math.max(area, 20))
    println(best.describe())

    printTotals(cart)
}
```

Running `vex run store` prints:

```text title="Output"
Receipt for Ana
  pen.......   3 (tool)
  notebook..  12 (paper)
  ruler.....   5 (tool)
area: 19
most: 20
total: 20, clamped: 15
```

`printTotals` lives in `totals.vx`, in the same root folder as `main.vx`, so it needs no import. `as fmt` renames an import.

**Packages.** A package is a git repository with version tags such as `v0.3.1`. `vex get` adds one to `package.toml` and writes the exact version, commit and content hash of every package to `package.lock`. Code imports it with `package:`.

```sh
vex get https://github.com/ann/charts           # the newest tag
vex get https://github.com/ann/charts@0.3       # the newest 0.3.x
vex get                                         # download what package.toml lists
```

```toml title="package.toml"
[dependencies]
charts = { git = "https://github.com/ann/charts", version = "0.3.1" }
```

```vex title="main.vx"
import "package:charts"
import "package:charts/line"

fn main() {
    println(charts.title("Sales"), line.draw([1, 4, 2]))
}
```

Commit `package.lock`: builds use exactly the versions it lists, and stop when a package's files don't match their hash. Downloads are cached in `~/.vex/pkg`, so a project whose packages are cached builds offline.

More: [Modules](/docs/projects/modules), [Packages](/docs/projects/packages), [Standard library](/docs/stdlib).

## JSON

`vex:json` turns a struct or enum that lists `Codable` into JSON text with `json.encode`, and reads it back with `json.decode`. The compiler writes the conversion from the fields: a missing key takes the field's default, or `nil` for an optional. For JSON of any shape, `json.parse` gives a `Json` value to look inside with `get`, `at` and `asString`.

```vex title="json.vx"
import "vex:json"

enum Role: Codable { admin, guest }

struct User: Codable {
    name: string
    age: int
    email: string? = nil
    role = Role.guest
}

fn main() throws {
    let ann = User(name: "Ann", age: 30, role: Role.admin)
    let text = json.encode(ann)
    println(text)

    let team = try json.decode<[User]>(r"""
        [{"name": "Bo", "age": 4}, {"name": "Cy", "age": 52, "email": "cy@vex.dev"}]
        """)
    println(team[1])

    try json.decode<[User]>(r"""
        [{"name": "Di", "age": "ten"}]
        """) catch e { println(e) }

    let doc = try json.parse(r"""
        {"user": {"name": "Ann", "langs": ["vex", "go"]}}
        """)
    println(doc.get("user")?.get("langs")?.at(0)?.asString ?? "?")
}
```

```text title="Output"
{"name":"Ann","age":30,"email":null,"role":"admin"}
User(name: "Cy", age: 52, email: "cy@vex.dev", role: Role.guest)
[0].age: expected an int, found a string
vex
```

`decode` throws a `JsonError` that says where the JSON didn't fit, such as `[0].age`, or where the text stopped being JSON. Its type comes from where the result goes, or is written after the name, as in `decode<[User]>`.

More: [vex:json](/docs/stdlib/json).

## Dates, random numbers, patterns and crypto

The standard library has modules for the everyday work of programs: `vex:datetime` for moments and durations, `vex:random` for random numbers, `vex:regex` for regular expressions and `vex:crypto` for hashing, encryption and signatures.

```vex title="stdlib.vx"
import "vex:random"
import "vex:datetime"
import "vex:regex"
import "vex:crypto"

fn main() throws {
    let rng = random.Random(seed: 42)
    println(rng.nextInt(1..=6), rng.pick(["red", "green", "blue"]) ?? "none")

    let launch = datetime.utc(2024, 3, 15, hour: 9, minute: 30)
    let meeting = launch + 1.hours + 30.minutes
    println(meeting, meeting - launch, meeting.weekday)
    let parsed = try datetime.parse("2024-03-15T15:00:00+05:30")
    println(parsed == launch, parsed)

    let date = try regex.compile(r"(?<year>\d{4})-(\d\d)-(\d\d)")
    if let m = date.find("due 2024-03-15") {
        println(m.text, m.group("year") ?? "")
    }
    println(date.replace("on 2024-03-15", with: "$3/$2/$<year>"))

    println(crypto.sha256("abc".toBytes()).toHex().substring(0, 16))
    let key = crypto.SecretKey.generate()
    let box = crypto.seal("attack at dawn".toBytes(), key)
    println(try crypto.open(box, key).decodeUtf8() ?? "")
}
```

```text title="Output"
1 red
2024-03-15T11:00:00Z 1h30m0s 5
true 2024-03-15T09:30:00Z
2024-03-15 2024
on 15/03/2024
ba7816bf8f01cfea
attack at dawn
```

- `random.nextInt(1..=6)` and the other functions use a generator seeded by the system. `Random(seed: 42)` gives the same values on every run, for tests; neither is for keys or passwords.
- A `DateTime` is shown in UTC or in local time, and `1.hours` makes a `Duration` in a file that imports `vex:datetime`. Moments compare by the instant, so `parsed == launch` even though one was written with an offset.
- Patterns are best written as raw strings. Matching takes time in proportion to the pattern times the text, so no pattern can take exponential time.
- `vex:crypto` never implements a primitive of its own: it uses Monocypher, built into the program, and each system's provider. Keys have their own types, and `seal` encrypts and authenticates in one step.

More: [Standard library](/docs/stdlib).

## C interop

`extern fn` declares a C function, which Vex calls directly with no header and no glue code. Strings, sized numbers such as `int32`, optional strings and closures convert at the call.

```vex title="extern.vx"
extern fn strlen(s: string) -> int
extern fn getenv(name: string) -> string?
extern fn abs(x: int32) -> int32

fn main() {
    println(strlen("hello"))
    println(getenv("VEX_TOUR_MISSING") ?? "not set")
    println(["a", "bb", "ccc"].map(strlen))
    println(abs(-7))
}
```

```text title="Output"
5
not set
[1, 2, 3]
7
```

A project can build its own C files, listed in the `[c]` section of `package.toml`. `as "name"` calls a C function under a different name, a `fn` parameter passes a Vex closure to C as a callback, and `export fn` lets C call Vex.

```toml title="package.toml"
[package]
name = "cdemo"

[c]
sources = ["native/counter.c"]
```

```c title="native/counter.c"
#include <stdint.h>

static int64_t count = 0;

int64_t counter_next(void) {
    return ++count;
}

void each_up_to(int64_t n, void (*cb)(void *ctx, int64_t i), void *ctx) {
    for (int64_t i = 1; i <= n; i++) cb(ctx, i);
}

int64_t vex_twice(int64_t x);

int64_t call_twice(int64_t x) {
    return vex_twice(x);
}
```

```vex title="main.vx"
extern fn next() -> int as "counter_next"
extern fn each_up_to(n: int, f: fn(int))
extern fn call_twice(x: int) -> int

export fn vex_twice(x: int) -> int => x * 2

fn main() {
    next()
    println(next())

    var sum = 0
    each_up_to(4, fn(i: int) { sum += i })
    println(sum)

    println(call_twice(21))
}
```

```text title="Output"
2
10
42
```

More: [C interop](/docs/projects/c-interop).

## Memory

Memory is managed by a tracing garbage collector compiled into every program. Objects nobody can reach are freed, including objects that refer to each other in a cycle, so there is nothing to free by hand and no `weak` keyword.

```vex title="cycles.vx"
struct Node {
    value: int
    next: Node? = nil
}

fn main() {
    var total = 0
    for i in 0..1_000_000 {
        let a = Node(value: i)
        let b = Node(value: i, next: a)
        a.next = b
        total += b.value
    }
    println(total)
}
```

```text title="Output"
499999500000
```

Each pass through the loop creates a two-node cycle that becomes unreachable at the end of the iteration. The collector reclaims them as the program runs, so its memory stays small. It is generational, reads heap objects by their exact layout, so a number never keeps an object alive, and gives empty pages back to the system when the heap shrinks.

More: [Memory](/docs/language/memory), [Memory management](/docs/internals/memory).

## Tests

A `test` block names a test and holds its code. `expect(cond)` reports a failure without stopping the test, and when `cond` compares two values, the report shows both. `vex test` runs the tests; other builds leave them out.

```vex title="math.vx"
fn add(a: int, b: int) -> int => a + b

fn average(xs: [int]) -> int {
    var sum = 0
    for x in xs {
        sum += x
    }
    return sum / xs.len
}

test "adds two numbers" {
    expect(add(2, 3) == 5)
    expect(add(-1, 1) == 0)
}

test "averages a list" {
    expect(average([2, 4, 9]) == 5)
    expect(average([1, 2]) == 2, "should round up")
}
```

```text title="vex test math.vx"
✓ adds two numbers
✗ averages a list
  math.vx:18: expect(average([1, 2]) == 2)
    should round up
    left:  1
    right: 2

2 tests: 1 passed, 1 failed
```

Integer division rounds down, so the second `expect` fails; its message and both sides show why. Each test runs in its own process, and the exit status is 1 when a test fails.

More: [Testing](/docs/tools/testing).

## Documentation and tools

A `///` comment above a declaration documents it, and a `///` comment at the top of a file, set apart by a blank line, documents the module. Doc comments are Markdown, and names in square brackets become links. `vex doc` turns them into HTML pages, or prints one declaration in the terminal, like `go doc`.

```vex title="shapes.vx"
/// Flat shapes and their areas.

/// A circle. Its [area] grows with the square of [radius].
pub struct Circle {
    /// The distance from the centre to the edge.
    pub radius: float

    /// Returns the area, in square units.
    pub fn area() -> float => 3.14159 * radius * radius
}

fn main() {
    println(Circle(radius: 2).area())
}
```

```text title="vex doc shapes.vx Circle"
struct Circle

    A circle. Its [area] grows with the square of [radius].

    radius: float
        The distance from the centre to the edge.

    fn area() -> float
        Returns the area, in square units.
```

Plain `vex doc` writes HTML pages to `doc/`, and `vex doc vex:json Json` shows the standard library the same way.

`vex doctor` checks the tools Vex builds with: the C compiler, git for `vex get`, and, for phone apps, Xcode and the Android SDK, NDK and JDK. It says what is missing and how to install it, and never installs anything itself.


Vex runs on macOS, Linux and Windows. The SDK archive for each system holds `vex`, the standard library and, on Windows and Linux, the C toolchain, so nothing else is needed to build programs. On Windows, `vex build hello.vx` writes `hello.exe`, and no Visual Studio is needed.

## Built-in functions

These are always available, with no import:

| Function | What it does |
|---|---|
| `print(a, b, ...)`, `println(...)` | Print values separated by spaces; `println` adds a new line. |
| `eprint(...)`, `eprintln(...)` | Print the same way to standard error, for warnings and problems. |
| `input(prompt)` | Read a line from standard input; the prompt is optional. |
| `int(x)`, `float(x)`, `str(x)` | Convert between types. `int` and `float` of text that isn't a number stop the program. |
| `panic(msg)` | Stop the program with a message. |
| `assert(cond, msg)` | Stop the program when `cond` is false; the message is optional. |
